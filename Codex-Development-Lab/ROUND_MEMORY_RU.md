# Контекст между раундами

В панели проекта блок **«Память и результаты по раундам»** открывает отдельное
окно с выбором текущей памяти или конкретного раунда. Оно показывает ошибки,
подтверждённые исправления, результаты проверок, приёмку и заметки агента.
Пустые, недоступные и повреждённые записи отмечаются явно. Окно обновляется
каждые пять секунд, пока открыто; просмотр не запускает задание.

Новые раунды сохраняют снимки памяти перед разработкой и после проверки.
Для старых раундов без снимков доступны исходные отчёты и публичный итог агента;
текущая память отображается отдельно и не выдаётся за историческую.

ТЗ остаётся единственным источником требований. Контроллер передаёт краткую
сводку независимых проверок, известных ошибок и последних рабочих заметок.
Он больше не просит каждый новый раунд перечитывать все большие документы.

| Файл рабочего каталога | Назначение |
|---|---|
| `document-index.json` | Разделы ТЗ, диапазоны строк и хеш версии документа. |
| `round-memory.json` | История ошибок проверки, повторы, подтверждённые исправления и недавние заметки. Контроллер восстанавливает копию из своих артефактов. |
| `agent-handoff.json` | Итог агента, следующие шаги, решения и ошибки с предложенными исправлениями. Это неподтверждённые заметки. |

Claude и его специалисты выбирают строки через `read_lines`, ищут буквальный
текст через `search_text` и запрашивают до 12 требований со связанными сценариями
через `read_requirements`. Codex получает те же файлы контекста и инструкцию
выбирать нужные строки и JSON-записи обычными инструментами. Обрезанный ответ
инструмента явно сообщает об ограничении.

Агент завершает раунд небольшим `agent-handoff.json`:

```json
{
  "spec_sha256": "хеш из document-index.json",
  "summary": "Что изменилось и что осталось непроверенным",
  "next_steps": ["Конкретный пункт REQ-... и нужные файлы"],
  "decisions": ["Выбранный подход и причина"],
  "errors_and_solutions": [
    {
      "error": "Наблюдаемая ошибка",
      "solution": "Выполненное действие или предложение",
      "evidence": "Команда, файл результата и ограничения проверки"
    }
  ]
}
```

Заметки не могут поставить требованию PASS или закрыть ошибку проверки.
Исправление подтверждает независимый запуск. Смена ТЗ делает прежние заметки
устаревшими. Контекст и заметки не входят в хеш проверяемого исходного кода:
обновление заметок само по себе не обесценивает результаты тестов.

Это не бесплатная память провайдера и не гарантия полного отказа от повторных
чтений. Полные документы остаются доступны, когда требуется проверить соседние
ограничения или провести обзор полноты. Первоначальный разбор выполняется по
частям с сохранением прогресса.

Сбой среды проверки ставит задание на паузу без следующего платного раунда.
После явного возобновления контроллер сначала повторяет заблокированную
проверку того же кода и сохраняет прежнюю диагностику. Обычные ошибки сборки
и тестов продолжают поступать агенту для исправления.

При обновлении образа worker нужно также перезапустить простаивающий `runner`:
он закрепляет ID образа при старте. Иначе новые проверки используют старый код,
даже если worker и агенты уже обновлены. `START_WINDOWS.ps1` пересоздаёт службы;
при выборочном обновлении после пересборки выполни `docker compose restart runner`.
Обновление выполняется после подтверждённой паузы и завершения текущей проверки.
