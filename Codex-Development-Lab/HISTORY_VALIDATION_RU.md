# Независимая проверка истории агентов

Дата: 2026-10-21. Статусы назначил независимый агент `history_verifier`,
который не менял реализацию. Независимый агент `history_review` также выполнил
Python-проверки и добавил проверки границ доступа и сохранения попыток.

**Результат: PASS для проверенного просмотра истории, HTTP API и сохранения попыток.**
Это проверка программной функции панели, а не качества создаваемого мода.

## Проверенные сценарии

HTTP-проверки использовали реальные маршруты приложения с отдельными временными
базами и файлами: исходный запрос и параметры модели, листинг попыток, страницы
с byte cursor, поступление новых событий, незавершённая JSONL-строка с последующим
завершением, замена файла с reset потока, старый `round-NN/codex.jsonl` без
выдуманного prompt, ошибки неизвестного задания/попытки и неверных параметров.
GET-запросы не изменяют состояние задания.

Проверены отказы при попытке выбрать историю другого задания или подложить
request другого проекта. Проверки с symlinks включают файл запроса, журнал,
каталог mailbox и родительский каталог архива. Повреждённые записи, обычный текст,
необъектный JSON, чрезмерно длинная строка и JSON с 2000 уровнями вложенности
не скрывают следующие корректные события и не обрушивают просмотр.

Проверки worker имитируют transport агента без вызовов модели: неудача и повтор
с разными ID сохраняют оба фактических prompt/result/log; пауза до начала удаляет
mailbox request только после архивации; восстановление использует действительно
отправленный запрос; отмена заменяющим контроллером сохраняет журнал до retirement.

UI-проверки выполняют фактический JavaScript панели в Node с минимальным DOM:

1. Prompt, сообщение и идентификатор агента с HTML/JavaScript показываются как текст;
   попытка использования `innerHTML` в тестовом DOM немедленно завершила бы проверку.
2. Фильтр дочернего агента включает адресованный ему публичный запрос сотрудничества.
3. Дозагрузка не дублирует byte offsets и сохраняет существующие карточки,
   раскрытые детали и позицию прокрутки.
4. Задержанный ответ проекта A не рисуется поверх B; возврат к A показывает кэш.
5. Переключение A → B → A во время запроса сохраняет события и byte cursor.
6. Задержанный ответ старой попытки не заменяет выбранную новую попытку.
7. Reset потока удаляет старые карточки и принимает новые записи с прежними offsets.
8. Лимит 1000 отображаемых событий сохраняет cursor; «С начала» запрашивает offset 0.

Это проверка логики DOM и асинхронных ответов; настоящий графический браузер
и визуальная вёрстка отдельно не проверялись.

## Доступ и границы полноты

Dashboard получает `/agent-tasks` и `/artifacts` только для чтения. Авторизация
Codex и Docker/runner sockets ему не подключены. Новый просмотр использует
публичный JSONL-экспорт CLI: сообщения, команды, результаты и доступные события
сотрудничества. Структурированные приватные поля и события reasoning исключаются.
Это не просмотр сырых HTTPS-запросов к модели, внутренних рассуждений или
гарантированно полных отдельных диалогов всех дочерних агентов.

У старых раундов может сохраниться только `codex.jsonl`; тогда интерфейс честно
показывает отсутствие сохранённого исходного запроса. Архивирование каждой будущей
попытки, включая повторные попытки одного раунда, начинает работать после обновления
worker. Обновление только dashboard позволяет читать уже имеющиеся live-журналы
и старые артефакты без остановки выполняющегося задания.

Изолированная проверка не запускала настоящие LLM-запросы, Minecraft, облачное
хранилище или авторизацию. В ходе этих тестов рабочие контейнеры лаборатории
не перезапускались и не менялись. Создан отдельный тестовый image tag;
тестовые контейнеры удалены через `--rm`.

## Независимая проверка обновлённой рабочей панели

После завершения тестов основной агент обновил только `dashboard`, используя
тот же проверенный образ, без запуска зависимостей и без пересоздания
`worker`, `agent`, `runner`, `backup`, `storage`. Проверяющий агент затем
независимо выполнил только GET-запросы и чтение метаданных Docker.

**Результат: PASS для фактической доступности новой панели и старой истории.**

- `http://localhost:8080/` возвращает HTTP 200 и содержит «История агентов».
- Для существующего задания `16c911fc0fbf4d` API возвращает `legacy-round01`,
  доступный журнал размером 195986 байт и отсутствие сохранённого prompt.
- Запрос страницы истории с `limit=2` возвращает ровно два события и `has_more=true`.
  Текст реального журнала в отчёт не копировался.
- Состояние существующего задания — `FAILED`; проверка его не возобновляла
  и не изменяла. По предварительной проверке основного агента этот статус
  существовал до обновления панели.
- Фактический image ID dashboard совпадает с проверенным
  `1919983de81330c42c7549ea6b947f761c1bfb3e81d61c16980c8258660f2802`.
- Docker inspect подтверждает `/agent-tasks` и `/artifacts` с `RW=false`.
  Авторизация Codex и управляющие sockets среди mounts панели отсутствуют.

Независимо прочитанные текущие container ID совпали с переданными основным
агентом значениями до обновления для всех служб, кроме обновлённой панели:

| Служба | Container ID после обновления |
| --- | --- |
| dashboard | `1b1f3585009f` |
| worker | `4a7e5da78743` |
| agent | `38c1e63599fc` |
| runner | `0b5e774538cd` |
| backup | `4701b80b964b` |

Новая панель уже работает. Worker остаётся на прежнем образе; для долговременного
архивирования будущих попыток его потребуется обновить отдельно после завершения
или подтверждённой паузы заданий. Проверяющий агент live-развёртывание не выполнял.

## Воспроизведение

Из корня проекта, в среде с Docker CLI и доступными ранее закэшированными слоями:

```powershell
docker build --network none -f Dockerfile.service -t codex-lab-service:verify-history .
docker run --rm --network none --read-only --tmpfs /tmp:rw,mode=1777 --user 1000:1000 --cap-drop ALL --security-opt no-new-privileges:true codex-lab-service:verify-history python3 -m unittest discover -s tests
```

В среде с Node 22:

```powershell
node audit/history_ui_check.js
```
