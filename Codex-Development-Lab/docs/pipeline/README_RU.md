# Новая архитектура: интерактивное объяснение

Архитектура внедрена в runtime v1:
[реализация](../../audit/SEMANTIC_PIPELINE_V1_RU.md),
[действующие схемы](../../schemas/pipeline/README.md).
Эта страница сохраняет демонстрационные примеры proposal-v1; рабочие схемы
дополняют их привязкой контрольных точек к JUnit и доказательствами ревью.

Откройте [index.html](index.html) в браузере. Сервер не нужен.

Страница содержит 11 блоков, 24 предлагаемых контракта, схемы полей, примеры
JSON, демонстрацию проверок контроллера и один цикл с контрольными точками.
Текст описывает целевую архитектуру. Действующий API не меняется.

- [Все схемы Draft 2020-12](contracts.schema.json).
- [Все примеры сообщений](examples.json).
- `contracts/<Contract>.schema.json` — самостоятельная схема сообщения.
- `contracts/examples/<Contract>.json` — пример этого сообщения.
- [Согласованные принципы](../../PIPELINE_DESIGN_RU.md).
- [Действующая схема планировщика](../../schemas/planner_output.schema.json).

Обозначение `proposal-v1` отделяет проектные контракты от runtime-контрактов.
Примеры вымышлены; хеши обозначают разные версии и не являются хешами реальных
файлов мода. JSON Schema проверяет структуру. Проверки ссылок, происхождения,
графа и согласованности полей выполняются отдельным кодом. Смысловую полноту
оценивает LLM. Исполняемые тесты подтверждают наблюдаемое поведение.

Загрузка пользователем: файл Markdown и настройки формы. ProjectInput —
нормализованный JSON после приёма файла, а не объявление нового HTTP endpoint.
GatewayRequest/GatewayResult — внутренние сообщения; конкретные HTTP/SSE-конверты
провайдеров остаются обязанностью адаптера. Не передавайте ключи через эти JSON.
Usage.input_tokens включает cache_read_tokens и cache_write_tokens: подкатегории
нельзя повторно прибавлять к input_tokens. Адаптер нормализует счётчики провайдера.
При measurement=unavailable нулевые счётчики означают отсутствие измерения, а не
бесплатный запрос. Время, число запросов и тарифы можно хранить отдельными
событиями шлюза; эта страница не задаёт финансовую модель.

