# Исправление повторяющихся решений

Один вопрос каталога должен иметь одно текущее решение. Если два решения относятся к одному вопросу, ошибка относится к составу `question_resolutions`, а не к написанию поля `question`.

Контроллер сообщает группы индексов повторов и разрешает атомарную замену только затронутого массива. Модель может удалить идентичные повторы или объединить полезные сведения. Противоречащие решения требуют явного анализа по доверенным источникам; контроллер не выбирает ответ автоматически.

Одна SubmissionPatch может менять несколько связанных разрешённых полей. Разрешение на исправление массива не разрешает замену всего ответа или изменение соседних разделов каталога. Проверки хеша базы, ожидаемых старых значений, непересечения путей и полного итогового формата сохраняются.

После слияния правки проверяется сохранность каждого ранее корректно связанного уникального вопроса и объединения его известных условий. Оригиналы ответов, причин и доказательств остаются в канонической истории исправлений. При изменении формулировок требуется смысловая проверка; программная проверка связей не доказывает эквивалентность текста.

Старые сохранённые ошибки `question_link`, которые требовали «one unique exact question», автоматически получают область исправления массива. Новая ошибка неизвестного вопроса остаётся на уровне конкретного поля. Поэтому уже остановленный процесс может продолжить свою текущую правку после обновления без сброса исходников и истории.

Регрессии: `tests/test_duplicate_resolution_repair.py`. Проверки не вызывают LLM и не назначают PASS функционалу Minecraft-мода.
