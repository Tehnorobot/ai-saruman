# Подробности отказа API

Для новых HTTP-отказов шлюз сохраняет:

- исходный HTTP-статус и тело ошибки провайдера;
- ID запроса шлюза и разрешённые заголовки request-id/correlation-id/retry-after;
- модель, max_tokens, output_config и tool_choice;
- размер запроса и системы, список инструментов с размерами схем;
- последовательность сообщений и типов блоков, ID tool_use и tool_result.

Тексты промптов, результаты инструментов, параметры команд и заголовки авторизации в сводку запроса не включаются. Тело ответа провайдера очищается от известных ключей/токенов и секретных полей. При ошибке провайдер может вернуть собственные фрагменты запроса — эта диагностика предназначена для владельца проекта.

Полные публичные подробности доступны в журнале агента как событие `provider.error` и в истории API: `GET /api/jobs/{job_id}/usage`, поле `requests[].diagnostic_json` (JSON-строка). Краткая строка «Последняя ошибка» может быть короче; она не заменяет эту запись.

Тело ошибки до 8 МиБ сохраняется полностью; при превышении диагностической границы устанавливается `body_truncated=true`. Это защита чтения недоверенного ответа, а не ограничение контекста LLM. Старые тела ошибок, которые раньше не сохранялись, восстановить нельзя.

HTTP 502 шлюза может содержать исходный HTTP 400 провайдера. Диагностика показывает оба уровня. Автоматический повтор неизменённого отклонённого запроса не добавлен. Отдельные платные диагностические запросы не выполняются.
