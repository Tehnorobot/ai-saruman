# Контекст точечного исправления

Планировщик получает проверенный индекс задач и при первом ответе, и при точечной правке. Индекс формируется из ссылок на принятые каталог и граф: ID задачи, название, зависимости, ID условий и открытые технические вопросы. Это справочные данные, а не новые поля ответа модели.

Инструмент `read_patch_field` имеет три раздела:

| section | Что читает | Пример path |
|---|---|---|
| value | Неизменяемый сохранённый ответ | $.actions[0].task_ids |
| format | Формат поля ответа | $.actions[0].task_ids |
| context | Доверенные данные для исправления | $.task_index |

Значения читаются из памяти запроса. Инструмент не открывает файлы и не выполняет команды. Для больших данных используется постраничное чтение; полное содержимое доступно без обрезания оригинала.

При неверном пути модель получает запрошенный путь/раздел, доступные разделы, корневые поля ответа и контекста, разрешённые пути правки и инструкцию, где искать индекс задач. В журнале успешные и неуспешные чтения содержат имя инструмента и ID вызова. Ошибка не заменяется короткой строкой без контекста.

Запись изменений по-прежнему выполняется только через SubmissionPatch с проверкой хеша базы, старых значений и разрешённых полей. Чтение контекста не расширяет права записи и не позволяет менять индекс задач. После слияния контроллер проверяет полный результат.

Регрессионные тесты используют фиктивные ответы без вызова платных моделей. Они проверяют передачу данных и обработку ошибок, но не гарантируют, что конкретная модель завершит любое рассуждение в заданный лимит токенов.
