# Общая история запросов

Окно «История запросов» показывает одну таблицу для всех провайдеров: время, провайдер, роль, модель, статус, входные и выходные токены, кеш и уникальный ID. Дополнительные страницы загружаются кнопкой «Загрузить ещё». Общее число доступных записей не ограничено размером одной страницы.

API-запросы имеют собственный request_id. Несколько запросов внутри одного запуска агента не объединяются в строку с одинаковым task_id. Порядок API-записей определяется последовательностью вставки в базу, а не часами системы. Исходные даты не переписываются.

Для CLI видны известные завершённые ответы из публичных журналов, с ID запуска и смещением записи. Отдельные скрытые API-вызовы CLI не выдумываются. Кешированный вход не прибавляется второй раз. Если статистика ещё неизвестна, интерфейс не должен выдавать её за доказанный расход.

`GET /api/jobs/{job_id}/requests?limit=50` возвращает страницу. `next_cursor` передаётся следующему запросу без изменений. Курсор связан с заданием и снимком истории; после истечения срока окно предлагает обновить первую страницу. Большие истории остаются доступными через новые страницы, а не обрезаются до первых 200 строк.

Пересчёт архивов идёт в фоне. Ожидание этого пересчёта и медленный запрос общей статистики не блокируют историю API. При временной ошибке уже показанные строки сохраняются. Обновление не закрывает раскрытые подробности ошибок.

При поступлении большого числа новых запросов или завершении фоновой индексации пагинация обновляется; ранее показанные строки не теряются. При дозагрузке промежуточных страниц порядок последовательности API восстанавливается даже при неверных временных метках.
