# Продолжение работы без старых прерывателей

Истечение времени исследования больше не уничтожает процесс модели. После мягкого срока агент должен завершить текущий полезный результат, сохранить выводы и перечислить нерешённые вопросы. Это не разрешение считать работу выполненной.

## Что изменено

| Место | Старое поведение | Текущее поведение |
| --- | --- | --- |
| `agent/daemon.py` | Завершение процесса после времени роли | Ожидание результата; отмена только по запросу пользователя или при остановке сервиса |
| `worker/engine.py`, транспорт | Повторная отмена через время роли + 30 секунд | Ожидание подтверждённого результата; сохранена подтверждаемая отмена пользователя |
| `provider_gateway/main.py`, `worker/engine.py` | Авторизация истекала вскоре после времени роли | Контроллер продлевает действующую авторизацию; capability, расходы и лимиты не сбрасываются |
| `agent/dslab.py`, API | Нет уведомления уже работающей модели о мягком сроке | После завершения текущего обмена каждый следующий запрос содержит указание завершить исследование |
| `worker/pipeline.py`, код и ревью | Новые замечания могли бесконечно возвращать работу кодеру | По мягкому сроку сохраняются замечания и реальные сценарии передаются независимому проверяющему |
| Старый `TIMEOUT` | Фиксированное число попыток, затем пауза | Продолжение с сохранёнными файлами и историей, рефлексия и отменяемая задержка |
| Старый планировщик | Остановка после одного напоминания прочитать диагностику | Повторные конкретные замечания в пределах выбранного бюджета |
| Историческая проверка формата | Одна коррекция, затем ручное продолжение | Итеративные исправления с архивом отклонённых ответов и остатком исходного бюджета |
| Устаревший исторический план | Архивирование и ошибка до ручного продолжения | Архивирование и новое планирование текущих исходников без пересоздания проекта |
| Старое делегирование | Три специалиста и 12 запросов дочерней модели | Общий выбранный бюджет запросов |
| Команда агента | Указанный таймаут принудительно уменьшался до 300 секунд | Положительный таймаут конкретной команды без скрытого верхнего ограничения |
| Начальный контекст | Превышение целевого размера истории завершало агента | Начальные инструкции сохраняются целиком; сокращается история завершённых обменов, архивы остаются доступны |

Мягкий срок кода и ревью сохраняется в контрольной точке. Он учитывает активное время и связан с раундом и принятым планом. Пауза пользователя не расходует его. Новый план не наследует срок другого задания.

## Настройки

Существующие имена сохранены для совместимости:

- `AGENT_TIMEOUT_SECONDS`: общий мягкий срок, по умолчанию 3600 секунд.
- `PLANNER_TIMEOUT_SECONDS`: отдельный мягкий срок планировщика; пустое значение наследует общий.
- `REVIEWER_TIMEOUT_SECONDS`: отдельный мягкий срок ревьюера; пустое значение наследует общий. Передаётся через Compose.
- `PREPARATION_SOFT_LIMIT_SECONDS`: активное время подготовки или обсуждения кода перед передачей готовой работы дальше.
- `MAX_AGENT_TIMEOUT_RETRIES`: устарел, больше не управляет остановкой работы.

`.env` автоматически не меняется. Сроки не означают точного завершения на указанной секунде: API получает уведомление после текущего ответа провайдера; CLI получает целевое время и инструкцию проверять часы. Генерация не обрывается ради соблюдения срока.

## Что продолжает останавливать работу

Сохранены явная пауза/остановка пользователя, выбранные бюджеты токенов/запросов/раундов, ошибки доступа и конфигурации, реальные внешние зависимости, обязательные ручные проверки и ошибки независимой проверяющей среды.

Сохранены изоляция контейнеров, ограничения ресурсов и путей, проверка хэшей и принадлежности, запрет восстановления отозванных ключей задачи, подтверждение остановки писателя перед снятием блокировки проекта, ограничения размера сетевого сообщения и таймауты сетевых операций и отдельных тестовых команд. Это защита или граница конкретной операции; её нельзя заменить бесконечным платным повтором.

Открытые замечания не становятся PASS при передаче на тестирование. Готовность по-прежнему требует независимых результатов и полного покрытия условий ТЗ.
