# Исправления после частичного запуска Auto Defense

Исправления применены к локальной системе 21 октября 2026 года. Исходный разбор:
[FAILURE_ANALYSIS_2026-10-21_RU.md](FAILURE_ANALYSIS_2026-10-21_RU.md).

## Что изменилось

- **Ресурсы:** agent имеет конечный лимит 768 процессов/потоков вместо 256,
  JVM использует два процессора, Gradle — два workers, ограничены потоки
  программного рендеринга. Память агента остаётся ограниченной 6 GiB.
  Ограничения параллелизма также передаются изолированным проверочным контейнерам.
- **Очистка:** Linux supervisor использует child subreaper и pidfd, завершает
  отделившиеся дочерние процессы и собирает zombies после успеха, отмены и
  таймаута. Если очистка не подтверждена, terminal result не публикуется:
  Compose перезапускает контейнер, а ACK разрешён только в новом PID namespace.
  Supervisor выполняет задачи последовательно; это условие его учёта процессов.
- **Контроль времени:** prompt передаётся через временный файл вместо
  блокирующей записи в PIPE. Таймаут остаётся доступен, даже если CLI ещё
  не начал читать stdin. Бюджет этапа по умолчанию — 3600 секунд.
- **Восстановление:** один автоматический повтор TIMEOUT в том же раунде
  сохраняет исходники и историю. После двух неоконченных попыток —
  `USER_PAUSED / agent_timeout`. Явное продолжение даёт новый конечный бюджет.
  Счётчик резервируется до dispatch и переживает перезапуск worker.
  Terminal result сохраняется до durable checkpoint, поэтому аварийный выход
  worker не теряет завершённый PASS/FAIL/TIMEOUT и не создаёт лишний запрос.
- **Очередь и UI:** старые FAILED можно продолжить; STOPPED/FINISHED остаются
  конечными состояниями. Добавлена миграция `resume_generation`, сериализованная
  для одновременного старта сервисов. Quota recovery не воспроизводит бесконечно
  закэшированный отказ. В новых ошибках UI сохраняются статус и длительность.
- **Codex:** роли передаются явными CLI overrides, поэтому их загрузка не
  зависит от доверия к проектной `.codex/config.toml`. Пин 0.162.1 сохранён.
  Фактическое делегирование требует событий выполнения; текст основного агента
  не считается доказательством независимого ревью.
- **Бэкап:** сохраняются wrapper JAR, входные JAR/ZIP, ресурсы, build/libs,
  test-results/reports и клиентские crash reports. Кэши и миры исключены.
  Manifest v2 сообщает исключения и конечные ограничения размеров/обхода.
  Добавлена защита от подмены файлов/каталогов ссылками во время чтения.
- **Сборка образов:** audit-кэши исключены из Docker build context; `.env`
  и рабочие папки по-прежнему не передаются при сборке.

## Исправления сохранённого мода

В `projects/b8fff539803e4d/workspace/` исправлены состояния после Stop/resume и
disable/enable: OBSERVING требует нового действительного observe. F8 сообщает
фактическое состояние. Добавлены регрессии, metadata клиентского GameTest и
ограничение параллелизма сборки. Бессодержательный серверный GameTest больше
не запускается в build; клиентский тест компилируется, а игровой запуск остаётся
отдельной явной проверкой. EULA имеет opt-in через параметр оператора.

dry-run; init script запрещал игровые и EULA-задачи в графе исполнения.

- `build`: exit 0, production JAR и sources JAR созданы.
- JUnit: 9 тестов, 0 failures, 0 errors, 0 skipped.
- `compileGametestJava` и `processGametestResources`: выполнены.
- Minecraft и принятие EULA: не запускались.
- Production JAR: 7469 байт, SHA-256
  `c3498eaea2803296d67d3e32540277b83ae6117d745f1809502c0e1ad709e736`.

Независимые specialist review/test planning выявили и помогли воспроизвести
аварийные окна до checkpoint и очистки; соответствующие исправления проверены
повторными воспроизводимыми сценариями. Отдельный независимый verifier до
финального прогона подтвердил первоначальные 14 проверок timeout/cleanup/UI.

backup, worker, agent и runner. Прежние образы сохранены под тегами
`before-runtime-fix-20261021`. Storage не пересоздавался.

  прежняя история проверены через HTTP.
