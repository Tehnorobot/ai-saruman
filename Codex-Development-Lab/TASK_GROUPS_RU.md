# Объединённые задачи

Для Auto Defense список сокращён с 240 исходных условий до **29 задач**
по разделам — в **8,3 раза**. Большой раздел интеграции Saruman разделён
по существующим подразделам. Небольшие подразделы объединены в родительскую
задачу. Исходное ТЗ и REQ-ID сохранены.

В «Приёмке по ТЗ» по умолчанию открывается вид **«Задачи по функциям»**.
Карточка показывает общий прогресс и раскрываемый список входящих условий.
Проверки, журналы и видео связаны с этой задачей; один сценарий внутри карточки
показан один раз. Вид **«Исходные условия ТЗ»** сохраняет подробную приёмку.
Фильтр «Выполнено частично» показывает задачи с неоднородными результатами.

Объединение не меняет смысл проверки:

- задача подтверждена только при подтверждении всех её условий;
- ошибка любого условия не скрывается;
- несколько успешных условий внутри задачи показывают частичное выполнение;
- прежние доказательства и история не удаляются;
- число задач не равно числу сценариев или assertions; за проверочный раунд
  по-прежнему выполняется не более четырёх сценариев.

Перед новым вызовом модели контроллер записывает в workspace
`acceptance-tasks.json`. Документ содержит задачи и их REQ-ID. В запрос агенту
передаются компактный индекс задач, ID групп ближайших сценариев и сами
ближайшие сценарии. Агент должен реализовывать связное поведение в рамках
задачи; отдельный абзац ТЗ не считается отдельной разработческой работой.
Связанный сценарий может покрывать несколько условий, если для них есть
явные assertions и корректные связи в acceptance-plan.json.

Полный документ задач доступен агенту по требованию. Чтобы не раздувать запрос,
индекс ограничен 32 задачами и 140 символами заголовка. При большем количестве
приоритетные задачи идут первыми, число пропущенных групп указано явно.
Все 29 задач текущего проекта помещаются в индекс.

Документ задач — контекст, а не исполняемый код. Его обновление не изменяет
хеш исходников и не сбрасывает результаты. Итоговые статусы по-прежнему
определяет независимая проверка, а не агент.
