# Связанные задачи за один раунд

Дата: 2026-10-24.

## Реализация

Планировщик выбирает 1–4 действия: основное `action`, до трёх `additional_actions`,
обоснование `bundle_reason`, порядок зависимостей `depends_on` и
`verification_limit` от 1 до 4. Каждый участник проходит прежнюю проверку цели,
области текущей задачи/регрессий, доступных доказательств и статусов сценариев.
Ремонт сценария ставится первым. Обзор покрытия, ручные проверки, глубокая
диагностика и обязательные директивы переключения не смешиваются с пакетом кода.

Весь пакет передаётся одному вызову кодера. Состав и причина объединения сохраняются
в контроллерном плане, памяти раунда и публичном API. При восстановлении проверяется
весь пакет; при подготовке следующего раунда старый пакет сбрасывается.

Независимая проверка сначала получает по одному доступному сценарию каждого
участника пакета, затем следующие сценарии по очереди. Точный ремонтируемый
сценарий идёт первым; явные проверки — раньше общих mappings. Новые mappings,
созданные кодером, учитываются после его работы. Существующие успешные сценарии
не запускаются заново без основания. Непроверенные приоритетные сценарии возвращаются
в `omitted_priority_scenario_ids` и остаются в очереди.

Окно планировщика показывает полный пакет, зависимости, общую причину и лимит
проверок. Старые одиночные планы остаются совместимыми. Готовность и no_progress
не подменяются числом действий в пакете.

## Проверки

- 23 новых теста: 11 проверки пакета/workflow и 12 очереди.
- Проверен сквозной маршрут: предложение → валидация → один вызов кодера со всем
  пакетом → запись истории и публичного состояния → реальный метод checks выбирает
  сценарии в порядке пакета. Модели и DockerSandbox в этих тестах заменены
  локальными детерминированными ответами; логика контроллера исполняется реально.
- Проверены отклонения неизвестных/несвязанных/повторных целей, будущих зависимостей,
  неправильного размера/лимита, отсутствия доказательств у дополнительного ремонта,
  ручного/глубокого/обязательного одиночного хода с дополнительными задачами.
- Проверены приоритет свежего ремонта перед старыми регрессиями, равномерное
  выделение проверок при большом первом требовании, учёт наблюдаемой ошибки другой
  задачи, сохранность отложенных проверок и отбраковка подменённых доказательств.
- Полный Linux-образ: **711 тестов — OK, 28 пропущены**. Без сети, без секретов,
  корень контейнера только для чтения.
- Независимый reviewer отдельно выполнил **58 тестов — OK, 1 пропущен**.
- Edge: окно планировщика — **13 проверок PASS**, включая весь пакет, зависимости,
  лимит, безопасный вывод текста и сохранение видео.
- Общая панель — **5 вариантов размера/страницы PASS**, включая мобильную ширину 390.

## Установка и границы проверки

Образы `service:round-bundles` и `worker:round-bundles` устанавливаются штатным
скриптом только при отсутствии активных заданий/исполнителей. Состояния, раунды и
выбранные модели сохраняются. Отчёт: `audit/round-bundles-deployment.json`.

Модели и Minecraft в ходе этой проверки не запускались, задания не возобновлялись.
Смысловая связность будущего пакета зависит от качества планировщика; контроллер
проверяет его границы и зависимости, но не гарантирует правильность рассуждения.
Пакет из четырёх действий не обещает завершение четырёх требований за раунд.
У одного требования может быть несколько сценариев: лишние проверки остаются
незавершёнными, а окончательный PASS требует прежней независимой приёмки.

Этот набор изменений не исправляет отдельно обнаруженные числовые фрагменты ТЗ
и прежнюю метрику no_progress; они требуют самостоятельной миграции и проверки.
