# Учёт токенов Codex и API

Панель «Расход» использует общий endpoint /api/jobs/{jid}/usage. API сохраняет
учёт шлюза; common/token_usage.py дополняет его публичными usage из архивных
и активных журналов Codex. Один task_id учитывается один раз, копии журналов
не суммируются. Архив после завершения сохраняет статистику при очистке очереди.

Вход Codex уже включает cached_input_tokens. Он нормализуется в непересекающиеся
категории: input_tokens = полный вход минус кеш, cache_read_input_tokens = кеш.
input_tokens_total — полный вход; total_tokens = полный вход + output_tokens.
Reasoning не прибавляется к выходу повторно. saved_input_tokens равен кешу:
это экономия повторной обработки, не уменьшение контекста или квоты аккаунта.
Стоимость Codex неизвестна; денежная оценка API сохраняется отдельно.

Интерфейс показывает вход/выход, кеш и его долю по ролям. Отдельное окно содержит
ходы Codex, API-запросы, дни UTC и среднее Codex за активный день. Попытки без
итогового usage, некорректные события и усечение отмечаются явно. Codex обновляется
по завершении хода, текущий ход может быть не включён. При недоступности шлюза
статистика Codex остаётся доступной.

Доступ к журналам только для чтения через существующие безопасные history helpers.
Dashboard получил read-only mount planner-tasks внутри Codex-Development-Lab.
Файлы профилей, авторизация и .env не читаются. Результаты ограничены числами и
публичными метаданными попыток; текст запросов модели не включается.

Проверки: 791 тест, OK, 28 пропущены в Linux-контейнере без сети и монтирования
папок хоста. Контрольный рендер настоящей функции UI: вход 100, кеш 80, выход 20
даёт всего 120 и долю кеша 80%; неизвестная цена не становится нулевой ценой.
Независимый специалист проверил UI, безопасное чтение и отсутствие дублирования.

выход 268 584, кеш 40 935 936, всего 43 750 500, долю кеша 94,14%, 56 ходов,
четыре попытки без usage и отсутствие усечения. Это срез на момент проверки.
