# План ремонта без прочитанной диагностики

Дата: 2026-10-24. Задание Auto Defense `5babdfba708646`, раунд 50.

## Причина

Планировщик Gemma выбрал `repair_scenario / client-f8-releases-manual-controls`
и сослался в прозе на ошибку мыши, но не вызвал инструменты и не добавил
`action.evidence_refs`. Коррекция повторила тот же дефект. Контроллер правильно
остановил запуск кодера. Реальные log и JUnit доступны в `.lab-feedback`;
ошибка не означает потери файлов или отсутствия диагностики.

## Исправление

- Worker передаёт API-исполнителю признак обязательного чтения, когда экспортированы
  диагностические файлы.
- API-планировщик обязан выполнить чтение: используется поддерживаемый шлюзом
  принудительный выбор `read_lines`, пока не прочитан файл из индекса диагностики.
- Засчитывается только успешное непустое `read_file/read_lines` по точному пути
  экспортированного диагностического файла. Индекс, поиск, пустое чтение, другие
  файлы и ошибки инструментов не снимают ограничение.
- Финальный ремонт/диагностика без ссылок получает одно напоминание внутри того же
  задания, счётчика запросов и токенного бюджета; повторный отказ завершает попытку.
- Шаблон финального JSON явно содержит `action.evidence_refs`; подсказка коррекции
  называет недостающие поля и требование фактического чтения.
- Контроллер не фабрикует ссылки и сохраняет независимую проверку файлов, строк,
  точных цитат и завершённых результатов инструментов. Кодер и делегированные
  read-only специалисты не получают принудительный режим планировщика.
