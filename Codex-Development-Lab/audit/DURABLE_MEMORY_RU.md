# Полная память и ссылки на записи

Рабочая сводка и постоянная память теперь разделены. Сводка остаётся небольшой;
ошибки и заметки не удаляются из постоянного архива из-за возраста или количества.

## Где хранятся данные

Контроллер сохраняет архив задания:

```text
artifacts/<project_id>/<job_id>/memory-archive/
  index.json
  errors/<signature>.json
  notes/<round-or-00>-<hash>.json
  rounds/<round>.json
  reports/<round>-<report_hash>.json
  pages/errors-000001.json
  pages/notes-000001.json
```

Оригинальные отчёты и снимки раундов сохраняются отдельно. Первая миграция читает
все доступные прежние раунды, включая старше последних 30, и восстанавливает
ошибки, заметки и ссылки. Недоступные или никогда не записанные данные не
выдумываются. Старые ограниченные выдержки не превращаются в полный оригинал.

Изменённая версия отчёта сохраняется по отдельному хешу. Если старый отчёт
исправлен, статусы пересчитываются в хронологическом порядке: более ранняя
ошибка не должна перекрыть более позднюю успешную независимую проверку.

## Что получает агент

В `workspace/.lab-memory/` контроллер размещает доступные для чтения копии:
индекс, страницы ошибок/заметок, полные записи и публичные отчёты проверки.
У каждой записи есть источник, а в рабочей сводке — `archive_path` и счётчики
записей вне сводки. Агент читает конкретную запись через обычные инструменты
чтения; загружать весь архив в каждый запрос не требуется.

30 ошибок и 8 заметок — теперь только размер рабочей сводки, а не срок хранения.
Открытые ошибки имеют приоритет. Для заметки отдельно фиксируются известный
источник и наблюдение контроллером: неизвестный раунд происхождения остаётся
неизвестным. Неизменившаяся заметка не получает новый раунд происхождения после
проверки без кодера.

Заметки и предложенные решения остаются `UNVERIFIED`. Они не устанавливают PASS.
Истории разных версий ТЗ сохраняются раздельно по хешу спецификации.

## Где посмотреть пользователю

«Открыть память» → «Все ошибки» или «Все заметки».
Архив открывается постранично, запись — кнопкой «Прочитать запись целиком».
Сводка и исторические снимки по-прежнему доступны через выбор раунда.

Read-only API:

```text
GET /api/jobs/<id>/memory/archive?kind=errors&page=1
GET /api/jobs/<id>/memory/archive?kind=notes&page=1
GET /api/jobs/<id>/memory/archive/record?path=errors/<signature>.json
```

## Изоляция и ограничения передачи

Постоянный архив не читается из копии, которую мог изменить агент. Запись
контроллера использует безопасное открытие каталогов и атомарную замену файлов.
Символьная ссылка в `.lab-memory` не может направить экспорт за пределы проекта.
Приватные поля протокола не попадают в публичные копии. UI выводит данные текстом.
Копии `.lab-memory` не меняют хеш исходников мода.

Лимиты размера API-запроса, одной страницы интерфейса и рабочего контекста
сохраняются. Это ограничения передачи, а не удаление архивных данных. Для
отдельной записи больше 8 МиБ API явно сообщает `too_large`; оригинал остаётся
в архиве. Постоянный архив увеличивает расход диска и пока не имеет автоматической
политики удаления. Архив не является семантическим поиском или отдельной LLM.

Проверка: 916 тестов в Linux-контейнере, ошибок нет, 29 пропусков.
Проверки защиты от символьных ссылок выполнены на Linux. Навигация по архиву
и вывод недоверенного текста проверены отдельным Node.js-тестом.
API-агент читает записи больше 2 МиБ инструментом `read_file` по символьным
смещениям, без загрузки всего файла в оперативную память.

Перенос выполнен для пяти существующих заданий: 80 записей ошибок и 170 заметок.
Ошибок экспорта нет; хеши исходников, состояния заданий и номера раундов сохранены.
На живом API проверены доступ ко всем 33 ошибкам старого задания и 36 заметкам
текущего, а также открытие полной записи. Модели не запускались.
