# Разбор частичного FAIL

В приёмке и памяти раундов появились результаты каждой именованной проверки:
TEST_PASSED, FAIL, явно SKIPPED, отсутствие результата и UNKNOWN. Для FAIL
показано наблюдаемое сообщение JUnit, для отсутствующего результата причина
отмечается неизвестной. Возможное раннее завершение не объявляется доказанной
причиной. Частичный успех не закрывает исходный пункт ТЗ.

Новые запуски сохраняют testcase-факты в assertion_evidence.test_cases и
производный failure_details. Старые отчёты восстанавливаются из XML только
после проверки путей, типа файла, размера, UTF-8, SHA-256 и запрета DTD/entities.
Чтение не меняет канонические файлы или вердикты. Если сценарий уже STALE или
NOT_TESTED, последний незакрытый FAIL показывается отдельно как исторический,
с номером его раунда. Это не превращает старое доказательство в актуальное.

Для агентов добавлен ограниченный scenario-N-checks.txt в .lab-feedback.
Он перечислен в индексе рядом с исходным журналом и XML, помечен как
диагностические данные. Обычный контекст получает компактные счётчики; полный
разбор читается по необходимости. Причины не выдумываются моделью контроллера.

Исправлены две ошибки управления:

- Настоящий именованный assertion FAIL учитывается при рефлексии даже при
  отсутствии последующих testcase. Условия полного PASS не ослаблены.
- Назначенный diagnose_failure резервирует запуск своего сценария и учитывается
  в verification_limit. История раунда 49 на временной копии теперь выбирает
  self-defense-nearest первым. Следующий раунд 51 получает исправление после
  диагностики self-defense-radius-boundary.

Политика маршрутизации: reflection-routing-v2-early-failure. Старые подготовленные
решения заменяются по ревизии политики; ошибки и обязательства возврата сохраняются.
Лимит записи ledger остаётся 128 КиБ. При необходимости из его частной копии
убираются только восстанавливаемые новые подробности; исходные доказательства и
вердикт сохраняются в прежних границах, XML остаётся в артефактах.

Проверено: полный Linux-набор 824 теста, OK, 28 пропущены. Компонент UI проверен
на статусах, сохранении раскрытых секций и безопасном выводе HTML-подобного текста.
Независимые специалисты проверили маршрутизацию, парсер и интеграцию.

Реальные данные: раунд 48 self-defense-nearest — 4 пройденных, 1 FAIL, 2 без
результата; раунд 50 self-defense-radius-boundary — 3 пройденных, 1 FAIL, 1 без
результата. Игровые проверки и модели во время этой работы не запускались.
Состояния заданий, номера раундов и выбранные модели сохранены при установке.
