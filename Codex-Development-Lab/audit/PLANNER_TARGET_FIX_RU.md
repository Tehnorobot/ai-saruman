# Ошибка типа цели планировщика

Дата: 2026-10-24. Задание `fd124aec0a1647`, план раунда 5.

## Причина

Планировщик выбрал `implement_and_map_requirement`, но указал в `target`
`birch-inventory-cycle`. Это ID сценария, тогда как действие требует ID требования.
Контроллер обоснованно отклонил ответ, однако сообщил только «unknown requirement».
В ответе также неверно объявлены непроверенными сценарии, прошедшие в раунде 4.

## Изменения

- Планировщик получает `action_targets`: отдельные ID требований и сценариев,
  актуальные статусы сценариев и требования с ожидающим обзором покрытия.
- Инструкция явно связывает implement/review с REQ и repair/verify со сценарием.
- Ошибка различает неправильный тип цели, неизвестный ID и выход за текущую задачу.
- Успешный сценарий не выбирается повторно для реализации из-за нерешённой ошибки
  другого сценария. Устаревший или непроверенный сценарий допускает проверку.
- После завершённого невалидного ответа допускается одна коррекция той же моделью.
  Ответ не исправляется молча. Первоначальный журнал и ошибка архивируются;
  исправленный ответ проходит те же проверки, включая фактическое чтение цитат.
- Сбой провайдера, отмена и изменение исходников не запускают коррекцию.
- Для LiteLLM/DSLab дополнительный запрос использует только остаток первоначального
  резерва планировщика. Расход берётся из доверенных суммарных счётчиков шлюза,
  включая кэшированные токены и число запросов. Неизвестный расход или исчерпанный
  резерв запрещают автоматическую коррекцию. Резерв кодера не увеличивается.
- Состояние коррекции сохраняется с поколением запуска и хешем исходников, чтобы
  восстановление обработчика не создавало неограниченный цикл исправлений.

## Проверка

12 новых регрессионных тестов: пространства ID, актуальные сценарии, одна коррекция,
два отказа, сохранение журналов, восстановление лимита, недоступный учёт,
оставшийся API-бюджет и отмена пользователем.
Полный итоговый Linux-образ: 680 тестов, OK, 28 пропущены.
Независимый reviewer отдельно выполнил 27 связанных тестов — OK.

Модели и Minecraft в ходе исправления не запускались. Установка при паузе всех
заданий сохраняет раунды, состояния и модели. Отчёт установки:
`audit/planner-targets-deployment.json`.

Полное смысловое качество будущего ответа модели проверяется при следующем
пользовательском возобновлении. Успех существующего сценария по-прежнему не
подтверждает полноту всех условий ТЗ.
