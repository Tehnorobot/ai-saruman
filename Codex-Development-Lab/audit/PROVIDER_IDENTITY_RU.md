# Имена провайдеров и общего исполнителя

Внутренний API-исполнитель исторически называется `agent/dslab.py`, а контейнер
кодера API — `agent-dslab`. Оба обслуживают DSLab, LiteLLM и MiniMax.
Это имена компонентов, не маршрутизация на DSLab. `codex.jsonl` и
`codex_result.json` также являются совместимыми историческими именами артефактов.

Исправлены неверные пользовательские подписи:

- Общие ошибки исполнителя теперь используют API вместо DSLab.
- Ошибки контроллера показывают фактические provider/model/role, например
  `MiniMax / MiniMax-M3.1-Flash [planner] TIMEOUT`.
- При восстановлении используется провайдер сохранённой попытки, а не новый выбор
  в интерфейсе. Неизвестный провайдер обозначается Agent, без выдуманного Codex.
- События `turn.failed` содержат provider/model/role отдельными полями.
- Настройка размера истории называется `API_CONTEXT_BYTES`; старое
  `DSLAB_CONTEXT_BYTES` остаётся запасным вариантом для существующего `.env`.

Маршрутизация по provider, ключи и выбранные модели не менялись. Старые журналы
и уже сохранённые ошибки не переписываются. Исправленные подписи появляются
в новых попытках. Провайдер и модель — разные поля: например, провайдер MiniMax,
модель MiniMax-M3.1-Flash; LiteLLM — интерфейс доступа к моделям сервера.

Проверка: полный набор 899 тестов в Linux-контейнере без сети и пользовательских
подключений, OK, 29 пропусков. Compose config выполнен успешно.
Оплачиваемые запросы к моделям не выполнялись.
