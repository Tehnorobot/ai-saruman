# Восстановление после частичной работы кодера

Дата: 2026-10-24. Задание `fd124aec0a1647`, незавершённый раунд 4.

## Причина

Кодер изменил клиентские тесты и acceptance-plan, затем модель отказала с capacity.
При возобновлении контроллер обнаружил, что сохранённый план привязан к исходникам
до этих изменений. План был обоснованно отклонён и архивирован, но вместо нового
планирования контроллер вернул USER_PAUSED / planner_error.

## Исправление

- Устаревший план того же раунда и ТЗ теперь вызывает одно новое планирование
  в рамках текущего запуска; дополнительное нажатие «Продолжить» не требуется.
- План и инструментальный журнал архивируются вместе с сохранением прошлых архивов.
- Контекст обновляется, частичный код сохраняется; планировщик получает указание
  проверить существующие изменения перед выбором следующего шага.
- Очередь проверки и сведения об ошибочных сценариях сохраняются при обновлении.
- Ошибка нового планирования возвращается сразу: нет неограниченных повторов.
- Чужой раунд/другое ТЗ по-прежнему блокируются без вызова модели.
- Незавершённый транспорт планировщика не удаляется. Восстановление уже работающего
  кодера по прежнему checkpoint проходит без перепланирования.
- Публичный план содержит `checkpoint_replanned`; журнал поясняет причину замены.

Независимый обзор: блокирующих замечаний нет; замечание о сохранности архивов
при поздней гонке также исправлено.

Модели при проверке не вызывались. Задание автоматически не возобновлялось.

дополнительный барьер восстановления после него.
