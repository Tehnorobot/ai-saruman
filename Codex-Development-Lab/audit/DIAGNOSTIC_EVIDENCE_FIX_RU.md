# Исправление проверки диагностических ссылок

Дата: 2026-10-24. Задание `fd124aec0a1647`, остановка перед раундом 2.

## Причина

Планировщик выбрал ремонт `acceptance-plan.json` и сослался на прочитанные
`round-memory.json`, `acceptance-plan.json`, `tools/validate_acceptance_plan.py`
и `.lab-feedback/index.json`. Контроллер применял к этим диагностическим ссылкам
ограничение путей для обзора покрытия: только `src/` и `.lab-feedback/`.
Первая корректная ссылка на память раунда поэтому отклонялась с общим сообщением
`Invalid evidence path, lines or excerpt`. До кодера план не доходил.

## Исправление

- `common.coverage.read_evidence(..., diagnostic=True)` разрешает точный список
  файлов плана/памяти/ТЗ/Gradle и Python-валидаторы в `tools/`.
- `worker.engine` использует эту область только для `action.evidence_refs`.
- Обзор покрытия не получает расширенных прав и по-прежнему требует ссылки
  на исполняемые тесты.
- Сохранены проверка точного текста, диапазонов строк, фактического чтения
  инструментами и безопасное открытие файлов. Запрещены двоеточия, обратные
  слеши, абсолютные пути и обходы директорий.
- Добавлена поддержка многострочного вывода `nl -ba` при сопоставлении наблюдений.
- Сообщение об отказе теперь содержит индекс ссылки и конкретное нарушенное правило.
- Планировщик получает допустимый формат и список диагностических источников.
