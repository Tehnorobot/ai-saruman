# Независимая проверка skills

Дата: 20 октября 2026 года. Проверяющий отделён от автора реализации согласно AGENTS.md.

**Вердикт: PASS для исправления имени bundled skill, добавления code-quality и миграции установленных skills.** Это проверка лаборатории, а не приёмка Minecraft-мода.

Оригинальный `skill-creator/scripts/quick_validate.py` до исправления воспроизвёл ошибку имени `fabric-minecraft-1.21.11`. После исправления валидатор завершился с кодом 0 для каждого из четырёх skills:

Проверка выполнена локальным managed Python 3.10.15 с существующим PyYAML 6.0.3 из read-only cache; установка зависимостей не требовалась. Валидатор проверяет структуру и naming, но сам по себе не доказывает качество решений модели.

## Исполняемые регрессии

Новый `tests/test_skill_environment.py` проверяет наблюдаемое состояние синтетических проектов:

- установку всех настоящих bundled skills в новый проект и совпадение файлов с исходниками;
- повторную установку без перезаписи пользовательских skills, ресурсов, AGENTS.md, ТЗ.md и конфигурации агентов;
- миграцию старого каталога с сохранением пользовательского текста и бинарных ресурсов; отдельно проверены имена без кавычек и в обоих видах кавычек;
- конфликт старого и нового каталогов: сохранение текущего skill, архивирование старого вне discovery и сохранение уже существующего архива;
- исправление старого frontmatter в уже переименованном каталоге;
- сохранение пользовательского skill, не относящегося к миграции;
- отказ при symlink каталога или SKILL.md за пределы project skills без изменения внешней цели;
- отказ до перемещения каталога при небезопасном manifest;
- установку и миграцию до передачи управления исполнителю как для pending request, так и для recovered running task. Подменена только граница запуска задачи, Codex не запускался.

В Linux выполнены **все 10 новых тестов: PASS, без пропусков**. Команда использует существующий образ с текущими исходниками, подключёнными только для чтения; сеть отключена, Docker config пустой, авторизация не подключена:

```powershell
docker --config $emptyConfig run --rm --network none `
  --mount "type=bind,source=$repoPath,target=/src,readonly" `
  --workdir /src --env PYTHONPATH=/src --env LAB_DB=/tmp/lab.sqlite3 `
  codex-lab-service:fix-test python3 -B -m unittest discover -s tests -p test_skill_environment.py -v
```

На Windows тот же набор также выполнен: 8 тестов прошли, две настоящие symlink-проверки пропущены из-за WinError 1314. Эти два теста затем действительно выполнены в Linux; переносимая проверка порядка preflight выполнена в обеих средах.

## Применение code-quality к review

Проверяющий прочитал новый code-quality и применил его к небольшому реальному review жизненного цикла миграции. Найден случай, когда каталог перемещался раньше проверки symlink у manifest. Добавленная регрессия сначала завершилась FAIL. После исправления автором реализации preflight проверяет manifest обоих каталогов до rename/archive; та же регрессия прошла. Тест не был ослаблен.

В skill сохранены полезные принципы приложенного CLAUDE.md: явные существенные предположения, минимальные изменения, отсутствие посторонних рефакторингов и проверка наблюдаемого результата. Указания из приложенного документа использовались как материал для адаптации; они не заменяли запрос пользователя и правила проекта. Рутинные решения не требуют остановки и дополнительного согласования.

## Совместимость

Полный текущий набор выполнен в Linux тем же способом с `-m unittest discover -s tests -v`:

```text
Ran 60 tests in 6.253s
OK (skipped=4)
```

Фактически выполнены 56 тестов. Четыре пропуска относятся к ранее существующим отдельным средам: JavaScript/Node, проверке настоящего pinned CLI и двум Docker sandbox integrations. В этом изменении они повторно не выполнялись. Отдельный Windows-прогон всех 7 `test_codex_settings.py` также прошёл, включая передачу параметров fake Codex процессу.

Рабочие проекты, .env, секреты и сохранённая авторизация не читались и не изменялись. Настоящие модельные запросы и Minecraft не запускались. Образы использовались как тестовая среда с подключёнными текущими исходниками; пересборка production-образов и применение к работающей системе в эту проверку не входили.
