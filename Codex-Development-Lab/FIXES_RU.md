# Исправления по аудиту

Механизм запуска сборок дополнительно ограничен после этого аудита:
[ISOLATION_RU.md](ISOLATION_RU.md), независимая проверка —
[RUNNER_VALIDATION_RU.md](RUNNER_VALIDATION_RU.md).

Исправлены 11 пунктов из [AUDIT_REPORT_RU.md](AUDIT_REPORT_RU.md).
Независимые результаты запуска и ограничения приведены в
[FIX_VALIDATION_RU.md](FIX_VALIDATION_RU.md).

| № | Проблема | Изменение |
|---|---|---|
| 1 | Аргумент запуска Codex не поддерживался закреплённым CLI | Политика задаётся через `-c 'approval_policy="never"'`; Docker build проверяет разбор команды через настоящий `codex exec ... --help`. |
| 2 | Старый `CANCELLED` ломал возобновление | У каждой попытки собственный ID; pending-запрос атомарно переходит в running. Контроллер дожидается подтверждения отмены; результаты другой попытки не потребляются. |
| 3 | Перезапуск пропускал незавершённые тесты | Разработка и проверка имеют отдельные долговечные checkpoints. Незавершённая проверка повторяется в том же раунде без нового вызова модели. Учитываются прежние задания с `round=n, phase=verifying`. |
| 4 | После падения worker пауза/стоп застревали | Новый worker забирает просроченное задание даже с control flags, останавливает оставшийся executor/sandbox и только затем подтверждает паузу/стоп. |
| 5 | Build/test имели доступ к базе контроллера | Команды выполняются в отдельных Docker-контейнерах с одним workspace и временным export-каталогом. База, артефакты, mailbox, Docker socket и авторизация туда не монтируются. |
| 6 | В Docker-образе тестов не хватало модулей | Сервисный образ включает `worker` и `agent`; команда из README использует полный комплект модулей. |
| 7 | Kotlin DSL пропускал Minecraft | Определение проекта читает `build.gradle`, `build.gradle.kts` и `gradle.properties`. |
| 8 | Управление перезаписывало устаревший статус | Переход и событие выполняются одной SQLite-транзакцией. Продление lease и запись прогресса проверяют владельца. |
| 9 | SHA-256 manifest не совпадал с архивом | Хеш вычисляется по тем же байтам, которые передаются в tar. Агент, проверки и backup координируются project lock. |
| 10 | S3 игнорировал смену назначения/политики | Дедупликация учитывает endpoint, регион, bucket, prefix, длительность и версию обработки. Ссылки подписываются только для подтверждённой записи текущей политики. |
| 11 | Журнал замирал на 500 событиях | Панель догружает страницы через `after`, хранит отдельный курсор проекта и отображает последние 2000 полученных строк. |

Дополнительно fake Codex в исходных тестах сделан переносимым между Windows и Linux.
Для образа worker указан числовой UID, чтобы запуск не зависел от имени пользователя
в базовом Ubuntu-образе. Проверены пути wrapper/экспорта на выход из workspace.

## Как устроен изолированный запуск

`worker` — доверенный контроллер. Он получает `/var/run/docker.sock` и запускается
как root с ограниченным набором capabilities, чтобы управлять временными контейнерами.
Проектные команды не выполняются в этом процессе: при недоступном Engine команда
заканчивается ошибкой без локального fallback.

Временный runner работает как `1000:1000`, с read-only корневой файловой системой,
отключёнными capabilities, отдельным `/tmp` и только двумя bind mounts:
workspace одного проекта и одноразовый `/output`. Runner не присоединяется к сети
Compose; стандартная Docker bridge используется для загрузки зависимостей.
Gradle/npm/Maven caches хранятся в `workspace/.lab-cache/` и не входят в backup.
Имена host bind mounts определяются через Docker inspection доверенного контроллера,
что поддерживает пути Docker Desktop без ручной настройки Windows-путей.

Для Minecraft Xvfb, ffmpeg и Gradle запускаются внутри одного runner. Видеозапись
по-прежнему ограничена 58 секундами и не считается доказательством игровой приёмки.

Контейнер принудительно удаляется при отмене/таймауте. Перед стартом сохраняется
`.lab-runner.json` вне workspace. Если удаление не подтверждено, задание прекращается,
а агент и backup не получают доступ к проекту до очистки контроллером. После сбоя
контроллер удаляет оставшийся runner до нового изменения исходников.

## Применение в существующей установке

Из каталога проекта:

```powershell
docker compose build dashboard worker runner
docker compose up -d --no-build --force-recreate
```

Существующие `.env`, исходники, очередь и том авторизации сохраняются.
Каталог прежнего механизма `runner-output/` больше не используется. Временные
копии хранятся в закрытом Docker volume. Прямой доступ worker к Docker Engine
удалён. Переход со старой установки описан в [ISOLATION_RU.md](ISOLATION_RU.md).

Тесты лаборатории:

```powershell
docker compose run --rm dashboard python3 -m unittest discover -s tests -v
```

Опциональные проверки Docker-изоляции и закреплённого CLI требуют специального
одноразового стенда; точные команды и результаты фиксирует независимый verifier.
Настоящие модельные обращения, S3 и Minecraft не заменяются синтетическими тестами.
Скрипты `audit/reproduce_*` сохраняют историческое воспроизведение ошибок до
исправлений; актуальные ожидания находятся в регрессионных тестах `tests/`.
