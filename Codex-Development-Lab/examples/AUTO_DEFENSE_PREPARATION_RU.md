# Как использовать единое ТЗ Auto Defense

В веб-панель загружать только [ТЗ_Auto_Defense.md](ТЗ_Auto_Defense.md).
Этот файл заменяет функциональные требования `AUTO_DEFENSE_SPEC.md` и
`SARUMAN_AUTO_DEFENSE_SPEC.md`. Копия в Downloads и исходные документы в
проекте Saruman не изменялись.

## Что объединено

- Универсальный мод: самостоятельная установка, бой, навигация, жизненный цикл,
  публичный API, HUD, ограничения и все 26 исходных игровых сценариев приёмки.
- Профиль Saruman, JVM-арбитраж UnionClef, тонкий Python-адаптер, выбор
  current/native/auto, восстановление задач, Gradio и проверки связки.
- Контекст существующего bridge и пакет подключения персонажа. Для обычного
  игрока Saruman, Python, Redis, Gradio и сторонние моды не нужны.

Универсальность ядра и обязательность результата интеграции разделены:
разработчик должен подготовить оба результата, но владельцу обычного клиента
достаточно основного JAR. Бой не переносится в Python.

## Что уже предоставляет лаборатория

Worker добавляет `AGENTS.md`, skills и инструкции разработки в workspace.
Для Fabric 1.21.11 он направляет агента к
`.agents/skills/fabric-minecraft-12111/IMPLEMENTATION_GUIDE.md`.
Это руководство в текущем проекте побайтно совпадает с исходным
`AUTO_DEFENSE_IMPLEMENTATION_GUIDE_1_21_11.md`; его не нужно дублировать в ТЗ.

Из примера убраны ссылки на отсутствующие входные Markdown, повторяющиеся
общие указания агенту, таблица рекомендуемых классов и повторные ссылки на
инженерные примеры. Настройка Docker, Codex login, секретов, backups, S3 и правил
делегирования относится к лаборатории и не включается в ТЗ мода.

Сохранены требования к версиям зависимостей, Gradle Wrapper и production JAR:
установленные в контейнере JDK и Gradle не заменяют воспроизводимый проект,
который должен собираться и на другом компьютере. Сохранены игровые ограничения
и критерии приёмки: встроенный skill сам по себе их не заменяет.

## Что один Markdown не заменяет

Контейнер не получает доступ к соседнему проекту Saruman или установленным
Minecraft-модам на Windows. ТЗ достаточно для постановки задачи, реализации
ядра и публичного контракта; точный патч действующего runtime и подтверждение
совместимости требуют его исходников, точных JAR и игрового стенда.

Если эти ресурсы нужны для следующего этапа:

1. Загрузи ТЗ, поставь созданное задание на паузу и дождись `USER_PAUSED`.
2. Найди его `projects/<project-id>/workspace/` внутри лаборатории.
3. Помести безопасную копию необходимых исходников Saruman, тестов и описания
   зависимостей в `integration-inputs/saruman/`, сохранив относительные пути.
   Требуемые JAR положи в `integration-inputs/mods/`.
4. Не копируй `.env`, авторизацию, ключи, личные данные или живой мир. Затем
   продолжи задание. Исходный проект Saruman остаётся за пределами контейнера.

Точные участки runtime перечислены в разделе 20.2 ТЗ. Доступность API или
mock-тесты не считаются подтверждением игры и реальной передачи управления.
Порядок включения игровых тестов и согласия с EULA остаётся в README лаборатории.

Результат проверки именно документа: [AUTO_DEFENSE_SPEC_REVIEW_RU.md](AUTO_DEFENSE_SPEC_REVIEW_RU.md).
