# Запросы и история агентов

В панели выбери проект и открой раздел **«История агентов»**.
Выбери попытку в списке: показаны раунд, статус запуска, модель и время.
В раскрываемом блоке **«Исходный запрос»** находится задание, отправленное
контроллером агенту. Ниже — сообщения, команды, результаты инструментов,
поиски и изменения файлов, экспортированные Codex CLI.

История обновляется каждые пять секунд. **«Загрузить ещё»** читает следующую
страницу, **«С начала»** возвращает к началу выбранного журнала. В браузере
хранятся последние 1000 загруженных событий; полный файл остаётся на диске.
Открытые блоки и выбранный фильтр сохраняются при опросе.

Фильтр агентов заполняется только наблюдаемыми идентификаторами. Названия
архитектора/тестировщика не означают, что они действительно были запущены.
Если CLI экспортирует делегирование, видны переданный запрос и идентификаторы
получателей. Полные отдельные диалоги дочерних агентов могут отсутствовать:
панель не получает внутренних HTTP-запросов модели и не читает хранилище
авторизации Codex. Доступные сообщения и действия не равны скрытым рассуждениям.

## Что сохраняется

Новый worker до отправки задания записывает оригинальный запрос, а перед
удалением транспорта сохраняет журнал и результат каждой попытки:

```text
artifacts/<project-id>/<job-id>/round-01/agent-history/<attempt-id>/
  request.json
  events.jsonl
  result.json
  meta.json
```

Повтор после квоты/отмены получает свой каталог; история не перезаписывается
последней попыткой раунда. При восстановлении используется фактически сохранённый
запрос, а не заново составленный текст с новыми настройками.

Пока агент работает, панель читает его журнал из `agent-tasks/logs/` и запрос
из `agent-tasks/running/` или `requests/`. Эта папка подключена к dashboard
**только для чтения**. Docker socket и volume авторизации панели не выдаются.

Старые `artifacts/<project-id>/<job-id>/round-01/codex.jsonl` тоже доступны.
Если исходный запрос старой попытки уже удалён, панель прямо сообщает, что
он не сохранён. Прошлые запросы и перезаписанные попытки задним числом не
восстанавливаются. Статус успешного запуска Codex не означает игровую приёмку мода.

## Обновление существующей установки

Для просмотра имеющихся журналов и активного запроса достаточно обновить
только веб-панель, не перезапуская исполнителей:

```powershell
docker compose build dashboard
docker compose up -d --no-deps --force-recreate dashboard
```

Для постоянного архива всех будущих попыток требуется также новый worker.
Перед его обновлением поставь активные задания на паузу и дождись
подтверждения `USER_PAUSED`. Затем пересобери и пересоздай лабораторию:

```powershell
docker compose build dashboard worker runner
docker compose up -d --no-build --force-recreate
```

Не запускай создание проекта повторно ради обновления интерфейса.
Обычное обновление вкладки состояние задания не меняет.

Результаты независимой проверки: [HISTORY_VALIDATION_RU.md](HISTORY_VALIDATION_RU.md).
