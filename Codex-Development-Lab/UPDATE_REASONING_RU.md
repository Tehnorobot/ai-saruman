# Обновление: выбор модели и уровня reasoning

В веб-панели `http://localhost:8080` теперь можно выбирать модель Codex и уровень reasoning **перед загрузкой ТЗ.md**. Пустое поле модели означает конфигурацию Codex по умолчанию. Выбор reasoning: `default`, `low`, `medium`, `high`, `xhigh`, `minimal`, `none`. Последние два значения доступны не для всех моделей, а доступ к моделям определяется твоей авторизованной сессией Codex.

После создания проекта модель/уровень видны в карточке и деталях задания. На странице проекта есть раздел **«Изменить модель / reasoning для следующих циклов»**. Если задание активно, сначала нажми «Пауза», дождись состояния `USER_PAUSED`, сохрани выбор, затем нажми «Продолжить». Во время активного вызова изменения заблокированы. После квоты и перезапуска Docker последние сохранённые значения остаются в SQLite.

## Обновление существующей лаборатории

1. Не удаляй текущие папки `.env`, `data/`, `projects/`, `artifacts/`, `backups/`, а также Docker volumes.
2. В PowerShell в старой папке выполни `docker compose stop`.
3. Распакуй обновлённый ZIP поверх существующей папки `Codex-Development-Lab`, соглашаясь заменить файлы. Архив **не содержит** `.env` с твоими секретами.
4. Пересобери обновлённые образы:

   ```powershell
   docker compose build dashboard worker runner
   docker compose up -d --no-build --force-recreate
   ```

5. Открой `http://localhost:8080` и проверь оба новых поля. Повторная авторизация Codex не требуется, если не удалял том `codex_auth`.

Если используешь чистую установку — просто запусти `START_WINDOWS.ps1`, как раньше.
При переходе со старого механизма сборок сначала выполни инструкции
[ISOLATION_RU.md](ISOLATION_RU.md), чтобы не оставить работающий старый контейнер.

## Как настройки доходят до Codex

Рассмотрим выбранные `gpt-6-sol` и `high`. Исполнитель вызывает Codex отдельными argv-аргументами:

```bash
codex exec --model gpt-6-sol -c 'model_reasoning_effort="high"' ...
```

Использование модели, к которой нет доступа, или неподдерживаемого уровня приведёт к явной ошибке в логах; **без автоматического переключения на платный API или другую модель**.

## Проверки

Локально пройдены **20 тестов**, включая: сохранение опций в SQLite, миграцию старой базы без удаления заданий, прохождение model/reasoning до аргументов Codex CLI (с фальшивым исполняемым файлом без обращения к сети), блокировку смены во время RUNNING и прежние тесты очереди/бэкапа/S3. JavaScript проверен `node --check`, Python-модули — `compileall`. Настоящие Docker/Codex/Minecraft не запускались в среде упаковки.
