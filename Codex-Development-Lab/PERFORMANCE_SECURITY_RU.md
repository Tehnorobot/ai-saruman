# Ускорение и изоляция лаборатории

Обновление от 21 октября 2026 года. Актуальные настройки находятся в `compose.yaml`,
`runner/policy.py` и `worker/verification_plan.py`; прежние отчёты описывают состояние
до этого обновления.

## Что ускорено

- Сборка, обнаружение игровых задач и клиентский тест выполняются в одном
  контейнере проверки. Исходники передаются и возвращаются один раз за раунд.
- Зависимости Gradle, `.gradle` проекта и `build` остаются в отдельном каталоге
  Linux volume, разделённом по project ID. Они не копируются через Windows при
  каждой стадии. Агент также получил постоянный Gradle volume.
- Gradle использует `--daemon --build-cache --max-workers=4`, JVM — до 2 GiB heap
  и четыре процессора. Daemon помогает внутри одного контейнера; между раундами
  сохраняется дисковый кэш, а не работающая JVM. Configuration cache не включён
  из-за различий совместимости плагинов.
- После неудачной сборки игровой этап не запускается. Задачи обнаруживаются один
  раз. Видео пишется только во время игрового этапа и заканчивается вместе с ним;
  предел 58 секунд не превращается в обязательную задержку.
- Отчёт содержит время упаковки, передачи, выполнения, возврата и очистки, а также
  объёмы архивов. JAR экспортируется в `artifacts/<project>/<job>/.../builds/`.

## Что ограничено

Папки Windows подключаются только из разрешённого набора подпапок лаборатории.
Корень лаборатории с `.env`, соседние проекты, Downloads и профиль Windows не
подключаются. `START_WINDOWS.ps1` проверяет итоговый Compose, включая overrides,
права подключения, junction/symlink в путях и метаданные существующих volumes.
Проверка запрещает подмену команд, healthcheck и hooks доверенного runner/прокси.

Агент и контейнер проверки не имеют Docker socket. Только небольшой доверенный
runner управляет Engine; у него нет папок Windows, авторизации или TCP-сети.
Его API не принимает пути хоста, образ или произвольную конфигурацию Docker.
У задания — только копия workspace, кэш собственного проекта и защищённый экспорт.
Команды проекта работают как UID/GID 1000 без capabilities; root-supervisor
отдельно сохраняет отчёт и не исполняет проектный код со своими правами.

Агент и проверки используют разные internal bridge-сети с `isolated` gateway.
Выход в Интернет проходит через rootless HTTP/CONNECT-прокси. Он разрешает только
публичные IP на портах 80/443, проверяет все DNS-ответы и подключается к проверенному
числовому адресу. Частные, loopback, link-local и переходные IPv6-адреса запрещены.
TLS не расшифровывается, содержимое запросов не журналируется. У worker, backup,
runner и init-сервиса сеть отключена. Панель опубликована только на `127.0.0.1`.
HTML/XML артефакты скачиваются как вложения с sandbox CSP и `nosniff`.

Граница доверия включает Docker Desktop, ядро VM, образы и код контроллера.
Проверка запуска не защищает от намеренного изменения самого проверяющего кода
владельцем компьютера. Авторизация Codex доступна его агенту; агент пока видит все
проекты этой лаборатории. Постоянные кэши не имеют дисковой quota и могут расти.
Удаление кэшей или изменение настроек Windows/Docker Desktop автоматически не
выполняется.

## Подтверждённые проверки

- Финальный сервисный образ: 191 найденный тест, 186 выполнены успешно, 5 пропущены
  (отдельные Node/CLI/Docker-проверки). Лог: `audit/performance-linux-tests-final.log`.
- 28 опасных вариантов Compose отклонены; стандартная конфигурация и метаданные
  существующих volumes приняты: `audit/isolation-admission-result.json`.
- Настоящий контейнер задания не подключился напрямую к
  `host.docker.internal:8080` и `1.1.1.1:443`. Прокси отверг семь локальных/частных
  целей на разрешённом порту 443. HTTPS Maven с проверенным TLS вернул 200:
  `audit/performance-security/network/network.json`.
- Проверка повторена после обновления на рабочем runner, включая HTTPS из Java
  через JVM proxy properties: `audit/performance-security/network-production/network.json`.
- В реальной Java-сборке проверены UID 1000, нулевые capabilities, запрет записи
  в защищённый отчёт, отсутствие служебных сокетов и чужих проектов, сохранение
  кэша между контейнерами и возврат настоящего JAR.

Замер выполнен без сети на небольшом Java-проекте с 400 файлами, отдельной задачей
`smoke` с исполняемыми Java assertions и встроенным в образ Gradle. Перед вторым
запуском изменён исходник; `compileJava` действительно выполнялся. Это не JUnit
или игровой Minecraft-тест.

| Измерение | Первый запуск | Повторный запуск |
| --- | ---: | ---: |
| Полный цикл, с передачей и очисткой | 10,874 с | 9,703 с |
| Команда Gradle с Java-проверкой | 4,477 с | 3,424 с |
| Отправленный workspace | 829 440 байт | 829 440 байт |

Для того же набора исходников с синтетическим старым кэшем прежний архив занимал
5 160 960 байт: новый меньше в 6,22 раза. Это сравнение архивов, а не обещание
ускорения всего создания мода в 6,22 раза. Полные результаты и JAR:
`audit/performance-security/benchmark-complete/`.

Ранние неудачные проверки стенда сохранены отдельно: сначала fixture ошибочно
требовал отсутствия даже пустого `/projects` из образа, затем Gradle 9 отверг
обычный Java main в JUnit source set. Fixture исправлен на отдельный smoke source
set; проверки продукта не отключались. Итоговый каталог — `benchmark-complete`.
Minecraft и модельные запросы при этих замерах не запускались. Холодная загрузка
Minecraft/Fabric, старт JVM/клиента и программный рендеринг остаются затратами,
которые этот небольшой замер не оценивает.

## Запуск и обслуживание

```powershell
powershell -ExecutionPolicy Bypass -File .\START_WINDOWS.ps1
```

Понадобится Docker с поддержкой bridge gateway mode `isolated` (Engine 28+);
проверенная локальная версия — 29.8.2. В `.env` новых обязательных значений нет.
Существующий Codex login volume сохраняется. Не используйте `docker compose down -v`
для обновления. Полная схема доступа и восстановление: [ISOLATION_RU.md](ISOLATION_RU.md).

Обновление применено к `dashboard`, `backup`, `worker`, `agent`, `runner` и `egress`.
Все семь рабочих сервисов запущены; runner и proxy healthy, `/healthz` отвечает.
Прежний контейнер storage и его настройки сохранены, `codex login status` показывает
`Logged in using ChatGPT`. Задание `16c911fc0fbf4d` осталось `FAILED`; модельные
раунды автоматически не возобновлялись. Фактические подключения контейнеров,
сети и сохранение статуса проверены: `audit/performance-security/deployment.json`
и `runtime-verification.json`. Временные runner/proxy и их scratch volumes удалены;
файлы с доказательствами сохранены.

Основания сетевых настроек: [Docker gateway modes](https://docs.docker.com/engine/network/port-publishing/#gateway-modes),
[ограничения internal network](https://docs.docker.com/reference/cli/docker/network/create/#network-internal-mode---internal),
[настройки прокси Gradle](https://docs.gradle.org/current/userguide/networking.html#sec:accessing_the_web_via_a_proxy).
