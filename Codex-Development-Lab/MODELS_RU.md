# Модели агентов

Откройте проект в панели и блок «Модели по ролям». Кнопки «Планировщик» и
«Кодер» открывают отдельные настройки провайдера, модели и reasoning.
Изменение разрешено на паузе и до запуска. Наследование использует общие
настройки задания. Вложенные специалисты используют настройки исполнителя;
независимый проверяющий остаётся программным.

Модель выбирается из выпадающего списка. Каталог Codex сверён с видимыми
метаданными CLI 23.10.2026: GPT-6.1 Sol, GPT-6 Astra/Sol/Luna и GPT-5.6
Sol/Terra/Luna. Для каждой показаны поддерживаемые CLI уровни reasoning,
включая max и ultra там, где они перечислены в каталоге. Это каталог Codex,
а не всех моделей приложения ChatGPT; доступ аккаунта может изменяться.
Сохранённые старые модели вне каталога явно отмечены.

Для всех пяти пользовательских моделей LiteLLM доступно только «По умолчанию»;
шлюз не отправляет переключатель reasoning. Для поддерживаемых DSLab моделей
Claude Sonnet 5.5 и Opus 5.5 доступны low, medium, high, xhigh, max.
«По умолчанию» соответствует high у Sonnet и medium у Opus. Другие Claude
не выдаются за доступные через DSLab без подтверждения поддержки провайдера.

Для LiteLLM задайте самостоятельно в `.env`:

```dotenv
LITELLM_BASE_URL=https://your-server.example/v1
LITELLM_API_KEY=your-key
```

После изменения выполните `docker compose up -d --no-deps --force-recreate provider-gateway`.
Делайте это на паузе задания. Ключ передаётся только шлюзу; агентам доступны
ограниченные временные разрешения. URL не вводится в интерфейсе. Используется
публичный HTTPS сервер; прокси блокирует локальные и частные адреса.
Для сервера пользователя отдельно разрешён `http://lnsigo.mipt.ru:4000/v1`.
Это точечное исключение для данного домена и порта; проверка публичного DNS
сохраняется. HTTP передаёт ключ без шифрования. Полный путь
`/v1/chat/completions` также допустим как значение базового URL.

Сервер должен поддерживать OpenAI chat completions, streaming, tool calls и
`stream_options.include_usage`. В LiteLLM настройте публичные имена моделей
точно как в каталоге интерфейса. Отсутствующие usage остаются неполным учётом.
Тарифы вашего сервера неизвестны: для LiteLLM отображаются токены, стоимость
помечается как ненастроенная и не заменяется тарифом Claude.

Клиент LiteLLM использует `AsyncOpenAI` по примеру
`agentic_memory-dev/models/llms/clients/openai_client.py`: адрес и ключ задаются
при создании клиента, запросы идут через `chat.completions`. SDK закреплён
в зависимостях; автоматические повторы отключены (`max_retries=0`). Из примера
не переносится подстановка reasoning вместо ответа: агент обязан вернуть
финальный текст или вызов инструмента. Секреты и бюджет остаются в шлюзе.

Планировщику нужны текст, вызов инструментов и точный JSON; для сложной
диагностики полезен reasoning. Кодеру нужны работа с инструментами, Java,
Gradle и Fabric. Текущие агенты получают текст и результаты инструментов;
поддержка фотографий моделью не включает визуальный анализ автоматически.

Контекст, память и диагностические файлы не сокращены. Лимиты платного API
сохраняются: 20% планировщику (минимум 1000), остальное кодеру. Ошибки API
ставят работу на паузу; автоматических платных повторов нет. Codex-вызовы
учитываются средствами подписки и не входят в API-счётчик шлюза.
