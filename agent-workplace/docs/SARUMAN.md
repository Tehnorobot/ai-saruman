# Настройка Сарумана

Персонаж подготовлен по описанию проекта из ../homework.md. Основной язык общения —
русский, язык рабочей памяти — английский, как предусмотрено шаблоном.

## Файлы персонажа

| Файл в agent/saruman/ | Назначение |
| --- | --- |
| PERSONA.md | Неизменяемое ядро: личность, речь, мотивы, настроение и игровые склонности; ниже — явно редактируемые привычки. |
| SESSION_PROMPT.md | Порядок чтения контекста, обработки сообщений, действий и сохранения памяти. |
| GOALS.md | Постоянные цели самого персонажа. |
| TOOLS.md | Существующие скрипты и контракты будущего игрового адаптера. |
| memory/state.md | Начальное состояние с неизвестными игровыми данными, затем — краткое состояние между сессиями. |
| memory/MEMORY.md | Индекс заметок о сущностях. |
| memory/entities/ | Изначально пустая память об игроках, местах и событиях. |
| inbox.jsonl, outbox.jsonl | Изначально пустые очереди сообщений. |
| state/sleep.txt | Начальный интервал следующего пробуждения: 15 минут. Персонаж может менять его. |

Примеры реплик в PERSONA.md не создают знакомства и события. Числа здоровья,
урона и перезарядки, скин, конкретный мод и игровые способности остаются
неопределёнными до выбора реализации и получения данных от сервера.

## Проверка и сборка контекста

Из корня репозитория:

```bash
python3 tools/check.py
python3 tools/compose_session.py saruman
python3 tools/compose_session.py saruman --from-operator 'После подключения осмотри окрестности и выбери место для сада.'
```

Последняя команда только показывает промпт с разовым поручением. Она не вызывает
модель и не изменяет GOALS.md. Сохранение поручения делает агент во время выполнения;
будущий раннер отвечает за надёжную доставку и учёт уже переданных сообщений.

Сборщик автоматически включает необязательный TOOLS.md, если он есть у персонажа.
Для персонажей без этого файла порядок и содержимое остальных блоков сохранены.

## Что уже подготовлено

Описание самостоятельного нейтрального мага, цели, память, очередь общения и
инструкция сессии готовы для подключения к раннеру. Настроение влияет на решения,
отношения обновляются по событиям, речь сопровождает осмысленные игровые действия.

Общее руководство agent/AGENTS.md согласовано с двухчастной PERSONA.md: ядро меняет
оператор, явно выделенный раздел развития может редко уточнять сам персонаж.
Это правило поведения; файловая система сама не защищает отдельные разделы файла.

## Что подключить для первого игрового прототипа

1. Выбрать версию Minecraft, загрузчик/мод и способ управления мобом. Задать скин,
   здоровье и способности на стороне игры.
2. Реализовать наблюдение и действия по контрактам из agent/saruman/TOOLS.md.
   Для начала достаточно observe, inspect, перемещения и игрового чата;
   затем добавить лошадь, бой, посадку и земледелие.
3. Подключить выбранную модель и цикл сессии: собрать контекст, предоставить реальные
   инструменты, исполнить вызовы, сохранить память и обработать следующее пробуждение.
4. Связать входящие события с inbox и исходящую очередь с реальными получателями.
   Текущий шаблон определяет отвеченность по получателю и времени, а не по ID сообщения;
   перед параллельными диалогами нужны ID, подтверждения доставки и защита от повторов.
5. Проверить в игре характер, память о встречах, отказы, помощь, бой и ошибки инструментов.
6. Затем добавить TTS/STT, Telegram, видеоконтент и стриминг YouTube/Twitch.

Раннер фиксирует AGENT_NAME=saruman и запускает текущие локальные скрипты из корня
репозитория. Сам персонаж может работать относительно agent/saruman/; пути для
обёрток задаёт раннер. Ограничение записи и разрешённые вызовы обеспечиваются
средой выполнения. Общий ticket.sh пишет вне папки персонажа, поэтому Саруман
передаёт такие обращения через outbox получателю operator.

На этом этапе сборщик не создаёт подключение к Minecraft, не отправляет сообщения,
не публикует контент и не запускает модель или планировщик.
