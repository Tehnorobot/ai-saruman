## Совместимость памяти поиска с RedisNestedDict

### Investigate
- Runtime вернул RedisNestedDict для game.tree_search. Новый поиск ожидал dict,
  вызвал отсутствующий clear(); далее отсутствовал бы setdefault(), а изменения
  вложенных списков не сохранялись бы. Предыдущие тесты использовали обычный dict.
- RedisDict.__setitem__ сериализует значения в JSON, поэтому обратная запись самой
  proxy-обёртки также недопустима: fallback default=str превратил бы её в строку.

### Plan
- На границе обоих инструментов делать независимый обычный снимок памяти;
  после успешного вызова явно сохранять dict. Общую Redis-обёртку не изменять.
- Проверить настоящие RedisDict/RedisNestedDict и JSON-кодек с изолированным
  hash-транспортом, без доступа к рабочим данным Redis или изменения мира.

### Implement
- [x] find_tree_planting_spots и grow_tree используют deepcopy(dict(state.items())).
  clear/setdefault и вложенные списки работают локально; результат явно записывается
  в game.tree_search. Исключение во время обзора не сохраняет частичное состояние.
- [x] Добавлены две интеграционные проверки: оба инструмента через StructuredTool
  с настоящими Redis proxy, первый/повторный обзор, следующий участок, смена породы,
  сброс операторским заданием; отдельно ошибки без частичной записи в dict/Redis.
- [x] Целевой прогон: 71/71. Синтаксис изменённых модулей и diff --check прошли.
  Модель, живые игровые действия и рабочие данные Redis не использовались.
- Применение: перезапустить Python-runtime и отправить задание заново.
  Git commit/push не выполнялись.
