# PersonaAgent и ActionAgent

В модовом режиме `SARUMAN_AUTOMATION_MODE=mods` персонажем управляет HybridAgent.
Прежние ChatAgent, PlannerAgent, CoreAgent и ReactionAgent в этом режиме не создаются
как рабочие агенты. Их код сохранён для явного legacy-режима.

## Роли и поток

| Роль | Вход | Результат | Полномочия |
|---|---|---|---|
| PersonaAgent | Исходное обращение, решение/факты, личность и предыстория, недавние реплики | `chat_text`, `voice_text`, `emotion`, `needs_action` | Только публичный текст |
| ActionAgent | Неизменённая просьба игрока, контекст предыдущих просьб, наблюдения, схемы инструментов | Решение, мотив, проверяемые предложения инструментов | Ограниченный набор игровых инструментов через runtime |
| Runtime и моды | Принятые цели, текущая ситуация | Реальные действия и подтверждённые результаты | Очередь, снабжение, TreeGrow, Auto Defense |

У ролей отдельные последовательные рабочие потоки. Медленная генерация речи
не блокирует решения; медленное решение не блокирует простую беседу. Игровые действия
не выполняются параллельно двумя моделями: ими распоряжается только ActionAgent,
а очередь и нативные проверки владения остаются обязательными.

Очевидное приветствие/благодарность или простая просьба рассказать о себе идут прямо
PersonaAgent. Остальные обращения консервативно передаются ActionAgent: сложную
просьбу нельзя потерять из-за ошибки дешёвой модели. Если PersonaAgent заметил
пропущенную просьбу, он может запросить передачу один раз; диспетчер передаст
**оригинал**, а не его пересказ. Этот флаг не содержит команд и не исполняет действий.
Такая маршрутизация экономит на очевидных беседах, но не обещает классифицировать
любую свободную фразу без сильной модели.

Предварительная реакция до решения не запускает отдельный запрос к PersonaAgent:
медленный ответ не должен занимать речевой поток перед фактическим результатом.
Устаревшие задания озвучки отбрасываются. После принятия цели и её результата
публикуется актуальная реакция. Срок ожидания речи учитывает тайм-аут её модели,
а смена фазы, остановка и смена мира по-прежнему отменяют старые реплики.
Один вызов PersonaAgent возвращает и текст чата, и текст голоса; второго запроса
для озвучки нет. Звук по-прежнему синтезирует Fish TTS, не языковая модель.

В разговор PersonaAgent получает до двух тематических воспоминаний из включённого
банка предыстории. Локальный подбор чередует недавние эпизоды без отдельного запроса
к модели; это художественное прошлое, не наблюдения текущего мира.
Самостоятельная речевая инициатива после 3–5 минут тишины использует только PersonaAgent
и её бюджет. Во время боя, активного поручения или звучащей речи она не запускается;
новое обращение отменяет устаревшую реплику. Инициатива не передаётся ActionAgent
и не создаёт игровых целей. Для отключения: `SARUMAN_PERSONA_INITIATIVE_ENABLED=false`.

## Граница управления

PersonaAgent не получает описаний инструментов или исполнительного интерфейса.
Его текст никогда не проходит через парсер команд. Строки, начинающиеся с `/`, `@`,
`!` или `$`, отклоняются при публикации; скрытые дополнительные поля JSON также
отклоняются. Его реплики остаются контекстом беседы, но не превращаются в факты
игровой памяти, подтверждения выполнения или новые поручения.

ActionAgent выбирает только разрешённые инструменты: наблюдения, `grow_trees`,
`stop_tree_growing`, отмена целей, получение предмета и обычные guarded-команды. Он не может вызвать
`chat`, `voice_send`, `speak`, изменять настройки инструментов или выдавать личные
реплики за инструмент. Сначала проверяется вся пачка предложений, включая схемы
аргументов; за один раунд допускается не более одного изменяющего мир инструмента.
После его принятия агент ожидает результат очереди, не строит зависимые шаги вслепую.

«Прекрати выращивать деревья» требует `stop_tree_growing`: он обнуляет только вес
фоновых деревьев в существующих настройках и отменяет все текущие цели trees.
Другие занятия и команды не отменяются. Новый явный `grow_trees` по просьбе игрока
по-прежнему допустим; фон оператор может вернуть переключателем в Gradio.
`cancel_mod_goal` отменяет конкретную задачу, принимает её ID либо фактический run ID
и возвращает отклонение для неизвестного ID, без ложного подтверждения отмены.

Для деревьев один `grow_trees(N)` запускает модовую цель; дальнейший счёт не требует
LLM между деревьями. Если модовая цель покрывает всю просьбу, по её итогам вызывается
только PersonaAgent. Для составной просьбы вроде «вырасти два дерева, потом подойди»
ActionAgent получает подтверждённый результат и выбирает следующий шаг. Для
нестандартной команды ActionAgent также получает исходную просьбу
и результат, наблюдает мир и при необходимости выбирает следующий шаг.

Все ограничения исходной просьбы сохраняются. Например, «два дуба без костной муки»
нельзя превращать в TreeGrow: установленный мод не поддерживает строгую породу,
запрет костной муки или запрет своей выдачи `/give`. ActionAgent должен сообщить
о несовместимости или запросить уточнение. Бой/плавание/отступление/снабжение не
перенесены обратно на LLM; Auto Defense и runtime продолжают работать независимо.

## Выбор моделей в Gradio

В Control находится блок **«Агенты и модели»**. Внутри — отдельные раскрываемые
окна настройки PersonaAgent и ActionAgent. Для каждого задаются:

- провайдер: Codex / ChatGPT, LiteLLM API или DSLab / Claude API;
- модель из каталога и поддерживаемый reasoning;
- тайм-аут, максимум ответа API, число запросов и токеновый бюджет роли за запуск runtime.

Сначала нажмите **Stop** и дождитесь окончания выполняющихся запросов. Сохранение
во время запроса отклоняется и на сервере, а не только интерфейсом. Новые настройки
подхватываются при следующем запросе; перезапуск для смены модели не нужен.
Кнопка загрузки возвращает сохранённые значения. Таймер не перезаписывает поля,
в которых вы ещё редактируете настройки.
Сохранение API-провайдера проверяет наличие ключа и корректность адреса без сетевого
запроса. Уже сохранённый неполный профиль показывает предупреждение с именем
отсутствующей переменной; ключи и ответы провайдера в него не попадают.

По умолчанию обе роли используют прежний Codex из `CORE_LLM_MODEL_NAME` и
`CODEX_REASONING_EFFORT`. Платный API автоматически не включается. Чтобы снизить
стоимость разговоров, явно выберите для PersonaAgent подходящую более дешёвую модель.
Разделение само по себе не гарантирует экономию: количество запросов зависит
от маршрутизации, а предварительная и итоговая реакции иногда требуют разных вызовов.

Каталог перенесён из `Codex-Development-Lab/common/provider_settings.py` и
`common/codex_settings.py`, снимок от 24.10.2026. Это не запрос к провайдерам и не
гарантия доступа аккаунта. LiteLLM-модели используют только reasoning «default».
В DSLab для Claude Sonnet 5.5 default соответствует high, для Opus 5.5 — medium,
согласно существующему контракту Lab. Несовместимая модель/параметр приводит
к явной ошибке, а не к незаметной смене провайдера.

## Ключи и провайдеры

Ключи задаются **только** в локальном `.env.saruman`:

```dotenv
LITELLM_BASE_URL=https://your-server.example/v1
LITELLM_API_KEY=...
DSLAB_BASE_URL=https://api.dslab.tech
DSLAB_API_KEY=...
```

После изменения ключей или URL нужен полный перезапуск runtime для загрузки
окружения. HTTPS предпочтителен; HTTP передаёт ключ без шифрования. Поддержан также
полный путь `/v1/chat/completions` в LiteLLM URL. Codex использует прежний отдельный
`CODEX_HOME` агента и вход ChatGPT. В браузер и базу настроек ключи не передаются.

В отличие от контейнерной схемы Lab, персонаж работает локальным доверенным Python
runtime: API-ключи доступны этому процессу. Отдельный контейнер provider-gateway
с временными разрешениями не создавался. Модели ключей не получают.

Codex использует существующий app-server и структурированный JSON, при этом его
собственные предложения внешних действий по-прежнему запрещены. LiteLLM использует
OpenAI-compatible `/v1/chat/completions`, DSLab — нативный `/v1/messages`. Для обоих
API результат возвращается одним протокольным вызовом `submit_role_result`; это
описание данных, а не доступ к инструментам игры. Требуется поддержка tool calling.
Ответы буферизуются до валидации. Потоковая озвучка незаконченных ответов не включена.

## Ошибки, лимиты и восстановление

Ошибка провайдера не вызывает автоматический платный повтор или fallback.
Роль блокируется для новых запросов до явного Stop → Start либо смены её профиля;
просьбу после ошибки при необходимости нужно повторить. Другая роль и моды
не обязаны останавливаться. Ошибка показана в UI без тела исключения с секретами.

Перед запросом резервируются токены с консервативной оценкой по UTF-8 размеру входа
и лимиту ответа. При отсутствии полного usage резерв остаётся занятым. Это ограничитель
новых запросов, не гарантированный денежный лимит провайдера. Поле максимума ответа
отправляется API; существующий Codex app-server не предоставляет здесь отдельный
параметр max_output_tokens, поэтому для Codex это резерв бюджета, не жёсткий предел
генерации. Подписка учитывается своими лимитами. Stop → Start не обнуляет бюджет
текущего процесса; новый процесс создаёт новую сессию бюджета.

История по ролям сохраняется в `data/role-models.sqlite` (путь можно заменить
`SARUMAN_ROLE_DB`). Видны провайдер, модель, состояние, вход/выход/кэш/всего и
известная суммарная часть токенов. Неизвестные значения — `?`, не ноль.
Сброс игровой памяти удаляет из этой БД только `intents`; профили моделей,
история запросов и токенов сохраняются. [Сброс из консоли и Control](../help/GAME_MEMORY_RESET.md).
Стоимость API не вычисляется без настроенных тарифов. Codex-лимиты остаются
в существующей отдельной панели. Открытие настроек, сохранение и обновление
статистики не обращаются к моделям.

Исходные просьбы и фактические шаги хранятся локально для продолжения. После обрыва
процесса уже выданные цели сопоставляются по request/context ID, а не запускаются
повторно. Неизвестный результат требует наблюдения. После Stop старое поколение
ответов не публикуется и не исполняется. У речи есть срок актуальности и проверка
world session; старый мир или новая фаза цели отменяют прежнюю реплику.

## Применение и проверка

Для первого применения изменений нужен полный перезапуск локального runtime:

```powershell
.\scripts\start-saruman.ps1
```

Docker пересобирать не требуется. Перед остановкой нажмите Stop в Gradio.
Установка новых зависимостей не нужна: httpx уже был в lock-файле, теперь также
объявлен прямой зависимостью; `uv lock --check --offline` проверяет согласованность.

Проверки выполняются с поддельными ответами провайдеров, тестовыми SQLite и реальными
Gradio callbacks. Они покрывают независимость потоков, исходные ограничения просьбы,
запрет команд у PersonaAgent, устаревшие ответы, модовые цели, профили и бюджеты.
Реальных платных запросов и игровых действий при реализации не выполнялось.
Доступность конкретной модели/ключа и качество её поведения требуют отдельного
пробного обращения пользователя; интерфейс не выполняет его незаметно.
