# Саруман: первый запуск Minecraft runtime

Это игровой runtime **Сарумана**. Сохранены
LangChain, инструменты, PostgreSQL, Redis, TTS/STT, HUD, OBS и VTube Studio.
Игровые события и команды идут через штатный Py4J-мост UnionClef.
Модельный провайдер `codex/...` добавлен отдельно; старые LiteLLM-провайдеры остаются.

## Что реализовано

- `resources/Characters/Saruman/`: личность из нашего PERSONA.md, идеи, отношения,
  псевдонимы и голосовой манифест. Все режимы личности сохраняют Сарумана.
- `src/saruman/`: запуск, проверка окружения, конфигурируемый шлюз и LangChain/Codex-адаптер.
- Модель предлагает JSON tool calls; адаптер валидирует имя и аргументы, а **Saruman**
  выполняет действие. Codex shell/desktop tools и approvals отключены.
- Ответы tool, история и изображения передаются обратно в модель. Usage возвращается
  как наблюдаемая метрика LangChain; если usage нет, точные числа не выдумываются.
- `compose.saruman.yml`: отдельные сервисы с loopback-портами и постоянным томом PostgreSQL.
- `scripts/start-saruman.ps1`: native Windows launcher; по умолчанию модельный цикл
  на паузе, Twitch/DonationAlerts не включаются без явной настройки.

Это ещё **не контейнер отдельного агента**. На первом этапе игровой агент,
Minecraft, аудиоустройства, OBS и VTube работают на Windows-хосте; контейнеры
обслуживают БД, фильтр и голосовые модели. Разделение агентного слоя и host bridge —
следующий этап после проверки реального игрового/голосового контура.
Telegram, видеопроизводство, публикация YouTube и единая лаборатория не добавлялись.

## 1. Подготовить Windows

Клонируй основной репозиторий `https://github.com/Tehnorobot/ai-saruman.git`.
Работай в его папке **`integrations/saruman`**, например
`C:\Repos\ai-saruman\integrations\saruman`, а не в корне лаборатории.
Оба Python-проекта содержат пакет `saruman`; не устанавливай их в одну .venv.
Saruman теперь входит в основной репозиторий обычными файлами: отдельный clone,
fork или `git submodule update` для него не требуется.
Разработка в Ubuntu возможна, но Windows имеет своё окружение и свои секреты.

1. Установи uv, Git, FFmpeg и Docker Desktop. Python-приложение запускай нативно,
   из PowerShell, не из WSL. Внутренний Linux/WSL2 backend Docker Desktop — отдельная вещь.
2. По инструкции курса установи Minecraft **Java 1.21.11 + Fabric**, Java 21,
   подходящий UnionClef и модпак, включая Simple Voice Chat. `@help` проверяет наличие мода.
3. В лаунчере выбери ник `saruman_mag`. Если нужен другой свободный ник, поменяй
   `Names.Minecraft` и `Names.Aliases` в `char_config.yml` согласованно.
4. Установи виртуальный аудиокабель и перезагрузи Windows.
5. Установи OBS; включи WebSocket, пароль и игровую сцену. Порт примера — 4455.
6. Для аватара установи VTube Studio и Live2D-модель; включи API и согласуй порт
   с `VTUBE_WEBSOCKET_URL`. При первом запросе подтверди плагин в VTube Studio.
7. Установи Codex CLI **в Windows**, выполни `codex login` через ChatGPT.
   Вход из Ubuntu автоматически в Windows не переносится. Учётные файлы не копируй в Git.

Ссылки курса: https://course.personalabs.ru/intensive и
https://course.personalabs.ru/instructions/minecraft . Проверяй совместимость
конкретного JAR: профиль не добавляет игровых заклинаний, маунтов, скин или новый тип NPC.
Персонаж входит на сервер как отдельный игрок. Первые действия проверяй в своём тестовом мире.

## 2. Конфигурация

```powershell
cd C:\Repos\ai-saruman\integrations\saruman
Copy-Item .env.saruman.example .env.saruman
```

Если `.env.saruman` уже существует, не перезаписывай его: отредактируй нужные поля.
Впиши уникальный `POSTGRES_PASSWORD`, пароль OBS и реальные имена звуковых устройств.
Не используй чужие `GodUsers`: по умолчанию список доверенных операторов пуст.

Внешние переменные окружения имеют приоритет над файлом. Старые `.env`/`.env.postgres`
не должны подменять явно заданные значения; launcher загружает `.env.saruman` первым.
Проверь старые экспортированные переменные, если выбран не тот профиль или сервер БД.

Для `gpt-6-sol` с рассуждением `low` (так называемый `gpt-6-sol-low`) заданы:

```dotenv
CORE_LLM_MODEL_NAME=codex/gpt-6-sol
CODEX_REASONING_EFFORT=low
```

Модель и reasoning effort передаются Codex отдельно; суффикс `-low` в ID не добавляй.
Пустой `CODEX_REASONING_EFFORT` оставляет настройку Codex по умолчанию.
`CORE_LLM_MODEL_NAME=codex/auto` выбирает default из каталога Codex. Можно закрепить
`codex/<id-доступной-модели>`. Каталог не гарантирует доступ: это подтверждается
успешным ответом. Никакого fallback на платный API-ключ нет. Лимиты подписки остаются.

Адаптер возвращает **буферизованный** ответ после валидации JSON, не live-токены.
У каждого вызова новый процесс/thread; прерывание текущей генерации кнопкой Stop
пока не реализовано. Таймаут ограничен `CODEX_TURN_TIMEOUT`. Не включай 24/7
автономный цикл до проверки частоты вызовов. Включённый Start может расходовать подписку.
Vision можно включить отдельно, указав совместимую модель в `VISION_LLM_MODEL_NAME`.
Embeddings/RAG для первого запуска выключены (`EMBEDDINGS_MODEL=NONE`), код сохранён;
для RAG нужен отдельно настроенный embedding provider — подписочный вход не заменяет его.

В Gradio открой **Control → Использование модели и лимиты ChatGPT**. Панель показывает
выбранную и фактически использованную модель, reasoning, активные запросы, ошибки,
токены и длительность последних 20 запросов. Общие счётчики учитывают все вызовы
адаптера Codex за текущий запуск Python, включая раунды инструментов и другие агенты
в этом процессе. При перезапуске эти счётчики обнуляются; это не долговременный биллинг.
Кэш — часть входных токенов, рассуждения — часть выходных. Отсутствующие данные
помечены явно; неудачный запрос тоже мог расходовать токены.

UI обновляется раз в секунду без модельных вызовов. Токены поступают по уведомлениям
Codex и могут появиться только к концу ответа. Проценты использованного лимита аккаунта,
оставшийся процент и даты сброса берутся из `account/rateLimits/read` при каждом вызове
и из уведомлений `account/rateLimits/updated` во время ответа. Панель показывает время
последнего обновления: в простое лимиты не опрашиваются. Они общие для аккаунта,
включая его другие сессии; токены агента нельзя напрямую перевести в процент лимита.
Точная цена запроса в рублях/долларах при таком подписочном входе недоступна.
Протокол: [официальная документация OpenAI](https://learn.chatgpt.com/docs/app-server).

### Отдельный аккаунт ChatGPT для Сарумана

Для отдельной авторизации задай в локальном `.env.saruman` абсолютный путь:

```dotenv
CODEX_HOME=C:/path/to/ai-saruman/integrations/saruman/data/codex-home
```

Создай в этом каталоге `config.toml`:

```toml
cli_auth_credentials_store = "file"
forced_login_method = "chatgpt"
```

В отдельном PowerShell из `integrations/saruman` выполни:

```powershell
.\scripts\use-codex.ps1
$env:CODEX_HOME = Join-Path (Get-Location).Path 'data\codex-home'
codex login
codex login status
.\scripts\start-saruman.ps1 -Doctor
```

В браузере выбери аккаунт, выделенный агенту. `CODEX_HOME` в этих командах действует
только в текущем терминале и его дочерних процессах; не задавай его глобально для Windows.
При последующих запусках launcher прочитает путь из `.env.saruman`.
`use-codex.ps1` находит CLI в PATH или в установленном расширении Codex для VS Code;
`start-saruman.ps1` вызывает его автоматически. Версия каталога расширения не закреплена.
Файл авторизации хранится в игнорируемом `data/codex-home/auth.json`.
Обычный каталог Codex и вход расширения VS Code сохраняются отдельно.
Лимиты расходуются у выбранного аккаунта; отдельный каталог не меняет размер лимита.
Источник: [официальная документация OpenAI — Credential storage](https://learn.chatgpt.com/docs/auth#credential-storage).

### Ошибка Codex RPC: account/read

Это сбой чтения аккаунта до thread/start и запроса модели, а не результат игрового
действия. Адаптер показывает код и исходное сообщение RPC, скрывая типичные токены,
адреса email, URL и произвольное error.data. Doctor сохраняет эту диагностику.

`workspace routing discovery failed` (код -32603) означает, что Codex не определил
маршрут к рабочему пространству ChatGPT. Само сообщение не доказывает исчерпание
подписки или истечение входа. Сначала проверь доступность ChatGPT, VPN/прокси и
`codex login status` в профиле агента. Если сеть доступна, повтори `codex login`
в том же CODEX_HOME по командам выше, затем запусти Doctor и Python-runtime заново.
Выбери аккаунт агента в браузере; удалять auth.json или выходить из профиля IDE не нужно.
Если ошибка остаётся, сохрани её код/сообщение и версию `codex --version` для диагностики.

Уже заданный в PowerShell CODEX_HOME имеет приоритет над .env.saruman: launcher
не перезаписывает переменные окружения. Поэтому проверку входа и запуск выполняй
из одного терминала с нужным путём. Не заменяй вход агента на API key и не переключай
его на аккаунт IDE. Автоматический повтор модельного хода при ошибке не выполняется.
`refreshToken=false` не отключает штатное автоматическое обновление ChatGPT-входа;
`true` принудительно обновляет токен, а не исправляет сеть или маршрутизацию.
Описание: [OpenAI Docs — Authentication](https://learn.chatgpt.com/docs/app-server#authentication).

## 3. Поднять сервисы

Для выбранного трека Rich используй Fish Speech 1.5.1 на GPU и Parakeet на CPU.
Подготовь checkpoints Fish до запуска. При 8 GB VRAM проверяй запас памяти вместе с игрой и аватаром.

```powershell
docker compose --env-file .env.saruman -f compose.saruman.yml --profile rich --profile voice up -d --build
docker compose --env-file .env.saruman -f compose.saruman.yml --profile rich --profile voice ps
uv sync --locked --python 3.10 --no-default-groups --group collectors
```

Группа collectors пока нужна даже при выключенном Twitch: upstream импортирует
её модули из main.py. STT в этом запуске — штатный streaming Parakeet-контейнер;
настройка STT_BACKEND не переключает активный run_voice_processor на faster-whisper.
Для первого запуска предусмотрен именно Parakeet. Локальный STT-код не удалён.

Профили `simple` и `rich` **взаимоисключающие**: оба используют 22231.
Rich — исходный Fish образ курса; требует поддерживаемой NVIDIA/CUDA, GPU-доступа
Docker и подготовленных checkpoints в `data/fish-tts/checkpoints` по инструкции Fish.
Если ранее включал запасной CPU TTS, сначала останови `tts-simple`, затем включай `rich`.
Реальный GPU-запуск, загрузка весов и задержка голоса требуют проверки на твоём компьютере.

Compose-проект `saruman` использует том `saruman_saruman_db` для памяти/отношений. `docker compose down` его сохраняет;
**не используй `down -v`, если нужно сохранить данные**. Перезапуск Saruman очищает
оперативный контекст Redis штатным `flush_on_start`, но не PostgreSQL.
Память из `agent-workplace/` в корне ai-saruman в эту БД автоматически не импортируется.

## 4. Проверка и запуск

Открой Minecraft, войди в тестовый мир/сервер. Затем:

```powershell
.\scripts\start-saruman.ps1 -Doctor
.\scripts\start-saruman.ps1
```

Doctor проверяет версию Python, импорты, профиль, голосовые файлы и настройки.
Live-проверка дополнительно читает account/read Codex, доступность TCP-сервисов,
`GET /health` фильтра с готовностью его моделей, `inGame()` мода и `SELECT 1` PostgreSQL.
**Не генерирует ответ, не запускает миграции
и не отдаёт игровые команды.** Открытый TCP TTS/STT не доказывает исправность модели.

Первый запуск остановится при провале обязательных preflight-проверок. Gradio —
`http://127.0.0.1:22228`. Нажми штатный **Start**, когда готов расходовать лимит модели.
Для явного автостарта: `start-saruman.ps1 -AutoStart`.

Для ручного задания от оператора открой **Control → Задание Саруману**, введи текст
и нажми Enter или кнопку отправки. Под полем виден статус принятия задания.
Обычный текст, введённый в консоль инструментов, тоже передаётся как задание.
Задания, введённые до Start, обрабатываются после запуска; повторно отправлять их не нужно.
Сообщения в Minecraft от собственного ника персонажа считаются своими:
для разговора с другим игроком нужен другой клиент/аккаунт. Саруман управляет уже открытым
клиентом Minecraft, отдельный NPC от запуска Python не появляется.

В одиночном мире отключи паузу при потере фокуса сочетанием **F3+P** в окне Minecraft
(на ноутбуке может понадобиться Fn). Игра должна сообщить, что pause on lost focus отключена.
Меню Escape всё равно ставит одиночный мир на паузу: закрой его перед проверкой движения.
При необходимости направление задаётся словами через «Сообщение или просьба Саруману»; модель сама выбирает
конкретную команду `agent_action`, например `@goto 10 64 20`. Сам инструмент принимает
только одну команду UnionClef. Осмотр блоков выполняется через `get_nearby_blocks`,
проверка выполнения — через `get_game_status` (`task_chain`, `hasActiveTask`).

### Самостоятельная жизнь, вероятности занятий, урожай и охота

После смерти запущенный персонаж автоматически запрашивает возрождение через
`respawnPlayer` установленного UnionClef. Первая попытка — примерно через две
секунды после наблюдения нулевого здоровья; всего до трёх попыток с интервалом
пять секунд в серии. Если живой игрок не появился, через 60 секунд начинается новая
серия, пока агент включён. Это выполняет bridge, без ожидания ответа модели. Факт отправки
не считается успехом: требуется свежее положительное здоровье игрока.

Start разрешает автоматическое возрождение, Stop его приостанавливает. По умолчанию
`SARUMAN_AUTO_RESPAWN=true`; можно выключить в `.env.saruman`. Пока персонаж мёртв
или его состояние недоступно, модельные игровые действия и новые фоновые дела
не запускаются. Старый маршрут/сбор отменяются; координаты и подтверждённый счёт
деревьев сохраняются в приостановленной задаче. Для её продолжения после смерти
нужно проверить новый инвентарь/положение и передать «продолжи».

Gradio в панели самостоятельных занятий и `get_game_status().respawn` показывают
состояние возрождения и число попыток, журнал — строки `[RESPAWN]`. В hardcore
обычное возрождение не запрашивается. Зависшая отмена прежней задачи не блокирует
запрос возрождения; после появления живого игрока обычные действия всё ещё ждут idle.
При отказе/отсутствии подтверждения система показывает ожидание повторной серии.
Перезапуск Python применяет
изменение; пересборка Docker и изменение игровых правил не нужны.

Защита от воды выполняется bridge примерно каждые 0,2 секунды, до обработки
обычных очередей и независимо от модели. Поверхностное плавание сохраняет задачу:
bridge отпускает приседание и поддерживает всплытие. Отсутствие native-задачи,
четыре секунды без горизонтального продвижения, погружение дольше двух секунд
или воздух не выше половины запускают спасение: однократная остановка и плавание
по наблюдаемому коридору к берегу, включая выход на грядки и полуплиты.
Плавательный поиск не требует стоять на дне;
если берега ещё не видно, выбирается следующий наблюдаемый водный участок.
Шаг проверяется по положению; застрявшие выходы не повторяются. Воздух над водой
во время прыжка не считается берегом: нужна опора. После выхода и idle сохранённые
цели продолжаются с прежними координатами/счётом/ресурсным лимитом. Обычная native
задача возобновляется только в том же мире; после двух повторных спасений один
и тот же native goal больше автоматически не запускается. Stop/смерть снимают
удерживаемые клавиши и отменяют native-возобновление.

Gradio показывает **Версия моста: water-safety-v2**, состояние самосохранения и воздух;
те же данные доступны в `get_game_status().survival`. Если версии/respawn нет,
старый процесс не загрузил изменения: завершить Python полностью (Ctrl+C), заново
запустить `scripts/start-saruman.ps1` и нажать Start. Кнопки Stop/Start не перечитывают
Python-модули. Redis defaults теперь содержат agent_enabled=false, alive и respawn.

Вызов мода использует штатный
[ClientPlayerEntity.requestRespawn](https://maven.fabricmc.net/docs/yarn-1.21.11%2Bbuild.1/net/minecraft/client/network/ClientPlayerEntity.html#requestRespawn()).

Обычный режим — самостоятельный: после **Start** задания вводить не требуется.
В Gradio, **Control → Самостоятельная жизнь Сарумана**, видны текущее занятие,
состояние игры, последний случайный выбор и история последних 20 выборов.
Даже если подходящей работы не нашлось и попытка уже закончилась, её результат
остаётся виден. Подробности включают ответ инструмента и текущую навигацию.

Там же меняются веса занятий: введи числа и нажми **Сохранить вероятности**.
Например, 40/20/20/20 задают исходные шансы четырёх занятий при формировании очереди.
Нулевой вес исключает занятие; все нули приостанавливают случайный выбор,
но не питание и не уже начатую игровую задачу. Таблица показывает базовый шанс
и шанс при новом розыгрыше с учётом временных пауз. Уже сформированный порядок
показан отдельно в очереди. Веса не гарантируют
частоту в короткой серии: веса определяют случайный порядок доступных дел без повторов
в одной очереди. Наличие ресурсов и целей проверяется после выбора.

Планировщик также учитывает **Tool Controls**. Если нужный инструмент выключен или
не зарегистрирован, занятие получает нулевой шанс следующего выбора; колонка
«Доступность инструментов» показывает причину. Охоте нужны `hunt_hostiles` и
`attack_hostile`, всем занятиям — `get_inventory`, разведке — `agent_action`.
Посадке деревьев нужны `tend_trees`, `agent_action` и `obtain_item`; расширению поиска —
`explore_nearby` и `agent_action`. Отключённые инструменты не обходятся очередью.
Отключение инструмента не считается неподтверждённым игровым действием и не
останавливает остальные занятия. Если недоступно всё, агент ждёт включения инструментов.
Уже начатая игровая задача при переключении не обрывается; новые шаги отключённого
занятия не запускаются. Нужные инструменты включаются по отдельности через Toggle ON/OFF.

Изменения сохраняются в `data/autonomy-settings.json` и применяются работающим
планировщиком без перезапуска. Текущее занятие не прерывается. Обновление панели
раз в секунду не перезаписывает введённые, но ещё не сохранённые значения.
Настройки переживают перезапуск Python; история выборов относится к текущему запуску.
Если планировщик ещё не подтвердил новые веса или давно не обновлял состояние,
панель явно сообщает об этом. **Stop** останавливает агента и игровую задачу;
**Start** возобновляет самостоятельные занятия. Поле общения необязательно.

После Start, когда нет выполняемой игровой задачи или текущая цель заблокирована,
runtime выбирает случайное занятие из
[autonomous_activities.json](../resources/Minecraft/autonomous_activities.json):
farm — урожай (вес 3), hunt — враждебные мобы (2), explore — короткая разведка (2),
trees — посадка дуба/берёзы с естественным ростом (2). При чтении прежних трёх весов
добавляется trees=2; если все прежние веса нулевые, trees тоже получает 0.
Вес меняет вероятность выбора. Следующий фоновый шаг проверяется примерно через
8 секунд, продолжение выбранного занятия — через 1,5 секунды; внешний чат и
150-секундный idle-таймер для этого не нужны. При включённой автономности старый
таймер скуки не запускает параллельные занятия через модель. Длинный ответ модели и выполняемая
native-задача всё ещё задерживают шаг. Дополнительного запроса LLM на него нет.

Цикл не заканчивается после одного занятия: выполнение или обычная неудача →
следующее готовое дело из очереди. После локального no_work/no_target/waiting_for_growth
добавляется направленная разведка. Нативный снимок ограничен радиусом 5 блоков;
охват расширяется реальными переходами с бюджетами 4 → 8 → 16 → 32 → 64, а не увеличением
фиктивного радиуса. После подтверждённого перемещения сначала проверяется работа
на новом участке. Максимум фонового поиска задаёт `SARUMAN_SEARCH_MAX_MOVES=64`
в `.env.saruman`, допустимо 4..256, применяется после перезапуска Python. Это
суммарные предложенные переходы в текущем проходе поиска, а не блоки/токены. После
полного прохода с максимальным бюджетом следующий вызов начинает новый проход,
сохраняя посещённые места и последние реальные позиции для защиты от циклов. Лимит
одного локального пути — 8 соседних шагов, новая точка разведки — в 1..4,5 блока;
общий охват последовательно увеличивается. Отдельные counted-tree процедуры
сохраняют свой явный search_steps 0..8 и ресурсные ограничения. Обычные поиски идут
к сухим точкам; фактическая native-навигация может пересечь воду по поверхности
с контролем дыхания bridge. Спасение управляет плаванием отдельно от pathfinder.
Посещённые места общие для фоновых поисков; повторные неподтверждённые
маршруты не отправляются. Если новый участок не виден, допускается короткий
сухой переход через знакомую землю (`route_kind=connector`), с исключением недавних
возвратов и проваленных целей. Если единственный выход из тупика уже посещён,
разрешается целевой возврат (`route_kind=backtrack`) по наблюдаемому проходу.
Исчерпанная ветка помечается на 60 секунд; другая поисковая задача не отправит
туда сразу обратно. Возврат расходует тот же бюджет перемещений, не обходит
запреты движения, воду или временно проваленные маршруты. После большого переноса
персонажа (>16 блоков между сканами данного занятия) начинается новый локальный
проход поиска; координаты посаженного и лимиты counted-tree задачи сохраняются.
Из реально занятой грядки/плиты можно выйти на
полный сухой блок: проверяются native-коллизия, высота ног и onGround; сами частичные
блоки не становятся целями обычного поиска. Вода, неподтверждённая опора и пропасти
не считаются проходом. Если все занятия отдыхают и доступных маршрутов нет,
runtime автоматически дождётся ближайшего окончания паузы и продолжит без сообщения
в чат. `No tasks` относится к текущей игровой цепочке, а не к завершению автономной жизни.

`@stop`, вызванный для прервавшегося маршрута, завершает текущее занятие. Bridge
ждёт свежего наблюдения `hasActiveTask=false`, переводит `stop_requested`/поздний
`stop_failed` в `stopped`, затем разрешает следующий выбор. Повторных stop-команд
для этого не требуется; неудачные координаты остаются в списке временных запретов.
Кнопка **Stop** и явная просьба оператора стоять/ждать сохраняют паузу автономности
до **Start** или новой директивы. Ошибка с неподтверждённым игровым взаимодействием
завершает только это занятие: после окна 2,5 с для обновления bridge выбирается
следующее дело. Ошибочное занятие получает паузу 60 с; его следующий запуск заново
читает мир, инвентарь и доступность цели. Неподтверждённый клик или приложенное к нему
next_action автоматически не повторяются. Ошибка продолжения сохранённой задачи
переводит именно эту цель в blocked, сохраняя координаты, счёт и расход ресурсов;
остальные занятия продолжаются. В Gradio видна последняя проблема занятия, а в
JSON `autonomy.recent_issues` — до 20 записей с исходными результатами. Смерть и
последующие успешные действия не стирают эту диагностику в текущем процессе.
После полного перезапуска Python версия планировщика в Gradio должна быть
`command-equipment-preflight-v1`. Кнопки Stop/Start не перечитывают исправленные модули.

Перед обычными делами `ensure_scepter` проверяет доступные команды в дереве,
присланном сервером. При наличии `/give` и `/experience` заранее запрашивает
недостающие меч, щит, рабочий посох и запас опыта. Посох и опыт нужны только
при подтверждённой поддержке мода сервером. Спасение и срочная защита приоритетнее.
Выдача проверяется по реальному инвентарю и опыту до четырёх секунд. Если результат
не подтверждён, обычные дела продолжаются; повтор выдачи — не раньше 60 секунд.
Без команд достаточно меча; при наличии только `/give` выдаётся только меч.
Автоматического крафта посоха и добычи его материалов больше нет.
Обычная добыча меча — отдельная попытка максимум 20 секунд на подтверждённую
нативную задачу, затем однократная отмена, ожидание native idle и другие дела.
Следующая попытка — не раньше 120 секунд. Если выключен `agent_action`, такие
фоновые задачи не запускаются, поскольку отменить их было бы нельзя.
Замена нативной задачи другим контроллером отменяет владение подготовкой;
устаревшая/неподтверждённая наблюдением задача принудительно не останавливается.
Состояние и причина видны в Gradio: `autonomy.equipment_job/equipment_result`.

Реплики фоновых действий загружаются из PostgreSQL `action_voice_lines` при запуске:
54 варианта комментариев и 32 оригинальных художественных воспоминания образа.
Миграция добавляет их однократно; изменения `text`/`enabled` в БД сохраняются.
После редактирования каталога перезапусти Python. Исходный каталог —
`resources/Characters/Saruman/action_speech.json`; при недоступной таблице работает
локальный резерв. Пустой или полностью отключённый каталог БД означает тишину.
Воспоминания имеют `kind=authored_backstory`: это авторская предыстория, не канон
книг и не игровые достижения. Иногда они добавляются к мирным комментариям;
во время боя воспоминания не подмешиваются. Повтор недавней реплики избегается,
обычные комментарии звучат не чаще раза в 12 секунд (первый боевой комментарий
может прервать мирную речь). Дополнительных LLM-запросов
для комментариев нет. Источник каталога и последние записи видны в Gradio JSON
`autonomy.commentary`, недавние реплики также передаются в контекст модели.

Сообщения игроков Minecraft обрабатываются по очереди раньше фоновых дел, даже без
упоминания ника. Текущий фон уступает место общению и принятым заданиям игроков:
его намерение сохраняется, native-действие останавливается, новое игровое действие
ждёт подтверждённого idle. Активная задача с деревьями откладывается с прежними
координатами, счётом и бюджетом. После разговора остаётся окно 8 секунд; выполняемые
игровые задания и продолжения блокируют фон до окончания. Отложенные цели игроков
возобновляются раньше фоновых. Очереди сообщений, дел и отложенные цели видны в Gradio.
После перезапуска сохранённые цели остаются paused до явного продолжения и проверки мира.

Когда общения нет, активная сохранённая задача деревьев имеет приоритет: runtime
продолжает её с прежним config и счётом, включая отправку next_action. Заблокированная задача
остаётся в памяти. Неудачное фоновое занятие исключается на 60 секунд; максимум
8 шагов/45 секунд. При превышении 45 секунд собственная native-задача фона получает
один `@stop`; следующая работа ждёт подтверждения остановки. Чужую активную задачу
этот таймер не обрывает. Разведка
помнит посещённые области и неудачные маршруты. Неопределённый клик не останавливает
всю автономность; неподтверждённая отмена native-задачи по-прежнему блокирует её замену
до свежего idle. Stop и просьба стоять/ждать
приостанавливают фон; новое задание или Start возобновляет его. Чтобы выключить фон
в конфигурации, добавь `SARUMAN_AUTONOMY_ENABLED=false` в .env.saruman и перезапусти Python.

`farm_crops(mode="auto"/"plant"/"harvest")` выполняет один шаг: посев пшеницы,
моркови, картофеля, свёклы либо сбор только зрелого растения. Если нужно, получает
мотыгу и подготавливает свободную землю возле воды; семена получает только зрелым сбором. Уход, полив и мука не
применяются; незрелый урожай остаётся расти. harvested означает убранный блок,
collected — реальные прибавки предметов; к выпавшему урожаю предлагается подход.
При голоде фон использует eat_food, оставляя последнюю морковь/картофель на посев;
из трёх wheat заказывает хлеб. Здоровье восстанавливается по правилам игры.

`hunt_hostiles` сохраняет UUID цели; `attack_hostile` предпочитает посох, а при
невозможности магии предпочитает меч с проверкой sweep либо точный удар топором/киркой. Жители, скот, животные,
торговцы и големы исключены даже при ответной атаке. Игроки и допускаемые нейтральные
монстры требуют свежего подтверждения реального нападения от native damage callback;
слова в чате не подходят. При здоровье <10
или голоде <8 охота прекращается. Нулевое здоровье подтверждает killed; исчезновение
цели не считается победой. Штатная автоатака/forcefield UnionClef исключены из боя,
боевые команды и native-сбор животных материалов блокируются также на входе bridge.

### Основное оружие: Magical Scepter

Мод 1.2.0 для 1.21.11 должен быть установлен на клиенте и сервере. После полного
перезапуска Python фон через `ensure_scepter` заранее проверяет снаряжение.
При доступных командах недостающий посох запрашивается только своему фактическому нику с компонентом
`magicalscepter:scepter_contents="magicalscepter:magical"`. Простая выдача предмета
без компонента не назначает заклинаний. Результат подтверждает инвентарь, не факт команды.

Выдача недостающих предметов не повторяется до проверки/интервала повтора.
Без прав на команды достаточно обычного меча: автоматическая подготовка не ищет
лазурит, грибы и заготовку и не запускает крафт посоха. Доступность команд,
наблюдаемые предметы и состояние каждого запроса видны в `equipment_supply` в Gradio.

`get_scepter_status` показывает варианты **в реальных слотах**, attack/protect,
стоимость опыта, доступность опыта, прочность и native cooldown. `cast_scepter`
выбирает слот и действие attack/protect. По умолчанию выбирает допустимую безопасную
магию; один базовый посох не содержит все 20 заклинаний одновременно. Насыщение
происходит по правилам мода; инструменты распознают получившийся вариант автоматически.

| Вариант | Атака | Второе заклинание |
|---|---|---|
| Magical | Магический луч | Сопротивление |
| Blaze | Три огненных заряда | Огнестойкость |
| Breeze | Ветровой заряд | Прыжок / медленное падение |
| Dragon | Драконий огненный шар | Дыхание дракона |
| Evoker | Линия клыков | Кольца клыков |
| Ghast | Огненный шар | Регенерация |
| Guardian | Луч стража | Спешка / снятие утомления |
| Shulker | Снаряд шалкера | Телепортация |
| Warden | Звуковой удар | Устойчивость |
| Wither | Череп иссушителя | Отражение |

Атака вызывается настоящим `ItemAttackCallback` мода, отправляющим его сетевой пакет;
защитное действие — native interactItem. Обычный удар по существу не заменяет заклинание.
Опыт/прочность расходуются по правилам игры. До обычных дел runtime пополняет
запас опыта, когда осталось меньше 20 очков или стоимости пяти применений.
Целевой запас — минимум 100 очков либо стоимость 20 применений, максимум 10000.
`/experience add <свой ник> <недостающее> points` добавляет очки, не уровни.
Выдача требует доступных серверных команд и подтверждается реальными очками опыта;
непроверенный запрос повторяется не раньше 60 секунд. Внутри атаки выдачи нет.
Состояние `scepter_experience` видно в Gradio. Без мода опыт не выдаётся.
При неподтверждённой выдаче опыта и отсутствии запасного оружия фон запрашивает деревянный меч,
чтобы добывать опыт обычным боем с допустимыми целями. При достаточном опыте посох
снова предпочтительнее. Отключение cast_scepter в Tool Controls блокирует магию в охоте.
Проверяется фактическая перезарядка. `cast_requested` означает запрос, а не попадание;
победа подтверждается только наблюдаемым нулевым здоровьем. Неизвестный результат
не отправляется повторно вслепую.

Для луча проверяется линия с запасом от защищённых существ. Снаряды, клыки, облака
и отражение блокируются, если отслеживается любое постороннее живое существо.
Это ограничивает выбор массовой магии возле поселений. `/spell`, raw combat и клики
по прицелу не используются для обхода проверок. Безопасность будущего движения
посторонних и изменения серверных datapack-эффектов клиент гарантировать не может;
для абсолютного запрета побочного урона на сервере нужен отдельный damage guard.

Срочная защита работает в bridge с интервалом проверки 0,5 с, независимо от ответа
LLM. Враждебный моб в 8 блоках или native-подтверждённый нападающий в 12 блоках
прерывает обычные задачи. Proof игрока действует 20 секунд. После остановки старой
задачи персонаж подходит и атакует; низкие здоровье/еда не отменяют самозащиту.
Обычная необязательная охота сохраняет свои пороги здоровья. Native-отступление
выключено на время работы этой защиты и восстанавливается при Stop/отключении.
Всплытие/возрождение имеют приоритет. Goal checkpoint сохраняется. Отключение
defend_self в Tool Controls выключает bridge-защиту; cast_scepter запрещает магию
также в срочном бою. Жителей, животных и големов по-прежнему нельзя атаковать.

Наличие мода проверяется также у сервера через
[Fabric canSend](https://maven.fabricmc.net/docs/fabric-api-0.141.1%2B1.21.11/net/fabricmc/fabric/api/client/networking/v1/ClientPlayNetworking.html).
Без поддержки сервера выдача и крафт посоха не запускаются. При доступных командах
выдаются ванильные меч и щит; без команд планировщик получает только
ванильный меч через obtain_item, продолжая обычную жизнь. Меч применяется только
при свободной зоне sweep; рядом с мирными существами используется имеющийся
топор/кирка либо удар отклоняется. Если оружие ещё не получено, срочная защита может
использовать пустой слот, проверенный по инвентарю. Заклинания в этом режиме недоступны.
Gradio показывает снабжение посохом и последнюю магию в деталях самостоятельной жизни.
Маркер загруженного моста — **Магия: reflex-v2**. Для появления новых инструментов
нужен полный перезапуск Python, обычное Stop/Start код не перечитывает.

Обновлённый бой отмечается в Gradio как **Преследование: ranged-defense-v2**.
Решения боя по-прежнему выполняются bridge, без запросов к LLM. Сближение идёт
по одному соседнему сухому блоку из наблюдаемого связного маршрута. Непроверенный
участок, вода, недавний проваленный маршрут или повтор шага не считаются подходом.
Проверка точки выполняется ещё раз при отправке команды; нативный pathfinder всё
ещё может ошибиться или персонажа может столкнуть противник, поэтому контакт с
водой во время боя немедленно включает всплытие и выход. Боевой маршрут после
спасения не восстанавливается.

Новая враждебная цель выбирается до 16 блоков; подтверждённый нападающий-моб —
до 24, игрок — до 12 и только с доказательством реального нападения.
Базовый magical_attack действует до восьми блоков: дальность обнаружения не
увеличивает дальность заклинания. При входе в дальность имеющегося посоха
сближение останавливается для выстрела, без ожидания контакта мечом. На расстоянии
первым действием не расходуется общая перезарядка на защитное заклинание.
Перед пакетом атаки мода выбранный слот явно синхронизируется с сервером;
native selectHotbar сам меняет только локальный слот. Для обычного удара
добавлены поворот к цели и взмах руки.

Водная цель атакуется с берега при допустимых дальности, видимости и безопасности.
Если есть рабочее дальнобойное заклинание, персонаж может приблизиться к ней
по наблюдаемым сухим клеткам берега. За недоступной водной целью он не ныряет.
Погоня прекращается при 24 секундах сближения, 8 секундах без сокращения дистанции
или уходе дальше 12 блоков от начала боя. Это ограничения сближения, а не таймер
завершения боя с доступным противником. Нативная остановка подтверждается перед
освобождением тела для следующей задачи.

Недоступная цель остаётся живой в `combat_watch` на 30 секунд. Другие задачи могут
продолжаться. Новый подтверждённый удар, приближение видимой цели на расстояние
контакта или существенное перемещение сухой цели позволяют проверить её раньше.
Видимую цель в дальности имеющегося посоха можно перепроверять для выстрела
раз в две секунды: запрет повторного маршрута не запрещает дальнюю атаку.
Фоновая охота не создаёт параллельную погоню и не обходит список наблюдения.

В самой игре над хотбаром появляется локальная строка с типом/UUID цели,
расстоянием и состоянием боя. Отправленное заклинание/удар отделены от
подтверждённого уменьшения здоровья. Это локальный HUD, не сообщение игрокам
и не эффект подсветки через стены. Gradio показывает цель и последнюю попытку
магии; JSON и get_game_status содержат scepter_attempt и combat_attack,
включая отказы наведения, нехватку опыта и отсутствие дальности/видимости.

Counted-tree цели и фоновые занятия используют существующие checkpoints. Для
другой прерванной нативной задачи сохраняется настоящий root task в памяти bridge:
возобновление допускается только один раз после сухой земли, native idle и
отсутствия угрозы. Смена мира, Stop, смерть, выключение защиты, новая команда или
новый запрос игрока отменяют старое возобновление. Лимиты исходного маршрута и
добычи, позиции и подтверждённый прогресс не обнуляются; неизвестный результат
команды возобновления не отправляется повторно. Подробности доступны в Gradio JSON
и `get_game_status`: `combat_watch`, `combat_checkpoint`, `self_defense`.

Инструкция: [посох](../resources/Minecraft/procedures/scepter.md).
Правила мода: [Magical Scepter](https://moddedmc.wiki/en/project/magical-scepter/latest/docs/items/magical_scepter),
[заклинания](https://moddedmc.wiki/en/project/magical-scepter/latest/docs/spells/spells).
Автоматическое снабжение едой FoodChain отключено runtime-настройками, чтобы оно
не запускало забой скота; автоупотребление имеющихся припасов остаётся доступно.
JVM-исключения сохраняются при отключении Python до перезапуска клиента Minecraft.

Состояние видно в Gradio, get_game_status().autonomy и журнале `[AUTONOMY]`.
История поясняет локальное «нет работы»: нет семян/спелого урожая, воды, прохода
или подходящей почвы. Земля рядом сама по себе не обеспечивает все условия посадки;
песок не подходит ни дубу/берёзе, ни перечисленным культурам. При смерти или пустых
посадочных запасах поиск не выдаётся за успешный посев.

Если раньше bridge завершался с `IllegalAccessException` / `caller-sensitive method`
при установке боевой защиты, перезапусти Python с обновлённым кодом. Запись runtime-порогов
FoodChain выполняется прямым Java field setter на потоке клиента, без `Field.set`
через `publicLookup`. Пересобирать Docker или менять JVM-флаги не требуется.
Инструкции: [урожай](../resources/Minecraft/procedures/farm_crops.md),
[охота](../resources/Minecraft/procedures/hunt_hostiles.md). Нативные проверки:
[CropBlock.isMature](https://maven.fabricmc.net/docs/yarn-1.21.11%2Bbuild.1/net/minecraft/block/CropBlock.html),
[ClientPlayerInteractionManager](https://maven.fabricmc.net/docs/yarn-1.21.11%2Bbuild.1/net/minecraft/client/network/ClientPlayerInteractionManager.html).

Семена и посадочные морковь/картофель пополняются только сбором зрелого урожая через
`farm_crops`; при нехватке семян режим plant также сначала собирает спелые растения.
`waiting_for_growth` оставляет молодые грядки расти и переключает фоновое занятие;
позже фермерство может быть выбрано снова. Если зрелых растений нет, он не добывает
семена разрушением молодых посадок. Прямые `@get` семян/урожая и `@mineblock` культур
заблокированы также при отправке из очереди в Minecraft.

Для других предметов доступен `obtain_item`, например, `wooden_hoe`. Он запускает
штатную задачу `@get <item> <count>` в UnionClef; принятие задачи ещё не подтверждает
изготовление. Для `bread` требуется уже собранная пшеница в инвентаре: по три единицы
на каждый недостающий хлеб. Проверка повторяется перед отправкой команды в игру,
чтобы изготовление не превращалось в скрытую добычу пшеницы с молодых грядок.
Если до обновления уже запущен старый сбор семян, отмени его через `@stop` в игре
и перезапусти Python: новая проверка не отменяет ранее начатую native-задачу.
`get_inventory` читает реальные предметы, здоровье и сытость по отдельности.
Для еды из имеющегося инвентаря есть `eat_food`: выбирает продукт, использует его,
проверяет уменьшение количества, отпускает кнопку и восстанавливает выбранный слот.
При полной сытости обычная еда не используется. Отдельной команды `@eat` у мода нет.
Автоеда мода также существует, но действует по своим порогам голода.
Для применения костной муки к уже посаженному саженцу есть
`apply_bone_meal(x, y, z)`: координаты относятся к самому растению, не к почве под ним.
`@place bone_meal` не подходит, поскольку костная мука — предмет для использования.
Инструмент проверяет саженец, наличие муки, отсутствие активной игровой задачи и реальное
попадание прицела; выбирает муку из инвентаря, выполняет один клик через штатный
`interactBlock` мода и восстанавливает слоты. При отсутствии видимости/досягаемости
нужно сначала подойти к растению. Повторные клики автоматически не выполняются.
Ответ разделяет `applied`, `consumed`, `tree_grown` и `target_after`: расход дозы
не гарантирует немедленный рост. Не подтверждённую операцию нельзя повторять вслепую.
Состояние мира перечитывается из host bridge между раундами инструментов;
осмотр местности группирует блоки по типу и явно ограничивает список координат.

### Готовые игровые процедуры

Для заданного количества деревьев есть `manage_trees`: например,
`manage_trees(count=2, mode="plant")` или `manage_trees(count=2, mode="grow")`.
Пользователю достаточно написать «Посади два дуба»; инструмент выбирает агент.
Персонаж может поставить себе такую же цель без сообщения оператора.

Задача хранится в Redis в `game.tree_task`: параметры, отдельные позиции,
подтверждённый прогресс, оставшееся количество и бюджет муки. Сбор запрашивает
материалы для всех оставшихся посадок, места выбираются с интервалом минимум 4 блока.
Посадка учитывается после проверки саженца, выращивание — после проверки ствола.
Существующий саженец не считается новой посадкой; для выращивания его использовать можно.
Прогресс 1/2 сохраняется при сборе/подходе к следующей точке, completed достигается
при 2/2. Повтор завершённой задачи не создаёт дополнительных деревьев.

Один вызов выполняет не более одной целевой посадки/выращивания и пяти попыток удобрения.
Следующий шаг запускается через существующее продолжение агента; при сборе/движении
агент ждёт native-задачу. Перед каждым взаимодействием сохраняется точка и стадия:
после потерянного ответа сначала проверяется этот блок, неизвестный клик не повторяется.
Состояние видно через `get_game_status`. Stop сохраняет частичный результат со статусом
cancelled; новое операторское задание заменяет сохранённую цель.

Для grow `max_bone_meal` — общий бюджет на задачу, а не на каждое дерево; по умолчанию
5×count, явный меньший предел сохраняется при продолжении. В plant мука не применяется.
У каждого саженца отдельный сохраняемый счётчик: максимум пять попыток за всю задачу,
включая продолжения, пополнение муки и перезапуск Python. После пятой без роста
саженец остаётся на месте, помечается skipped и задача переходит к следующему.
Если все оставшиеся цели исчерпаны, результат partial: completed содержит только
подтверждённые деревья. Агент сообщает итог и переходит к другому занятию/заданию;
новую задачу для обхода пяти попыток создавать нельзя. Для одного дерева также
предпочтителен manage_trees(count=1, mode="grow"), сохраняющий этот счётчик.
Лимиты: 1..32 дерева, 20 минут, конечное число шагов и заданная глубина поиска.
При blocked агент сообщает выполненную часть и препятствие. new_task=true нужен для
новой самостоятельной цели; он не должен использоваться для обхода лимитов.
При обычном перезапуске Python сохранённая цель и память поиска восстанавливаются
из Redis; старые очереди команд очищаются. Незавершённая активная цель становится
paused, завершённые и отменённые сохраняют статус. Старый blocked из-за тайм-аута
ожидания native work также переводится в paused. Данные исчезнут при удалении Redis.
Старый ownership_lost без диагностических данных тоже допускает восстановление;
подтверждённая замена корневой задачи автоматически не снимается.
Чтобы продолжить в **том же мире Minecraft**, отправь **«Продолжи выращивание деревьев»**
или **«Продолжи посадку деревьев»**. Агент берёт прежние config, координаты и прогресс;
явное продолжение также разрешает возобновить цель после Stop. Лимит шагов и уже
израсходованная мука сохраняются; для paused начинается новое окно 20 минут.
Другие blocked (неопределённый клик, исчерпанный бюджет) автоматически не снимаются.
Новый запрос «Вырастить два дерева» создаёт новую цель, поэтому для оставшегося `1/2`
используй именно продолжение. Возврат к далёкой сохранённой точке идёт короткими
переходами по наблюдаемой связной поверхности. Если проход не подтверждён, задача
проверяет остальные сохранённые цели. Незасаженный план можно заменить найденным
доступным местом; старая позиция остаётся в истории. Уже посаженный саженец так
не заменяется, подтверждённое количество и расход муки сохраняются. Для обхода
к незасаженным местам можно использовать оставшиеся search_steps; после исчерпания
вариантов задача останавливается с причиной. Дальний маршрут не гарантируется.
Опора и свободное пространство для подхода проверяются через коллизии и категории
опасности самого Minecraft, без списка названий блоков. Это не делает опору почвой
для дуба. Обычные подходы планируются по суше с опорой под ногами; водные клетки
не входят в выбор поисковой точки. Native-маршрут может плавать по поверхности;
bridge следит за дыханием и прерывает затяжное погружение. Лава не является путём
поиска или спасения. Частичная высота пола (например, нижняя
плита) пока не поддерживается: короткий путь использует целочисленные высоты ног.
В scan.navigation видны standing_on и reachable_cells для диагностики пути.
Явное «Продолжи» разрешает заново проверить blocked с причиной неподтверждённого
маршрута, сохраняя шаги/дозы/позиции. Неопределённые взаимодействия и исчерпанные
бюджеты по-прежнему не разблокируются.

Задание **«Вырастить дерево»** автоматически добавляет в контекст подходящий локальный
сценарий. Можно также вызвать `get_minecraft_procedure(task)`; без task он показывает каталог.
Это не дополнительный агент и не модельный запрос: загружается соответствующий файл:

| Результат | Процедура | Инструкция |
| --- | --- | --- |
| Вырастить дуб/берёзу | `grow_tree` | [Полный сценарий](../resources/Minecraft/procedures/grow_tree.md) |
| Только посадить саженец | `plant_sapling` | [Посадка](../resources/Minecraft/procedures/plant_sapling.md) |
| Удобрить уже посаженный саженец | `apply_bone_meal` | [Костная мука](../resources/Minecraft/procedures/apply_bone_meal.md) |

Быстрый инструмент `grow_tree(sapling="oak_sapling", max_bone_meal=5)` читает материалы,
делает один локальный обзор, использует существующее подходящее растение либо сажает
один саженец и применяет доступные дозы до подтверждённого ствола или остановки.
Для каждого блока, слота или дозы отдельный вызов LLM не нужен. Инструмент не начинает
новую добычу, не ходит сам и не ломает препятствия: он возвращает недостающий материал,
точки для подхода или конкретную причину остановки. Максимум — 5 попыток за вызов;
для счётчика между вызовами используй manage_trees, включая count=1. Меньший лимит
оператора передаётся явно. Сценарий поддерживает `oak_sapling`/`birch_sapling`;
схемы 2×2 для других пород не реализованы.

`find_tree_planting_spots` сначала проверяет открытые поверхности на всех высотах
наблюдаемой области радиусом до 5 блоков через нативный canPlaceAt саженца. Неподходящая
почва не расходует лимит 128 кандидатов на проверку места для роста; число первичных
проверок видно в native_soil_checked. Доступные места ранжируются первыми.
Вместо фиксированного объёма 3×3×8 вызывается нативная проверка свободного места
TreeFeature.getTopPosition с минимальной высотой обычного дуба/берёзы. Используется
конфигурация ванильного клиента: серверный datapack, случайный более высокий вариант
дерева и рост с одной дозы этим не гарантируются. Проверка не запускает генерацию
дерева, не меняет мир и не расходует случайность. Дополнительно действует политика
установки. Возвращаются до трёх точек, досягаемость и rejected с причинами отсева;
отсутствие результата не доказывает отсутствие места во всей местности. Расчёт не
двигает персонажа. Поле `approaches` отдельно возвращает короткие проходы по
наблюдаемой связной поверхности с перепадами до одного блока: `standing_position` и готовую
`command`. Пустой список означает, что такой подход не подтверждён. Координаты
саженца и позиция для стояния различаются; при полу на Y=62 команда goto должна
указывать ноги на Y=63. Не добавляйте единицу к высоте саженца.
`plant_sapling` выполняет одну установку в выбранной точке и
проверяет появление саженца, не полагаясь на общий зацикливавшийся `@place`.
Описание нативных методов: [BlockState](https://maven.fabricmc.net/docs/yarn-1.21.11%2Bbuild.6/net/minecraft/block/AbstractBlock.AbstractBlockState.html),
[TreeFeature](https://maven.fabricmc.net/docs/yarn-1.21.11%2Bbuild.1/net/minecraft/world/gen/feature/TreeFeature.html).

Если места или подхода нет, `exploration.next_action` предлагает один переход в новый
доступный участок. После прибытия агент повторяет обзор. Память хранит проверенные области
и предложенные цели до нового задания, учитывает проваленные маршруты; повторное чтение
на месте не расходует дополнительный шаг. По умолчанию глубина — 4 перехода,
а ширина — 128 кандидатов за обзор. В обоих инструментах можно задать
`candidate_limit=256, search_steps=8`; больший поиск означает больше ходов модели и времени.
`search_steps=0` отключает разведку, при запрете перемещения команды подхода не выполняются.
Радиус самого `getBlocksAround` ограничен модом пятью блоками: расширение достигается
последовательными обзорами из новых точек, а не передачей неподдерживаемого радиуса.
Источник API: [UnionClef Py4jEntryPoint](https://github.com/3ndetz/unionclef/blob/main/src/main/java/adris/altoclef/Py4jEntryPoint.java).
При завершении поиска результат различает исчерпание бюджета, отключённую разведку и
отсутствие подтверждённого прохода. Это не доказательство отсутствия почвы во всём мире.

Для собственных явных `@goto` bridge проверяет свободные клетки ног/головы и опору
под ногами до отправки. Если 30 секунд нет улучшения горизонтальной дистанции к
цели минимум на 0.75 блока, bridge один раз вызывает native `stopPathing` (оба
навигатора) и ждёт подтверждения остановки; общий предел — 180 секунд. Прыжки и
движение между теми же точками не сбрасывают ожидание. Чужая задача, заменившая goto,
не отменяется. Это защита host-runtime, алгоритм маршрутизации самого мода не меняется.
`get_game_status` показывает позицию и navigation: running/stopping/blocked/stop_failed.
При блокировке агент получает событие с причиной, проверяет материалы и досягаемые
места либо выбирает другой подход; проваленная цель и соседние клетки запрещены
120 секунд. Если остановка не подтверждена, дальнейший маршрут не запускается.
Защита отслеживает новые команды после запуска Python; уже запущенный до перезапуска
маршрут остановите игровым `@stop`, затем отправьте исходное задание заново.

В процедуре сбора одновременно запускается только одна native-задача. После
`obtain_item` или `@get`/`@goto` агент проверяет готовность каждые 0,5 секунды по состоянию
bridge и продолжает исходное задание после завершения, без ожидания 150-секундного idle.
Начальная пауза после принятия native-команды остаётся 2 секунды, чтобы не спутать
задержку запуска с завершением. Локальный шаг in_progress готов к продолжению сразу.
Следующий выбор инструментов всё ещё требует ответа модели: её задержка к этому
ожиданию добавляется; в присланном логе TTFT был около 10 секунд.
Новый явно отправленный `@get item count` отслеживается отдельно: пока есть новые
участки пути, добыча или прирост инвентаря, сбор может длиться до 15 минут. Возвраты
в те же двухблочные клетки сами по себе не продлевают ожидание. Без прогресса 120 секунд
bridge один раз вызывает stopPathing и до 5 секунд проверяет остановку. Неизвестный
результат остановки не повторяется. Состояние видно в `get_game_status().collection`;
если bridge перестал обновлять статус, ожидание прекращается с сообщением о потере
наблюдения, без неподтверждённой отмены. Старый тайм-аут 180 секунд остаётся для
неотслеживаемой работы; явный goto имеет отдельную защиту маршрута выше.
В поддерживаемом UnionClef проверяется идентификатор корневой пользовательской
задачи, а не только выбранная сейчас цепочка планировщика. Еда/защита могут временно
перехватить управление: `collection.status=suspended` сохраняет ожидание и цель.
При неподтверждённом снимке статус `observing` допускается до 30 секунд; затем
`ownership_unconfirmed` останавливает продолжение без отмены неизвестной работы.
Изменение уже подтверждённого идентификатора даёт `ownership_lost`. Диагностика
сохраняет исходную цепочку, корневую задачу и причину; неизвестное не считается заменой.
При временном приостановлении остаётся общий предел 15 минут, чужая цепочка не отменяется.
Максимум четыре продолжения восстановления; у counted-задачи и разведки собственные
лимиты. Stop сбрасывает продолжение; новое задание заменяет его и очищает память поиска,
а явное «Продолжи» сохраняет цель и её координаты.
Уже выполняющаяся команда мода при этом отдельно отменяется через `@stop`.

Пример задания: **«Вырастить дуб, используй не больше 6 костной муки. Подтверди рост
по появлению ствола»**. Критерий завершения — `status="grown"`, а не сообщение в чате.
Текущие `.md` можно редактировать: соответствующая инструкция читается при следующем
задании. Для новой процедуры добавь файл, запись в `saruman/procedures.py` и правило
выбора; инструменты в инструкции должны реально существовать в tool bank.

Для текстового этапа без распознавания речи: добавь `-NoStt` и к Doctor, и к запуску.
`-NoFilter` допустим для диагностики в приватном мире, но отключает модерацию.

Если PowerShell блокирует скрипт, не меняй глобальную execution policy; эквивалент:

```powershell
uv run --locked --python 3.10 --no-default-groups --group collectors saruman-minecraft doctor --live
uv run --locked --python 3.10 --no-default-groups --group collectors saruman-minecraft run
```

## 5. Обязательный Windows smoke test

- [ ] Doctor показывает профиль Saruman, подключение к миру и БД.
- [ ] Start запускает один агентный цикл; в логах нет переподключений по кругу.
- [ ] Сообщение с обращением к Саруману попадает в его контекст; ответ — в игровой чат.
- [ ] Разрешённое follow/goto вызывает реальное движение, а не только реплику.
- [ ] После движения состояние/цепочка задач подтверждают результат. Постановка
      команды в очередь сама по себе не доказывает завершение.
- [ ] TTS слышен в OBS и через виртуальный микрофон в Simple Voice Chat.
- [ ] Голос другого игрока распознаётся с правильным именем; нет самоподслушивания TTS.
- [ ] OBS захватывает именно игровую сцену, VTube получает разрешение и двигает аватар.
- [ ] После перезапуска сохранились записи отношений в PostgreSQL.

Штатный Stop останавливает решения агента, **не гарантирует остановку уже запущенного
маршрута UnionClef**. Для аварийной остановки движения используй `@stop` в игровом чате.
При зависшем вызове модели действует таймаут; не нажимай Start повторно вслепую.

Голосовой манифест использует записи оператора: neutral.mp3 → neutral.wav
(0,16–5,80 с и 11,20–19,10 с, всего 13,66 с; чужая средняя реплика удалена), evil.mp3 → evil.wav
(13,813 с). angry и боевые реплики выбирают злой вариант, остальные эмоции —
нейтральный. Английские расшифровки референсов сохранены на языке оригинала;
текст реплик Сарумана остаётся русским. VoicePlaybackRate=1.0 сохраняет темп и
высоту без прежней прибавки 5%. Подробнее: [голосовые референсы](../resources/Characters/Saruman/Voice/README.md).
Проверочные WAV находятся в data/voice-previews/v2/saruman-neutral-ru.wav и
saruman-angry-ru.wav; это одна фраза с одинаковым seed, чтобы сравнить варианты на слух.
Создать новые пробы: `.venv\Scripts\python.exe scripts/preview-saruman-voice.py`.
Каждый запрос передаёт WAV/расшифровку без серверного reference cache; консоль
`[FISH TTS]` показывает фактический референс и хеш. После изменения профиля нужен
перезапуск Python, без Docker rebuild. Передача референса не гарантирует точную копию тембра.

Если пробы `v2` устраивают, но игровая речь звучит иначе, открой в Gradio **Voice Agent**:

- **Проиграть пробу v2 через TTS** отправляет готовый neutral/angry WAV на то же устройство,
  что и речь персонажа, без повторного синтеза. Это проверка вывода звука.
- **Обновить последнюю озвучку** показывает фактическую последнюю реплику до вывода,
  устройство, частоту и результат воспроизведения. WAV сохраняется в
  `data/tts/last-generated.wav`, метаданные — рядом; новые реплики заменяют прежнюю.
- Если сохранённая реплика звучит хорошо, а вывод через TTS плохо — проверь устройство
  `SOUND_DEVICE_IN` и его настройки Windows. Если плох сам WAV, смотри `[FISH TTS]`:
  профиль должен быть Saruman, референс neutral.wav/evil.wav, seed=42, cache=off.

Игровой синтез Saruman использует seed=42, как одобренные пробы,
и temperature=0.7 для angry/боевых эмоций, 0.4 для остальных. Проба angry в v2
обновлена после жалобы на металлические стуки; её прежняя версия сохранена в angry-debug.
Вывод звука работает
через sounddevice/WASAPI, ждёт окончания буфера и пересчитывает частоту по времени,
сохраняя темп и высоту. `FX_SOUND_DEVICE_IN` отдельно управляет сигналами интерфейса;
записи системного диктора из `resources/Audio/fx/records/` используют собственный голос.
После обновления зависимостей и перезапуска Python пересобирать Docker не требуется.

Адрес игрового сервера задаётся в Minecraft. Его порт и UDP-порт Voice Chat —
отдельные настройки сервера, не порты Python. Установка WSL2 backend Docker
не позволяет одновременно работать в двух загруженных ОС dual-boot: при уходе
из Windows все её процессы останавливаются.

## Проверки разработчика в Ubuntu

Из корня ai-saruman сначала перейди в игровой runtime. Далее все команды
используют его собственный `pyproject.toml`, `uv.lock` и локальную `.venv`:

```bash
cd integrations/saruman
uv sync --locked --python 3.10 --no-default-groups --group collectors
uv run --locked --no-default-groups --group collectors python -m unittest discover -s tests -p test_saruman.py -v
uv run --locked --no-default-groups --group collectors saruman-minecraft doctor --env-file .env.saruman.example
```

Последняя команда с незаполненным example обязана завершиться с FAIL для пароля БД.
Тесты используют fake RPC и fake gateway, а не реальную подписку или Minecraft.
Windows, слышимость голоса и GPU **не считаются проверенными** этими тестами.

Официальный протокол: https://learn.chatgpt.com/docs/app-server .
Адаптер следует account/read → thread/start → turn/start → agentMessage/usage/completed.
При обновлении Codex проверь совместимость протокола; stderr дочернего процесса
не сохраняется, чтобы не засветить приватные данные. Логи Saruman содержат текст
разговоров и аргументы игровых инструментов — не публикуй их без проверки.

## Имена и единые настройки

Сброс накопленного игрового опыта доступен в Gradio:
**Control → Игровая память · начать заново**. Нажми Stop, запланируй сброс
и полностью перезапусти Python. [Инструкция и состав очищаемых данных](help/GAME_MEMORY_RESET.md).

Текущий путь runtime — `integrations/saruman/`, пакет — `saruman-minecraft`.
`SARUMAN_CHARACTER_NAME=Saruman` выбирает профиль; старое имя переменной не используется.
`.env.example` и `.env.saruman.example` содержат одинаковые значения.
Основной конфиг читается раньше запасных `.env` и `.env.postgres`.

Локальный `docker-compose.override.yml` должен соответствовать новому example-файлу:
не включай в него `docker-compose.yml`, иначе получается рекурсивное включение.
Вариант `docker compose --env-file .env.saruman up -d --build` с новым override
и явный `-f compose.saruman.yml --profile rich --profile voice` используют одинаковые
сервисы и том. Старые контейнеры/данные не удаляются и не мигрируются переименованием.
Если там уже есть память, сохрани резервную копию и перенеси данные отдельно.

После перемещения каталога выполни `uv sync` из раздела подготовки сервисов,
чтобы переустановить команды и editable-пути виртуального окружения.
