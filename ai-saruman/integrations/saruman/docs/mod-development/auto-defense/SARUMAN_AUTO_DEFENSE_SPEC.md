# Saruman: интеграция универсального Auto Defense

Дата: 20 октября 2026. Это план будущей интеграции, а не описание уже подключённого JAR.

Основное независимое ТЗ для разработчика мода:
[Auto Defense 0.2.0](AUTO_DEFENSE_SPEC.md).
Передавать разработчику оба документа. Реализация общего боя находится в моде;
этот файл описывает только профиль персонажа, адаптер и переход текущего runtime.

Правила реализации под конкретную версию:
[Minecraft 1.21.11: инженерное руководство](AUTO_DEFENSE_IMPLEMENTATION_GUIDE_1_21_11.md).
Оно дополняет ТЗ точками проверки ввода, серверной синхронизации и совместимости.

## 1. Разделение ответственности

| Компонент | Что в нём находится |
|---|---|
| Универсальный Auto Defense | Наблюдение угроз, оружие, лук/щит, навигация, укрытие, уклонение, отступление, еда и выход из воды |
| Профиль Saruman | Правила целей, радиусы/пороги, приоритет посоха, разрешённое снабжение и ограничения ресурсов |
| JVM-адаптер UnionClef | Захват/освобождение ввода и checkpoint нативной задачи, без ожидания Python |
| Python-адаптер Saruman | Выбор backend, настройка профиля, статусы/events, связь с Gradio и обычными заданиями |
| LLM | Намерения, общение и объяснение подтверждённых событий; не отдельные боевые клики |

Для Saruman выбран **полный самостоятельный боевой контур нового мода**:
его CombatNavigation управляет всеми перемещениями в бою, уклонением и отступлением.
Боевая навигация не делегируется UnionClef. UnionClef остаётся исполнителем
мирных заданий вне боевого владения, источником наблюдений и объектом адаптера
приостановки/возобновления. Публичный мод сохраняет возможность иных backend
для других пользователей, но этот профиль требует native combat movement.

Обычный пользователь скачивает основной JAR Auto Defense, без исходников Saruman,
Python, Redis, Gradio, UnionClef и Magical Scepter. Дополнения опциональны.
У Saruman нет собственного форка алгоритма боя: те же состояния и действия
вызываются через публичный API и профиль. Не превращать персонажа в обязательную
зависимость и не переименовывать универсальные методы под его имя.

Текущие runtime-файлы пока не менять из-за одного появления нового ТЗ:
JAR ещё не предоставлен, совместимость и игровой бой не проверены.

## 2. Профиль Saruman

Профиль подключается явно при выборе нативного backend. Не включать его принудительно
в стандартную установку Auto Defense и не зашивать в общий CombatController.

Требования профиля:

- Враждебные мобы могут атаковаться первыми; игрок — только по достоверному урону
  по самому персонажу, с проверкой владельца снаряда.
- Жители, торговцы, големы, скот, питомцы и прочие животные защищены, даже если напали.
- Игровой чат/реплика LLM не отменяют защищённые типы и не создают доказательство урона.
- Радиус обнаружения по умолчанию 32; доказательство нападения 20 секунд;
  ответное преследование игрока ограничено 12 блоками.
- При ≤4 HP — отступление, при восстановлении до ≥10 HP — переоценка боя.
- В воде сначала спасение; сухие шаги по берегу допустимы, нырять за целью нельзя.
- Если установлен и реально поддерживается Magical Scepter, безопасная подходящая
  магия предпочтительна. Без него работают меч/топор/лук/щит, без блокировки жизни.
- Выдача недостающего оружия и XP через доступные команды явно разрешена заранее.
  Не ждать выдачи в бою и не объявлять команду успешной без наблюдения.
- Ручной аварийный Stop выше всех задач; разговор с игроками приоритетнее фоновых дел,
  но не должен мешать срочному спасению и защите.

Это ограничения профиля интеграции. Универсальное ядро предоставляет механизм
профилей и обязательной проверки их правил перед действием. Оно не знает имя
персонажа, его личность и базу памяти.

## 3. Как выбирается боевой backend

Один параметр defense_backend с вариантами current, native, auto:

- current — существующий Python CombatReflex; сохраняется до готовности мода.
- native — Auto Defense через проверенный публичный API; при несовместимости
  показать ошибку выбора, не подменять его незаметно другим бойцом.
- auto — выбрать native только после успешной проверки совместимости, иначе current.

Не выбирать backend по одному наличию mod ID. До активации проверять:

1. Версию API и формата snapshot, world/session и свежесть tick.
2. Реальные capabilities: самостоятельный бой, работоспособная навигация,
   вода/освобождение ввода, профили, журнал событий и нужный арбитраж управления.
3. Загруженный JVM-адаптер для фактически установленного UnionClef.
4. Возможность применить обязательные ограничения профиля.
5. Возможность отключить конкурирующих владельцев управления и подтвердить передачу.

Дополнительно требуется capability native_combat_movement: собственный игровой
контроллер дистанции, стрейфа, наведения и отступления без вызовов UnionClef goto.
Наличие лишь melee/bow API не удовлетворяет этому профилю.

Обычный пользователь Auto Defense не обязан иметь эти внешние интеграционные
capabilities: они нужны именно для режима Saruman. Без адаптера мод может работать
standalone, но связка с этим runtime не считается готовой.

Активный backend, запрошенный backend, причина отказа и фактический owner выводятся
раздельно. Отсутствие мода не ломает запуск приложения.

## 4. Передача управления и устранение дублирования

Переключение backend — операция, а не простая смена булевого флага:

1. Убедиться, что текущий бой/спасение позволяют безопасную передачу. Обычное
   переключение откладывается до безопасного состояния; аварийный Stop освобождает ввод.
2. Зафиксировать текущие настройки и checkpoint обычной задачи.
3. Остановить старого владельца и подтвердить отсутствие его маршрута/удержаний.
4. Настроить профиль/адаптер нового backend, получить результат применения.
5. Активировать нового владельца и опубликовать его поколение/lease.
6. При ошибке откатить переход только после подтверждения освобождения нового владельца.

При native backend:

- Python CombatReflex больше не выбирает цель, не вызывает attack/cast и не ведёт погоню.
- Нативные конкурирующие боевые цепочки UnionClef приостанавливаются адаптером.
- Во время боевого lease остановлены его TaskRunner и все активные исполнители
  пути, а не только текущая пользовательская задача. Подавляются независимые
  записи UnionClef/Tungsten в движение, поворот, sprint/jump, слот и attack/use.
  Обрабатываются также отложенные release/reset старого контроллера, чтобы они
  не отпускали ввод нового владельца. Не отключать полезные read-only trackers.
- Обычные инструменты движения/выбора предмета проверяют общий owner/lease;
  Java-адаптер блокирует устаревшие низкоприоритетные команды даже при задержке Python.
- Водное спасение имеет одного фактического владельца. В первоначальном native
  варианте им является WaterSafety мода; прежний Python WaterSafety наблюдает,
  но не шлёт ввод. Вариант с внешним спасателем допустим только после отдельной
  проверенной передачи lease, без одновременного управления.
- Возрождение может оставаться в bridge. DEAD у мода всегда означает отпущенный ввод;
  после respawn мод заново наблюдает мир и не воскрешает старую погоню.
- Питание в бою выполняет мод. Фоновая еда Python/UnionClef не подменяет предмет
  в руке, пока каналы инвентаря/use заняты боевым lease.
- Один владелец снабжения: для нового native профиля предпочтителен мод с
  command_supply, явно разрешённым оператором. Python ensure_scepter тогда не
  дублирует выдачу. Если выбран external supply, расширить текущую подготовку
  до лука/стрел и требуемого комплекта до переключения, а не считать это готовым.

Настройки UnionClef восстанавливаются только если адаптер всё ещё владеет
своим изменением. Старый close/cleanup не должен включать MobDefense поверх нового
контроллера или отменять чужой актуальный маршрут.

Проверено чтением установленного unionclef-1.21.11-0.95.61.jar:
PauseCommand сохраняет задачу, останавливает UserTaskChain и выключает TaskRunner;
stopTasks вызывает Nav.cancelAll; InputControls предоставляет releaseAll.
При этом AltoClef.onClientTick содержит InputControls.onTickPre/onTickPost
и WeaponSelector hooks вне TaskRunner.tick. Поэтому наличие pause/disable
само по себе не доказывает отсутствие вмешательства всех этих путей.
TaskRunner.disable также останавливает цепочки и меняет стек behaviour:
восстановление прежней задачи требует отдельной проверки, не простого enable.

Адаптер должен проверить точную версию и подавлять только изменяющие ввод/слот
участки на время чужого lease. Если публичных точек недостаточно, допустим
отдельный version-specific compatibility addon с mixin/accessor к UnionClef.
Универсальное боевое ядро не форкается и не получает жёсткую зависимость от него.
Совместимость с этой версией остаётся непроверенной до совместного игрового теста.

## 5. Аварии, отключения и fallback

Сбой Python не должен останавливать уже включённую локальную защиту мода.
Жизненный цикл боя, вода, освобождение ввода и его watchdog работают внутри JVM.

API недоступен — не означает, что мод уже отпустил управление. Запрещён слепой
запуск Python-бойца поверх потенциально активного native backend.
Сначала подтвердить освобождение через доступный JVM-адаптер/его watchdog или
зафиксировать состояние CONTROL_UNKNOWN и приостановить новые обычные действия.
Аварийный локальный Stop должен оставаться доступным пользователю.

Переход обратно к current разрешён после проверенного release: активировать его,
восстановить только принадлежащие ему настройки, повторно прочитать мир/инвентарь.
Не переносить живые Entity references между backend и world sessions.
Отдельный сбой HUD/журнала не является причиной отключить рабочий бой.

## 6. API, Gradio и озвучка

Python использует универсальный AutoDefenseApi и согласованную версию JSON:
cached snapshot и события с sequence. Никаких команд «повернись», «натяни лук»,
«подними щит» через LLM в процессе боя.

Gradio показывает:

- Выбранный/активный backend, API/mod version, профиль и capabilities.
- Enabled, state, фактического владельца, цель, дистанцию, оружие, щит и HP.
- Причину отказа/ожидания, ошибки совместимости и состояние передачи управления.
- Наблюдаемую потерю HP отдельно от доказанного собственного попадания/убийства.
- Задержки обнаружение→решение→действие и свежесть snapshot.
- Ограниченный журнал событий; gap приводит к перечитыванию snapshot, не к повтору атак.

Из Gradio разрешены включение/пауза/остановка, выбор профиля/параметров и backend.
Изменения подтверждаются фактическим состоянием мода. Stop/Start приложения
не должны незаметно оставлять отдельный мод в прежнем автономном состоянии:
при явном Stop отправить остановку и показать, подтверждена ли она.

Озвучка и реплики идут по значимым событиям асинхронно. Ни начало боя, ни выпуск
стрелы, ни выход из воды не ждут TTS или LLM. Повторные cooldown/poll события не озвучивать.

## 7. План перехода

1. Сначала реализовать и испытать универсальный мод на чистом клиенте:
   один JAR + Fabric API, F8, vanilla бой и локальная навигация.
2. Зафиксировать API v1 и реальную таблицу capabilities/совместимости.
3. Реализовать JVM-адаптер UnionClef и проверить захват/возврат отдельно от LLM.
4. Добавить тонкий Python backend-адаптер и профиль Saruman; current остаётся доступен.
5. Проверить весь путь native в отдельном тестовом мире, включая воду, смерть,
   две системы снабжения, потерю bridge и ручной Stop.
6. Только после приёмки включать native как предпочитаемый вариант auto.

Пока JAR/API отсутствуют, не создавать фиктивную интеграцию, которая только
рисует native=true, и не удалять рабочий current backend. Подготовительные
документы не являются результатом переключения runtime.

## 8. Критерии готовности связки

Общая приёмка мода находится в основном ТЗ. Дополнительно для Saruman:

- Без JAR всё запускается с current; несовместимый JAR даёт ясную диагностику.
- С подходящим JAR и адаптером текущая задача прерывается на угрозу без LLM.
- Два боевых контроллера, спасателя или поставщика предметов не действуют одновременно.
- При native lease не зафиксировано ни одной попытки UnionClef изменить ввод,
  поворот или предмет, прошедшей мимо адаптера. Проверить после паузы, после
  respawn и при позднем завершении поиска старого маршрута.
- Стрейф, удержание дистанции, уклонение и отход идут собственным контроллером
  мода; остановка UnionClef pathfinder не делает нового бойца неподвижным.
- Проверено возобновление актуальной задачи один раз; новое намерение/смерть/Stop
  не приводят к возврату старого задания.
- Сквозь Gradio видно, что реально делает мод; команда accepted не выдаётся за действие.
- При обрыве Python мод защищается локально, а повторное подключение не создаёт дубль.
- Протестирован возврат current после подтверждённого release native.
- Проведены измерения задержек и сценарные испытания, а не только сборка.

«Идеально при любом сервере и сочетании модов» не является проверяемым обещанием.
Результат — документированная совместимость, измеримые задержки, отсутствие
конкурирующего управления и понятное восстановление в проверенных сценариях.

Git commit/push и публикацию выполняет владелец проекта.
