# Модовый runtime персонажа

Реализация от 24 октября 2026. Режим по умолчанию — `SARUMAN_AUTOMATION_MODE=mods`.
Запуск — прежним `scripts/start-saruman.ps1`, затем **Start** в Gradio.
Актуальное разделение LLM: [PersonaAgent и ActionAgent, модели по ролям](../../dev/ROLE_AGENTS.md).
Docker с STT/TTS пересобирать для этих изменений не нужно: меняется локальный Python bridge.

## Три канала

| Источник | Кто выбирает | Кто исполняет |
|---|---|---|
| Просьба игрока / оператора | LLM принимает просьбу, выбирает инструмент | Деревья → TreeGrow; прочее → очередь обычных команд UnionClef |
| Угроза, вода, восстановление | Auto Defense по игровым ticks | Auto Defense, без Python/LLM в боевом цикле |
| Самостоятельное занятие | Python runtime случайно выбирает после 20 секунд простоя | TreeGrow или следование за доступным игроком через UnionClef |

Игроки приоритетнее фоновой очереди. Немедленное спасение и уже активная защита
удерживают тело до безопасной передачи; отвечать игроку можно во время боя.
Фоновая посадка или следование отменяются ради обращения игрока голосом либо текстом
с сохранением подтверждённого количества. Обработка обращения не ждёт ответа LLM.
Остаток этой отменённой фоновой цели автоматически не навязывается после разговора:
планировщик позднее выберет новую цель.

`AutomationRuntime` вызывается из updater MineBridge раз в 250 мс независимо от
генерации ответа. Сам бой продолжает работать внутри Java-мода каждый tick.
Фоновый выбор не запускает LLM. Служебные chat-сообщения Minecraft не вызывают
процедурного планирования. HybridAgent наблюдает очередь целей: простой результат
передаёт PersonaAgent, составную просьбу возвращает ActionAgent для следующего шага.

Старые Python CombatReflex, WaterSafety, NavigationGuard и Autonomy не управляют
телом в режиме mods. Сохранены bridge respawn и запреты UnionClef на самостоятельные
атаки/добычу еды убийством животных. Auto Defense использует свой контроллер боя.
Общие команды LLM остаются доступны для актуальных просьб игроков; старые
микропроцедуры деревьев/боя/фермы/исследования и ручная еда скрыты и отклоняются.

## Очередь и интерфейс

Новые инструменты: `grow_trees(count)`, `get_mod_status()`, `cancel_mod_goal(goal_id)`.
Пример: «вырасти два дерева» → один `grow_trees(2)`; два нативных запуска выполняются
без вызовов модели между деревьями. Прибавление `completed` происходит только при
`GrowTreeTask.success()`. Принятие в очередь не подтверждает посадку или рост.

Gradio показывает модовый режим, владельца управления, очередь, состояние,
прогресс и причину последнего результата. Есть ручная постановка количества деревьев
и отмена очереди. В модовой панели показаны Auto Defense, TreeGrow и следование UnionClef;
старый список занятий и редактор их вероятностей отсутствуют. Auto Defense реагирует
на ситуацию. Отдельный переключатель TreeGrow разрешает или запрещает новые фоновые
цели. Через 20 секунд реального простоя runtime равновероятно выбирает доступное
занятие: дерево либо следование. Затем случайно выбирается живой загруженный игрок,
кроме самого персонажа. Если игроков нет, остаётся посадка. Диалог, бой, ручной Stop,
ожидание мира/возрождения и активная задача не считаются простоем.
После ошибки занятие освобождает очередь; при наличии альтернативы выбирается другое
занятие. Новая просьба игрока доступна сразу, фон снова выбирается после 20 секунд
простоя, без дополнительной паузы после ошибки. Подтверждённый
прогресс сохраняется. Последовательные деревья одной просьбы не ждут фонового таймера.
Остановка следования при исчезновении игрока не отменяет чужие задачи.

Смерть/смена мира (`RESET`) отличаются от ручного Stop (`STOPPED`). После возрождения
автоматизация снова доступна, но старый оборванный запуск не воспроизводится вслепую.
Ручной Stop автоматически не снимается. Отмена собственной задачи не выключает весь
TaskRunner UnionClef. Завершённый корень снимается только при точном совпадении с нашей
задачей; квитанция и результат остаются доступны. Lab показывает текущую причину ожидания.

Очередь хранится в `data/automation.sqlite` (SQLite, несколько процессов, транзакции).
Это локальный журнал исполнения, независимый от PostgreSQL социальной памяти.
Путь можно заменить переменной `SARUMAN_GOALS_DB`. Запросы имеют идентификаторы;
runtime резервирует доставку до отправки, Java держит ограниченный журнал квитанций.
Одна SQLite lease разрешает управление только одному bridge одновременно.

После обрыва Python в том же Minecraft JVM адаптер переиспользует Java-журнал и
текущую задачу. После перезапуска Minecraft, смены мира или версии адаптера текущий
непроверенный запуск получает `uncertain`: сохранённый счёт остаётся, повторной посадки
вслепую нет. Оператор может поставить новую цель на оставшееся количество.
Произвольные команды, прерванные защитой, также требуют наблюдения перед продолжением.
Для обычной команды переход UnionClef в idle означает окончание активности,
но ещё не доказывает выполнение желаемого результата.

Потеря связи с Minecraft не означает отмену поручения. Мост отмечает игровые данные
как недоступные, закрывает старое соединение и обратный порт, затем заново подключает
адаптер и защитные правила. Подтверждённый прогресс и идентификаторы запросов остаются
в журнале. Неизвестный результат команды автоматически не воспроизводится.
Ошибка очистки JVM не мешает закрыть оставшиеся сетевые ресурсы и освободить lease.

Служебный heartbeat Python-процесса и свежесть наблюдений Minecraft проверяются
отдельно. Если игровые данные старше 10 секунд, Lab показывает потерю связи вместо
старого занятия. Это проверка достоверности статуса, не ограничение времени задачи.
Повторное подключение не снимает ручной Stop; явный Start применяется один раз.

## Совместимость установленных JAR

Адаптер компилируется локально `javac --release 21` и загружается в существующий JVM.
Нужен JDK 21+ в PATH, либо абсолютный путь `SARUMAN_JAVAC`.
Собранный служебный класс лежит в `data/native-bridge/<hash>/`; это не новый Fabric-мод,
класть его в `mods` не требуется. Вызовы мира выполняются на client executor;
проверка SHA-256 артефактов и компиляция проходят вне игрового потока.

Текущий адаптер намеренно привязан к проверенным сборкам:

| Артефакт | SHA-256 |
|---|---|
| Auto Defense 1.0.0 | `e19d47caa2ae553ab81b5b84ab4fc11179595809797cee7d122cad5f2b1db43c` |
| Auto Defense addon 0.1.0, установленная сборка от 02.11.2026 | `5e773d1e64f651943b5faf709aea3ef1458503a2a25910acd476ab6a457e25cb` |
| Auto Defense addon 0.1.0, исправление handover от 11.11.2026 | `6943228ddd690a24b5aad2e98bccb36e798c15b96c0a57a419979e42eeabe4ce` |
| Auto Defense addon 0.1.0, исправление ложного Stop после handover | `15af6beddd33e4388812a4502f629fdf08d73dd711017c3950612658bb094385` |
| TreeGrow 0.1.0, сборка от 28.10.2026 | `edd7a699318d0b18f46abe67db25046502e20ca400f4751c0ac0679664e5bee9` |
| UnionClef 1.21.11 / 0.95.61 | `76bbb677d2f8294e6d2de98b554f81818ae15605ef8a82ff7e1d3b9b82555d1b` |

Публичные API этих модов неполны, поэтому reflection совместимости изолирован в
`resources/Minecraft/bridge/ModGateway.java`. Неизвестная сборка даёт явную ошибку;
автоматического перехода к конфликтующим Python-контроллерам нет.
После обновления JAR адаптер нужно проверить и обновить вместе с контрактными тестами.

Поддерживаются два проверенных контракта Auto Defense. В старом моде ID
`auto-defense`, клиент `dev.autodefense.client.AutoDefenseClient`, API
`AutoDefenseApi.getStatusJson()`. В установленном аддоне ID `auto_defense`,
клиент `dev.autodefense.AutoDefenseClient`, API `AutoDefenseApi.get().state()`.
Для аддона адаптер читает владение через `combat().ownsControls()` и этап действия,
включает/выключает `combat()` на клиентском потоке и сохраняет исходный JSON API.
`needs` доступен в совместимом поле `missingItems`; владельца показывает состояние
реального управления. Предметы выдаёт собственный EquipmentSupplier аддона:
второй Python-поставщик в этом режиме не запускается.

У старой сборки `5e773d1e…` выявлено бесконечное target-free handover при
нескольких целях за опасным перепадом высот. Исправленная `6943228d…`
помнит отказанные цели независимо по UUID и не создаёт новую приоритетную
цепочку при пустом обзоре. Пороги безопасности и нативный бюджет 60 тиков
сохранены. Выполнены 52 проверки и remapJar; продолжение движения в живом
мире после установки проверяется отдельно. Старый хеш оставлен только для
совместимости/отката, а не как рекомендация использовать старую сборку.

В `6943228d…` также выявлена оставшаяся отметка владения runner после передачи
управления обычной задаче или спасению UnionClef. Обычное завершение чужой задачи
из-за неё ошибочно считалось ручным Stop и отменяло TreeGrow. В `15af6bed…` отметка
снимается при обеих передачах; настоящий Stop во время боя сохранён. Две проверки
воспроизвели ошибку до исправления, затем все 61 проверка и remapJar прошли.
Живая проверка продолжения посадки после установки остаётся отдельным шагом.

Причина отмены очереди сохраняется: `Native task stop`, `Automation stopped` или
исходная причина оператора. `Player priority` обозначает только вытеснение фоновой
задачи поручением игрока, а не любую остановку его собственной задачи.

Ручной Stop аддона остаётся защёлкнутым: опрос не включает защиту обратно.
Статус runtime становится `paused`; явный Stop → Start в интерфейсе разрешает
возобновление. Подтверждение события ручной остановки не снимает native-защёлку.
Старая очистка `bridge.lastLine`/`handover.savedCommand` применяется только к старому
контракту. В новый аддон эти внутренние поля не записываются.

Doctor проверяет реальные API и SHA-256 исходных JAR через FabricLoader без
компиляции, включения модов и игровых действий. Пустой `TreeGrowClient.current()`
означает отсутствие текущей задачи и проходит проверку. Ошибка конкретного API
или неизвестная сборка теперь указываются в диагностике, без общего сообщения
об отсутствии всех модов.
Сборка TreeGrow с прежней контрольной суммой `90c1a826…` больше не является текущей
целью адаптера. Номер версии аддона не изменился, но изменились его классы и состояния.
Снимок теперь включает outcome/reason/interruption, счётчики sites/uses/giveSends и
оставшееся время remainingNanos. После допустимого resume очищаются также новые
терминальные статусы; таймер, счётчики, участок и факт выдачи муки сохраняются.
Обычная ошибка добычи не превращается в resume даже после наблюдавшегося боя.
Прерывания сторонних цепочек без подтверждённого боевого перехвата остаются ошибкой:
адаптер не переопределяет Unstuck и не возобновляет любые отменённые задания.

Совместимость включает атомарное включение защиты, проверку владельца перед запуском,
отключение дублирующего command replay защиты, продолжение **того же** TreeGrow после
подтверждённого боевого прерывания без сброса участка/таймера/лимита и повторный вход
в нативное получение саженца после исчерпания саженца на неудачном участке.
Ручная отмена, смерть и смена мира не считаются разрешением такого resume.

TreeGrow сейчас сам выбирает дуб/берёзу. Строгая порода, режим «только посадить»
и пользовательский лимит костной муки не входят в его API. Адаптер не притворяется,
что поддерживает их. Действуют лимиты установленного мода: три места, до 16 применений
на место, пять минут на один запуск. Старое правило пяти применений Python здесь
не применяется. Магия Magical Scepter в новом Auto Defense не реализована и через
старый Python-контроллер параллельно не запускается.

Внешний `ModSupply` в спокойном состоянии читает `missingItems` Auto Defense и,
при серверных правах `/give`, запрашивает только недостающее из разрешённого комплекта:
меч, щит, лук, стрелы, еду, лечебные зелья с компонентом healing. Запрос резервируется
до отправки, подтверждается исчезновением нужды в нативном инвентарном снимке и
не повторяется раньше 60 секунд. Выдача не блокирует защиту. Без прав используются
наличные предметы; потребность видна в деталях. Костную муку получает сам TreeGrow;
второго поставщика для неё нет. XP и посох новый мод не запрашивает.

Для явного возврата старого поведения установите `SARUMAN_AUTOMATION_MODE=legacy`
и отключите Auto Defense вручную. Совместный независимый бой двух контроллеров
не является поддержанным режимом.

## Проверки и пределы подтверждения

Python-тесты проверяют очередь, количество, отмену, приоритет, lease, восстановление,
потерю ответа, неопределённый результат команды, отсутствие модового навыка и снабжение.
Java fixture-тест проверяет рефлективные сигнатуры, порядок операций, запрет запуска
при защите, дедупликацию, продолжение того же объекта и смену мира.

Сборка адаптера и эти тесты не подтверждают физику боя/плавания или рост в игре.
Read-only подключение к `127.0.0.1:25333` во время реализации было недоступно.
Не выполнялись игровые команды, бой, выдача предметов или перезапуск Minecraft.

Перед длительным запуском проверить в тестовом мире:

1. Start включает Auto Defense; Stop отпускает его и останавливает свою очередь.
2. Два дерева дают подтверждённые `1/2`, `2/2` без новых обращений к LLM между ними.
3. Нападение прерывает посадку; после защиты продолжается прежняя задача/участок.
4. Просьба игрока прерывает фоновое дерево; `@goto`/получение кирки работают через очередь.
5. Вода, отступление, щит/лук, отсутствие прав и возрождение работают с этими JAR.
6. Повторное подключение bridge не создаёт дубль; смена мира показывает `uncertain`.

До прохождения этих сценариев игровой статус — **NOT_TESTED**.
