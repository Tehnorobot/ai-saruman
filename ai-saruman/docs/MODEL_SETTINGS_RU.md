# Модели Saruman Lab

Окно: **Настройки** — http://127.0.0.1:8765/#settings.
У каждой задачи есть свой провайдер, модель и reasoning. Настройка выбирает
реальный клиент; скрытой замены на другого провайдера нет.

## Основные роли

| Роль | Что получает модель | Что возвращает |
|---|---|---|
| Чат Lab и память | Личность, память, диалог, сообщение | Реплику и факты; это один вызов |
| Персонаж | Проверенные события, исходную просьбу, личность | Речь, эмоцию, признак нужного действия |
| Игровые действия | Состояние игры, исходную просьбу, доступные инструменты | Предложения команд с аргументами |
| Telegram | Подтверждённые события и недавние посты | Текст и ID исходных событий |

Речь и инициатива используют PersonaAgent. Команды проверяет Python; исполняют
их нативные моды. Доставка Telegram, очередь, запись памяти, навигация и моды
не требуют собственных LLM. TTS/STT — отдельные системы звука.

Свёрнутый раздел содержит настройки старых Core/Planner/Reaction/Chat/Browser
агентов и инструментов оценки диалога, имени и изображения. Они применяются
только при вызове соответствующей функции. Выбор модели их не включает.
Анализ изображения требует модели с поддержкой изображений.
Экспериментальные скрипты в `src/experiments` не входят в работающий runtime.

## MiniMax M Plan Explore

1. В [Plan Details](https://platform.minimax.io/console/plan) скопируй Subscription Key.
2. В локальном `integrations/saruman/.env.saruman` укажи:

```dotenv
MINIMAX_API_KEY=ваш_Subscription_Key
MINIMAX_BASE_URL=https://api.minimax.io/anthropic
```

3. Перезапусти Python-процессы Lab и игрового runtime. Minecraft можно оставить.
4. Открой Настройки. В нужной роли выбери MiniMax / M Plan → MiniMax-M3.1-Flash.
5. Выбери reasoning и сохрани роль. Остальные роли не изменятся.

M3.1 Flash всегда использует thinking. Варианты: low, medium, high, xhigh, max;
default означает max. Для быстрых решений можно начать с low. Лимит ответа
API включает thinking. При выборе MiniMax интерфейс предлагает минимум 32768
токенов ответа; значение можно изменить в раскрываемых настройках. Это потолок,
а не обязательный расход. Верхнюю границу клиент не навязывает; ограничения
конкретной модели проверяет провайдер.

Subscription Key использует квоту M Plan и подключённые Credits.
Обычный pay-as-you-go ключ имеет другой способ оплаты. Клиент не может по строке
ключа проверить тип подписки. Выбирай ключ на странице плана.
Официальные источники: [M Plan API](https://platform.minimax.io/docs/m-plan/quickstart),
[reasoning и Messages API](https://platform.minimax.io/docs/api-reference/text-chat-anthropic).

Для Codex используй `codex login`, затем «Обновить каталог Codex» в настройках.
Полученные модели и их reasoning сохраняются в общей базе. Локальный стартовый
каталог не доказывает доступ аккаунта; доступ подтверждается реальным ответом.
Для LiteLLM и DSLab используются соответствующие переменные из шаблона окружения.

## Сохранение и применение

Общая база: `integrations/saruman/data/role-models.sqlite`.
`SARUMAN_ROLE_DB` позволяет выбрать другой файл; относительный путь считается
от `integrations/saruman`. Оба процесса должны использовать один файл.
Модель роли читается перед каждым запросом. Текущий запрос нельзя перенастроить;
остальные роли можно изменить независимо. Устаревшее окно не перезапишет
более свежую настройку. При ошибке обнови страницу и повтори сохранение.

При первом обновлении останови оба старых Python-процесса перед открытием нового
Lab: старый runtime не знает добавленных ролей. После обновления настройки
применяются со следующего запроса без перезапуска. После изменения ключей нужен
перезапуск: переменные процесса имеют приоритет над файлом окружения.
Сохранённая роль имеет приоритет над начальным CORE_LLM_MODEL_NAME.

Существующие PersonaAgent и ActionAgent сохраняют свои настройки.
Старый профиль Telegram наследует ранее выбранную PersonaAgent один раз.
Новые роли первоначально используют Codex. Открытие окна или сохранение
настроек не создаёт запрос к LLM и не включает платный API автоматически.

## Как проверить

1. Выбери MiniMax только для чата Lab. Отправь короткую реплику.
2. В настройках открой последние запросы: роль lab_chat, провайдер minimax,
   выбранная модель, статус, вход, выход и кэш должны совпадать с запросом.
3. Проверь, что PersonaAgent и игровые действия сохранили свои модели.
4. Обнови страницу: сохранённая роль должна остаться.
5. Для Telegram сначала оставь автопубликацию выключенной. При включённом
   Telegram и работающем игровом runtime дождись черновика из реального события.

Без ключа показывается конкретное имя переменной. Наличие ключа означает только
готовность конфигурации, а не подтверждённый доступ. Ошибки доступа не переключают
провайдера. Входные токены включают чтение/запись кэша; общий расход не складывает
эти значения повторно. Неизвестный расход остаётся неизвестным.

История в окне показывает 40 последних запросов. Полная история остаётся в SQLite.
Ключи и адреса с секретами не возвращаются в браузер и не пишутся в эту базу.
