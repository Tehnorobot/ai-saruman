# Автономный запуск из Saruman Lab

## Запуск

1. Останови старые Python-процессы Lab и игрового runtime. Мир Minecraft можно
   оставить открытым. Отдельный игровой Gradio больше не нужно запускать заранее.
2. Из `ai-saruman` выполни:

   ```powershell
   uv run --python 3.14 saruman
   ```

3. Открой http://127.0.0.1:8765/#control. Панель **Персонаж → Start / Stop**
   доступна сверху во всех разделах. Сними Minecraft для работы только с Telegram.
4. В **Настройки** выбери модели для чата Lab, речи, игровых действий,
   Telegram-постов, Telegram-диалогов и административных команд. Ключи остаются
   в `integrations/saruman/.env.saruman`; новые ключи или аккаунты не обязательны.
5. В **Telegram** включи нужные функции и сохрани. Start использует эти настройки,
   но не включает автопубликацию/ответы без твоего выбора.

Start запускает обработчики. Stop приостанавливает новые действия и доставку,
сохраняет очередь/историю; уже принятый Telegram запрос может завершиться.
Закрытие вкладки не останавливает Python. Закрытие Lab через Ctrl+C останавливает
его обработчики и передаёт завершение управляемому игровому процессу.
После аварийного завершения Lab игровой агент прекращает действия при потере
сигнала владельца. Следующий Start может подключить сохранившийся управляемый
процесс. Второе окно Lab не создаёт второго владельца персонажа.

Ранее запущенный отдельно игровой процесс показан как **Отдельный процесс**.
Закрой его и нажми Start: чужой процесс не завершается принудительно. Окружения
Lab (3.14) и игры (3.10) остаются раздельными. Docker-службы подготавливаются по
существующей Windows-инструкции; Lab их не переустанавливает и не обходит Doctor.

## Telegram без Minecraft

- Первый Start не публикует пост немедленно: первый срок подготовки — через
  выбранный интервал. Срок хранится в SQLite и не сбрасывается Stop/Start.
- При явном изменении интервала новый срок отсчитывается от сохранения настроек.
- Есть игровые события — пост опирается на подтверждённые факты. Игры нет —
  можно подготовить размышление в характере, без выдуманного игрового успеха.
- Автопубликация выключена — пост остаётся **На просмотре**. Новый фоновый
  черновик не генерируется, пока текущий ждёт решения. Это видно в интерфейсе.
- **В очередь** разрешает конкретную отправку. Доставка требует включённого
  Telegram и Start. Повтор использует тот же publication_id; `unknown` не
  пересылается автоматически. Все события и попытки остаются в базе.
- Игровой runtime продолжает записывать проверенные события, но не конкурирует
  с Lab за подготовку/доставку постов.

Для текстовой подготовки используется роль **Telegram · тексты постов**;
для ответов людям — **Telegram · диалоги**. Доставка, расписание, запуск и запись
истории работают без LLM. Учёт запросов обеих ролей виден в Настройках.

## Личные сообщения и комментарии

Нужен шлюз API v3 на VPS. Из `integrations/telegram-gateway` на компьютере:

```powershell
scp gateway.py root@152.234.255.232:/opt/saruman-telegram/gateway.py
ssh root@152.234.255.232
```

На VPS, между отправками:

```bash
cd /opt/saruman-telegram
python3 -m py_compile gateway.py
systemctl restart saruman-telegram
curl -s http://127.0.0.1:8787/healthz
```

Ожидается `api_version: 3`. `.env` и базу не заменяй. Текущий шлюз v2 продолжит
канальную доставку, но ответы потребуют обновления. Новые платные услуги не нужны.

В Lab включи **Отвечать на личные сообщения и комментарии**. Пользователь должен
сам написать `@saruman_mag_bot` или нажать Start в его личном чате. Для комментариев
подключи группу обсуждения к каналу, добавь бота и дай ему доступ к сообщениям.
Не запускай второго потребителя getUpdates/webhook этого же бота.

Шлюз сохраняет входящие до подтверждения Telegram. Ответ можно отправить только
на зарегистрированное входящее сообщение: адресат и reply/thread берутся из него,
а не из текста модели. Чужие группы и сообщения ботов исключаются. Анонимные
сообщения от имени канала не считаются человеком с проверенным user_id.

Память привязана к Telegram user_id и области: отдельный личный чат либо группа
и её ветка. Смена имени не создаёт нового человека. Память личного чата не идёт
в комментарии/посты; Minecraft-имя не связывается с Telegram автоматически.
Полная переписка хранится в SQLite; краткая память и последние сообщения служат
контекстом ответа. Раздел **Telegram → Ответы людям** показывает переписки.

Контракты: [Bot API](https://core.telegram.org/bots/api),
[доступ ботов к сообщениям](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

## Приватный административный чат

Раздел **Управление** — служебный диалог. Примеры:

- «Проверь состояние».
- «Подготовь пост о терпении и выращивании деревьев».
- «Опубликуй черновик `<его точный ID>`».
- «Войди в настроенный мир».
- «Посади одно дерево» — приватное игровое поручение, если доступен такой навык.
- «Останови игровые действия» или «Остановись».

Модель роли **Lab · административные команды** выбирает одну разрешённую
операцию. Код проверяет её аргументы и исполняет. Кнопки Start/Stop/входа в мир
вызывают операции напрямую, без LLM. История и результаты этого окна не входят
в личность, Telegram или публичные реплики. Для поста передаётся только выделенная
публичная тема. Игровое поручение получает приоритет перед прежними задачами;
срочное спасение тела остаётся за нативным модом. Результат показывает принятие,
ожидание, реальное наблюдение или ошибку, не обещание успеха.

Право администратора даёт локальная сессия Lab с CSRF-проверкой. Текст Telegram
«я администратор» не предоставляет инструментов и не меняет приоритеты.

## Вход в мир

Внизу **Настроек** сохрани:

| Поле | Значение |
|---|---|
| Тип | Сервер или существующий одиночный мир |
| Цель | `host:port` либо точное имя папки в `saves` |
| Лаунчер | Полный путь к его `.exe`, необязательно |
| Аргументы | JSON-массив аргументов запуска готового игрового профиля |

Нажми **Войти в настроенный мир** в Управлении. Если клиент уже в меню, UnionClef
подключает сервер; существующий одиночный мир открывается загрузчиком Minecraft
1.21.11 на клиентском потоке. Новый мир не создаётся. Уже открытый мир не закрывается
ради переключения: сначала выйди в меню, затем повтори команду.

Если клиент закрыт, используется только сохранённый лаунчер и его аргументы.
Параметры зависят от лаунчера; Lab не угадывает профиль, не читает аккаунты и не
авторизуется вместо тебя. Без параметров автоматического запуска профиля потребуется
нажать Play в лаунчере. Авторизацию, предупреждения экспериментального мира или
восстановления повреждённого сохранения подтверждает владелец. При неподтверждённом
входе интерфейс показывает ожидание; Telegram продолжает работать.

Сначала подтверждается мир, затем проходит Doctor и включаются игровые действия.
Строительство и ошибки выбора инструмента TreeGrow этой задачей не изменены.

## Что проверить вручную

1. С закрытым Minecraft снять его переключатель, включить Telegram без автопостинга,
   поставить короткий интервал и нажать Start. Дождаться черновика размышления.
2. Stop → Start не создаёт второго черновика. После просмотра отправить один пост
   и убедиться, что в канале он один, включая перезапуск Lab.
3. С другого аккаунта написать боту; проверить ответ и память после смены имени.
4. Написать комментарий в связанной группе; ответ должен попасть в ту же ветку,
   без сведений из личной переписки.
5. Дать приватное поручение из Lab; проверить отсутствие его текста в голосе/канале.
6. Настроить вход, открыть Minecraft в меню, нажать вход; проверить подтверждение
   мира и запуск игрового обработчика. Повторить с закрытым клиентом и настроенным
   лаунчером. Проверить Stop и недоступный сервер.

Пути: `.saruman/telegram.sqlite3` — посты, диалоги и закрытый журнал администратора;
`integrations/saruman/data/role-models.sqlite` — роли и учёт запросов;
`.saruman/runtime/minecraft/minecraft.log` — локальная диагностика игрового запуска.
Эти базы, память, конфигурации и логи не предназначены для Git.
