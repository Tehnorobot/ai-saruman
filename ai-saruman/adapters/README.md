# Адаптеры Saruman Lab

Lab читает папки `adapters/<id>/` при запуске. В окне **Моды и адаптеры**
управляются выключатели, доступность в текущем мире и фоновая очередь.
В **Настройки → Адаптеры** выбираются провайдер, модель и лимиты каждого агента.
Отправьте поручение в приватном чате **Управление**.
Саруман определит адаптер по смыслу поручения. В ответе и журнале видно, кто его
получил. Явные отдельные команды «Построй … дом» направляются Mage Home сразу,
а при свободной формулировке используется модель административных команд.

## Передача управления

В запущенном из Lab игровом обработчике команды из **Управления** имеют приоритет
над просьбами игрока. Следом идут самозащита, обычные задачи и фоновый выбор.
Команда Lab ждёт, пока игровой обработчик подтвердит освобождение управления
для её адаптера. Фоновая стройка приостанавливается при вытеснении и возобновляется
с тем же идентификатором запуска. Явную паузу можно снять командой продолжения.
Если нативная задача не поддерживает безопасное продолжение после передачи
управления, журнал сохраняет подтверждённый результат прерванной задачи.

В **Моды и адаптеры → Фоновые занятия** каждому занятию задаётся вес от 0 до 1.
Вес 0 исключает занятие. Во время выбора вес делится на сумму весов доступных
занятий. Поиск враждебного моба выбирается из той же очереди, имеет вес 0
по умолчанию и получает до 20 секунд на попытку.

Из сообщения в чате откройте **Журнал команды**. В потоке Mage Home видны
стадии стройки, подтверждённый прогресс, попытки, маршруты и решения эксперта
из журнала клиента. Ответы моделей связаны с той же командой. В нижней панели
**Журнал Minecraft** можно выбрать текстовый лог игрового процесса Сарумана
или лог клиента Minecraft после подключения Mage Home.

## Mage Home

1. Установите клиентские моды по [инструкции Mage Home](../integrations/mage-home/README.md#установка-для-игры)
   и откройте одиночное сохранение или войдите на vanilla-сервер.
   Для снабжения применяется `/give`. Строительные операции выполняет персонаж.
   Для моста нужна подготовленная игровая `.venv` Saruman с Py4J.
2. Включите **Mage Home** в окне **Моды и адаптеры**. В **Управлении** отправьте
   `Построй тестовый дом`. Адаптер обследует загруженный рельеф на расстоянии
   до 112 блоков, выберет участок с учётом объёма расчистки и подсыпки и запишет
   угол пола в журнал. Mage Home уточнит работы по чертежу и выполнит их перед стройкой.
   Тестовый дом 7×7 использует зафиксированный чертёж и обходится без модели.
   Для точного места добавьте координаты вида `X 4, Y -60, Z 5`.
3. Напишите `Как идёт стройка?`, `Поставь стройку на паузу`,
   `Продолжи стройку` или `Останови стройку`. Статус относится к
   открытому миру и после перезапуска Minecraft показывает запись из журнала
   стройки. Сохранённый статус отражает последнее наблюдение. При потере ответа
   на запуск `Повтори запуск` отправит ту же заявку с исходным ID.
4. Для произвольного дома выберите профили **проектировщика** и **игрового
   эксперта** и отправьте описание дома. В автоматическом режиме задайте габариты
   пола как `12×10`. Обследование проверяет размеры 3–32 блока по стороне и
   использует площадку 13×13, если размеры не указаны. Mage Home проверяет
   подготовку участка и итоговые габариты чертежа. Эксперт вызывается в случае инцидента, который
   обрабатывает исполнитель. Проверенный чертёж хранится локально и
   переиспользуется при том же описании, мире, угле пола и возможностях клиента.
   Lab использует пакет проектирования из `integrations/mage-home/python/`.
   При отдельной поставке адаптера без этого каталога можно положить один
   совместимый wheel рядом с адаптером.

Адаптер использует локальный Py4J UnionClef. Для запроса с описанием он
передаёт модулю путь к Python-пакету и локальный профиль модели. Выбранный
провайдер вызывается из Lab. Ключи хранятся в существующей конфигурации Saruman.
Заранее подготовленный чертёж можно проверить с запущенным клиентом Minecraft.

## Протокол `saruman.adapter/1`

Папка адаптера содержит два файла. Её имя и имена ролей состоят из строчных
латинских букв, цифр и подчёркиваний и начинаются с буквы.

- `adapter.json` содержит `protocol`, `title`, `description`, необязательную
  подсказку `example` и объект `agents`. Каждый ключ в `agents` обозначает
  отдельную роль с `label` и `description`. У адаптера может не быть ролей.
  Необязательный `chat_route` задаёт регулярные выражения `match` и `exclude`
  для прямой передачи явной команды. Поле `chat_actions` объявляет имена и
  описания действий, из которых выбирает модель административных команд.
   `minecraft_mods` перечисляет необходимые ID Fabric. `minecraft_api` задаёт
   полное имя класса, наличие которого проверяет Lab. Необязательное поле
   `background_action` указывает ключ из `chat_actions`. Для этого действия Lab
   позволяет поставить одно явное поручение в очередь случайного выбора.
- `adapter.py` экспортирует `create(context)`. Объект из `create` реализует
  `handle(text, request_id)` и `stop()`. `handle` возвращает словарь с `detail`
  и необязательным `status`, например `answered`, `running`, `completed`,
  `needs_input` или `failed`. Выполняйте длительную работу асинхронно и
  возвращайте принятие задания. `stop()` отзывает задачи этого адаптера.
  Lab вызывает его при выключении адаптера и при общем Stop.
  Если объявлены `chat_actions`, реализуйте также
  `handle_routed(text, action, request_id)`. `text` содержит исходное сообщение
  пользователя, `action` — проверенный ключ из `chat_actions`.
- Для адаптера, который управляет персонажем, `background_busy` сообщает,
  удерживает ли он управление. `yield_control()` запрашивает паузу, а
  `reclaim_control()` продолжает приостановленный запуск после проверки
  состояния игры. `scheduler_paused` отмечает только паузу планировщика.
  Lab записывает источник запуска в `owner_source`.

`context` предоставляет `directory`, `project`, `data_dir`,
`state()` и `save_state(dict)` для состояния между перезапусками.
Для событий есть `record(kind, request_id=…, status=…, details=…, key=…)`.
Необязательный `observe(enabled, state)` вызывается в фоновом потоке для
чтения телеметрии. Он может выполняться параллельно с `handle` и `stop`.
Для вызова выбранной модели доступен `complete(agent, instructions, payload,
schema, request_id)`. Для собственного Python-процесса адаптер может передать
локальный `model_endpoint(agent, request_id)`. Он принимает два сообщения
`system` и `user` (JSON), модель указывается именем роли. Для допуска адаптер
сохраняет текущий ID как `model_request_id` в своём состоянии и снимает его при
остановке. Выключение запрещает новые сообщения и новые запросы к модели.

Lab исполняет `adapter.py` как локальный Python-код. Устанавливайте адаптеры
из доверенных папок. Для обнаружения добавленной папки перезапустите Lab.
