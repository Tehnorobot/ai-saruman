# Инструменты Сарумана

Этот файл — каталог и контракт для будущей интеграции. Наличие записи здесь
не предоставляет инструмент. Сейчас Minecraft, модель, доставка сообщений,
планировщик, голос и публикации к шаблону не подключены.

## Существующие локальные скрипты

Запускаются из корня репозитория, с AGENT_NAME=saruman. Скрипты используют
пути agent/$AGENT_NAME/... относительно корня, а не относительно папки персонажа.
Раннер должен фиксировать AGENT_NAME и рабочую папку, а не брать их из игрового чата.

| Вызов | Реальный результат |
| --- | --- |
| `AGENT_NAME=saruman bash agent/scripts/say.sh <recipient> <text>` | Добавляет строку в outbox.jsonl; не доставляет сообщение. |
| `AGENT_NAME=saruman bash agent/scripts/remember.sh <entity> <fact>` | Добавляет датированный факт в заметку сущности. Обратные ссылки и индекс обновляются отдельно. |
| `AGENT_NAME=saruman bash agent/scripts/sleep.sh <minutes>` | Записывает интервал в state/sleep.txt; не запускает планировщик. |

Передавай текст отдельными аргументами, без интерполяции пользовательских сообщений
в команды оболочки. Для сущностей используй стабильный безопасный идентификатор
(например, UUID игрока); исходный ник сохраняй в тексте заметки.

В шаблоне также есть ticket.sh, но он пишет в корневой tickets/, за пределами
папки персонажа. При заявленном ограничении записи только в agent/saruman/
не вызывай его напрямую: записывай сообщение получателю operator в outbox.jsonl.
Раннер сможет создать инфраструктурную заявку от своего имени.

## Предлагаемый игровой интерфейс — пока не реализован

Одна точка входа: `agent/scripts/minecraft.sh <action> [arguments]`.
Её реализацию добавит разработчик после выбора версии Minecraft, загрузчика модов
и способа управления мобом. Это не список существующих команд.

| Действие | Аргументы | Что должен вернуть инструмент |
| --- | --- | --- |
| `observe` | нет | Идентификатор и время снимка, измерение, позицию, окружение, существ и недавние игровые события. |
| `inspect` | `self` или `<entity_id>` | Доступные наблюдению характеристики, здоровье, инвентарь, способности, ограничения сервера и список поддерживаемых действий. |
| `move` | `<dimension> <x> <y> <z>` | Статус пути и достигнутую позицию либо причину недоступности. |
| `mount` | `<entity_id>` | Результат посадки на доступную лошадь. |
| `dismount` | нет | Результат спешивания и позицию. |
| `attack` | `<entity_id> <ability_id>` | Доступность способности, результат или статус атаки, затраты и перезарядку. |
| `plant` | `<item_id> <dimension> <x> <y> <z>` | Результат посадки дерева или цветка и расход предмета. |
| `farm` | `<till|sow|harvest> <dimension> <x> <y> <z> [item_id]` | Результат работы с полем; item_id требуется для sow. |
| `interact` | `<entity_id> <interaction_id>` | Результат поддерживаемого взаимодействия; ответы существ возвращаются только при реальном событии. |
| `stop` | `<action_id>` | Подтверждение остановки длительного действия или причину отказа. |

Координаты, идентификаторы существ, предметов и способностей берутся из наблюдений
и конфигурации сервера. Ни название «маг», ни реплика о заклинании не создают
игровую способность. Скин и числовые характеристики задаёт разработчик на стороне
мода/сервера; персонаж читает фактические значения через inspect.

### Ответы и ошибки

Предлагаемый формат ответа — один JSON-объект с полями action_id, status,
observed_at, data и error. observed_at использует UTC; для ошибки без наблюдения
допустимо null. status принимает completed, pending или failed.

- completed означает подтверждённое завершение; в data находятся наблюдаемые результаты.
- pending означает только принятие команды. Проверь продолжение через observe по action_id.
- failed содержит error с полями code и message; для успешного ответа error равен null.
- Ненулевой код выхода сообщает об ошибке команды. Код 0 сам по себе не доказывает
  завершение игрового действия: учитывай status и данные наблюдения.

Типовые ошибки: NOT_CONNECTED, UNSUPPORTED_ACTION, TARGET_NOT_FOUND,
OUT_OF_RANGE, BLOCKED_PATH, INSUFFICIENT_ITEMS, COOLDOWN и SERVER_RULE_DENIED.
Запрещённое сервером действие отклоняет игровой адаптер. Повтор команды не должен
вызывать повторную посадку или атаку после неопределённого результата: сначала
проверь состояние прежнего действия. Раннер ограничивает длительность действий
и останавливает их при завершении сессии, если явно не поддержано продолжение.

## Следующие интеграции

- Голос: отдельные инструменты STT/TTS, выбранный голос и очередь озвучивания реплик.
- Telegram: доставка записей outbox и публикация историй из подтверждённых событий.
- Видео: запись игровых эпизодов, монтаж и загрузка на YouTube или в Telegram.
- Twitch/YouTube: стриминг и получение сообщений зрителей через отдельный транспорт.

До реализации этих интеграций сохраняй идеи и факты локально. Не утверждай,
что голос прозвучал, ролик записан или история опубликована.
